# 拆分任务

## 触发与边界

- use_when：当前纪要已明确确认，且用户在确认后单独选择了拆分；或基于仍有效的确认纪要修订已经授权的任务清单。
- do_not_use_when：纪要尚未确认、修改后未重新确认、只有纪要确认而无独立拆分选择、用户已拒绝拆分、只有转写、要求查询或写入任务系统、要求发送通知。
- 正例：p1：周岚完成连接检查，陈禾在检查通过后验证转写分页。
- 反例：纪要尚未确认、修改后未重新确认、只有纪要确认而无独立拆分选择、用户已拒绝拆分、只有转写、要求查询或写入任务系统、要求发送通知。

## 前提

接收调用方已提供且授权处理的材料；task_id 与 owner_context 由 Agent/Runtime 提供，不能自行生成身份或权限。若必要材料或绑定缺失，返回 needs_input，不读取其他私有目录补齐。

本技能只进行已授权第二段的任务拆分，不生成纪要，不联网取材，不调用其他 Skill，不查询外部任务系统，不询问项目/阶段，不承担外部创建。

## 执行步骤

1. 核对当前纪要已确认、确认后用户已选择拆分、两份真实依据都绑定当前纪要版本；任一缺失或过期返回 needs_input，用户选择暂不拆分返回 rejected（Skill 不应被调用），result=null 且不生成任务。Agent 对不拆分按正常完成处理，不能把此路由拒绝当成整个会议整理失败。
   - **来源链核对（本段特有）**：任务要**派给人**，所以来源必须落到人名的正确写法上。核对当前纪要来自**已纠错**的转写（前置纠错见 `meeting-minutes` 执行步骤 0）：若纪要是从腾讯会议原始转写直接成稿的，负责人姓名、产品名、专有名词都可能带同音错字——此时返回 `needs_input`，在 `pending_questions` 里要求先纠错并重新确认纪要，**不得据此派活**。`source_refs` 指向纠正稿与纪要版本，不指向未纠错的原始转写。
2. 从明确行动项及与行动有关的结论提取工作，不把讨论话题、否定决议或暂缓事项自动变成选中任务。
3. 按独立交付成果和可核验完成条件拆分；同一工作重复出现时合并并保留全部来源。不要为了凑数量拆成“思考/讨论/跟进”等无明确成果项。
4. 填写标题、描述、负责人原话、截止日期原话、完成条件、来源和依赖。会议未说明的完成条件或新拆分步骤标 proposed，并进入待确认；不推断成员标识、项目阶段、优先级或承诺日期。
5. 相对日期只在会议日期、时区和语义均明确时给出可追溯候选日期，且保留原话；有多种解释则 date=null。缺少负责人/日期时显式标注 pending，不用空字符串伪装已确定。
6. 给每条候选任务分配清单内稳定 local_id；修订保持已有标识，新任务新增标识，合并标明旧项，不回收删除标识。保留依赖、selected=false、confirmation=pending，不自行确认或建立外部子任务。
7. 按输出契约返回候选任务表、待确认问题、拆分理由和修订关系。默认任务表只有任务、负责人、截止时间、完成条件；性质、来源与依赖放详情。只保留清单允许字段仍待确认，不要求外部项目/阶段；选择拆分或清单勾选均不是外部创建授权。

## 预期输出

固定返回 status（draft / needs_input / rejected）、task_id、result、pending_questions、source_refs、audit_refs、error。成功 result 为本技能的草稿对象；缺少输入或拒绝时 result=null。audit_refs 只引用 Runtime 实际给出的记录，未提供则 []，不能伪造已审计事实。

## 外部依赖

无专属 MCP、浏览器账号、CLI 或脚本依赖。输入材料、owner_context 与审计记录由调用方提供。本技能不写知识库。Agent 保存清单并登记产物，应用在任务完成后自动归档；不要求手动导入，不等待索引。

## 候选状态

promotion_ceiling: staged
production_release_allowed: false
