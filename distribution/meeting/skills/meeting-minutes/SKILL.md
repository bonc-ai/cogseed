# 会议纪要

## 触发与边界

- use_when：已提供完整转写，需要整理会议纪要或修改已有纪要草稿。
- do_not_use_when：没有转写却要求获取会议、要求拆分执行任务、写知识库、创建外部任务、仅做文章摘要。
- 正例：p1：周岚说，决定先完成验证，验证通过后再发布。
- 反例：没有转写却要求获取会议、要求拆分执行任务、写知识库、创建外部任务、仅做文章摘要。

## 前提

接收调用方已提供且授权处理的材料；task_id 与 owner_context 由 Agent/Runtime 提供，不能自行生成身份或权限。若必要材料或绑定缺失，返回 needs_input，不读取其他私有目录补齐。

**关于前置纠错与"不调用其他 Skill"的关系**：前置纠错（执行步骤 0）要求的是**调用方**先做一次词表纠错，本 Skill 自己一次工具都不调用——它只是拒绝把未经纠错的原始转写当作可信输入。这与下条"不调用其他 Skill"的边界不冲突：那条禁止的是本 Skill 去编排别的 Skill，不是禁止它对输入质量提出要求。

本技能只生成/修订完整纪要草稿，不联网取材，不调用其他 Skill，不拆分独立候选任务，不查询任务系统，不提前索要任务字段。调用方先让用户审阅确认纪要，再单独询问是否拆分；确认纪要不表示授权后续任务。

## 执行步骤

0. **转写纠错前置（边界：这不是本 Skill 在调用工具）**——本 Skill 自身仍不调用任何工具，纠错由 Agent 层完成，并把纠错后的文本作为 `transcript` 传入。若调用方传入的是**未经纠错的腾讯会议原始转写**，先返回 `needs_input`，并在 `pending_questions` 里要求调用方先执行纠错，给出这一步的理由：
   - 腾讯会议转写存在**同音近音错字**（`巨升智能` / `具身智能`、`coxy` / `Cogseed`）与**人名、专有名词错认**；不纠而直接成稿，错误会传导进纪要，再被拆成任务派给人——**错误会被固化到执行层**。
   - 调用方应先用 `transcript_glossary_apply`（词表纠错）得到纠正稿文件（`corrected_path`，宿主已写好，不要重写），再按需按范围读取交给本 Skill。纠错只作用于**转写**；平台生成的"元宝纪要"（`get_meeting_minutes`）本身通顺，**不要**过一遍纠错，避免误改。
   - 若纠错结果里出现 `status: draft` 或非空的待确认项（`risk=high`，即两字中文词、常见词），**必须先把这些项以可点选的清单交给用户逐条确认**，再由调用方用 `transcript_glossary_upsert` 回写词表，然后**重跑一次纠错**。**不得把未经用户确认的候选词写入词表，也不得跳过确认直接出纪要。**
   - 同时要求调用方把**纠正稿另存为独立文件**（不得覆盖原始转写），使"原始转写 / 纠正稿 / 纪要"三份都可追溯。

1. 核对输入契约、完整性及实际来源。转写不完整时返回 needs_input；不得静默生成“完整纪要”。
2. 按议题提取要点，分开记录明确结论、建议和未决问题。保留原文中的否定、条件、范围、数字与单位。
3. 提取会议明确提出的行动项线索及负责人/日期原话，不进一步拆成执行任务，不补造承诺。决议、未决问题、行动项线索分别按 D/Q/A 编号；修订时沿用原编号。
4. 给每条结论、未决问题和行动项线索关联“source_id · 段落标识”，段落标识必须取自输入的真实 segment_id，不用“转写片段”等泛称；找不到出处的条目不写入结论，转入待确认。行动项落实某项决议时在 derived_from 写明决议编号。存在真实时间码才记录；录制时间码为相对时间，不转成会议绝对时间。引用原文时**以纠正稿为准**；若必须引用纠错前的原句，显式标注它是未纠正原文。
5. 有 prior_open_items 时逐项判断本次是否提及：给出已解决建议、进展或未提及，并附本次来源；只建议，不判定已解决。有 ontology_context 时，参会人、负责人、项目、系列仅在名称或别名唯一命中时带实体 id；完全没有命中的按输出契约提议为 new_entities（confirmed=false），命中多位的保持 null 并列入待确认。
6. 单独标记用户后续补充和解释；修订时关联前版，产出新的 draft，简述最多 3 条修改点并交回调用方重新审阅。不覆盖原始转写，不自行确认纪要；新版本不能沿用旧版本确认。
7. 按输出契约产出完整纪要、同版本 meeting_record（confirmed=false）和最多 3 条核心结论，自检引文、数字、建议/决议边界和版本。会议原有后续安排可忠实记录，但不得产出独立候选任务、查询任务系统或询问任务项目/阶段。返回纪要 Markdown 与文件产物意图；调用方生成文件并登记产物，应用在任务完成后自动归档。本 Skill 不执行保存，不要求先有入库回执，也不宣称已归档。

## 预期输出

固定返回 status（draft / needs_input / rejected）、task_id、result、pending_questions、source_refs、audit_refs、error。成功 result 为本技能的草稿对象，含同版本 meeting_record 与可选 follow_ups，summary 最多 3 条，完整 markdown 不缩减为摘要；缺少输入或拒绝时 result=null。audit_refs 只引用 Runtime 实际给出的记录，未提供则 []，不能伪造已审计事实。

## 外部依赖

无专属 MCP、浏览器账号、CLI 或脚本依赖。输入材料、owner_context 与审计记录由调用方提供。本技能返回纪要内容，Agent 负责保存工作区文件和登记产物，应用负责任务完成后的自动归档；归档尚未完成不影响本技能整理内容，不要求手动导入知识库。
