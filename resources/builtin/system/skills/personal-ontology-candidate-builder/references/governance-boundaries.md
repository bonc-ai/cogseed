# Governance Boundaries

本技能只服务用户个人，没有企业级**组织**路由（不区分部门/岗位/客户/组织本体），也没有团队共享或组织提交的路径；支持个人角色模板（学生/学者/FDE）的字段建议。

## 候选边界

- 候选池里的内容 != 已生效的记忆。用户点击确认前，AI 不会因为候选池里有内容而改变行为。
- `confidence=high` 意味着"证据充分、值得优先请用户确认"，不意味着"可以跳过确认"。
- `建议字段` 只是预选：技能给出的字段名会作为 App 确认面板下拉的默认值，**不绕过用户确认**——用户在面板里逐条确认、可改选或改选"流水区（不填坑）"。
- 用户点击确认后，候选由 App 后端负责写入（全局记忆 / 分组字段区 / 分组流水区）并从候选池移除；本技能本身不直接写这些文件。

## 记忆去向边界

- 全局记忆：`memory_scope: user`（USER.md，跟用户本人强相关、长期稳定的内容，容量小要精炼）或 `memory_scope: shared`（MEMORY.md，更泛化的事实/规则，容量稍大）。
- 分组字段区：候选确认时"对号入座"填入某个记忆分组的字段（多值追加 + 标来源，不覆盖）。
- 分组流水区：没有对应字段坑时，候选追加进分组的流水区（`§` 分隔，可后续升格为新字段）。
- 具体去向由用户在 App 确认面板决定；技能只提供建议，不指定具体分组。

## 数据边界

- 个人内容强制本地存储，不离开用户本机，不上传、不同步到任何团队/组织级存储。
- 涉及密钥、密码、他人未授权隐私信息的内容，无论置信度多高，都必须先脱敏或直接阻断，不能生成候选。
- 无法确认已脱敏时，按未脱敏处理。

## 用户修改保护

- 如果输入材料、原稿、草图、批注或待优化文档里已有用户自己的修改痕迹，默认保护，不擅自覆盖或重写。
- 只有用户明确要求重写、合并、清理或授权改动时，才可以动这些痕迹。
- 任务外内容优先保留，不因为提炼个人候选而顺手整理掉。

## 汇报边界

- 提炼完成后，对话里只给一两句小结（提炼了几条、大致类型），不在对话里展开全部候选细节——细节留给候选审阅面板。
