# Failure Modes

## 候选类型误判

症状：把一条关系误判成规则，或把一个实例误判成属性。

处理：保留来源引用，标低置信度，不因为类型可能判错就完全不输出——留给用户在审阅时判断。

## 证据不足却下了宽泛结论

症状：只凭一次性提及，就生成一条"长期规则"或"长期偏好"。

处理：标 `confidence: low`，或者干脆不生成候选，等下次再出现同样的模式再提炼。避免一次性吐槽被误判成稳定习惯。

## 脱敏失败

症状：候选的记忆文本里出现了密钥、密码、他人隐私信息等未脱敏内容。

处理：不生成候选，直接写入 `blocked_items`，说明原因和修复建议。

## 记忆文本过长/照抄原始配置

症状：把一整段配置 JSON 或长段原文直接塞进 `记忆文本`。

处理：重新提炼成一句精炼的话再写入候选。USER.md/MEMORY.md 容量有限，塞长文本会很快把旧的有效记忆挤掉。

## 候选重复

症状：同一条偏好/事实被反复提炼成多条候选，或者候选池里已经有类似内容还继续追加。

处理：写入前先读一遍现有候选池和已有记忆（USER.md/MEMORY.md），发现重复就跳过或合并成一条更新（用 `差异` 字段说明改动）。

## 把第三方内容当成用户偏好

症状：对话里提到别人的偏好/习惯，被误判成用户自己的偏好写进 USER.md。

处理：区分主体——只有明确是用户本人的内容才进 `memory_scope: user`；提到别人的内容如果值得记，也应该在 `摘要`/`记忆文本` 里说清楚"这是关于谁的"，而不是模糊地当成用户自己的偏好。
