# 运营商数据安全运营知识问答 Skill

> 这不是搜索引擎，而是把《数据分类分级标准》和安全处置规程结构化后的推理引擎。  
> 骨架是 Ontology + R-Box 规则 + A-Box 案例；LLM 是语言接口，不是答案来源。

---

## 1. 技能定位

把这个 Skill 想象成一位随时在线的**数据安全分级专家**——

- 运营专员问「身份证号是什么等级」，它秒出答案并说明原因；
- 问「三个字段组合导出是什么级别」，它不只看单字段，还判断组合风险；
- 碰到安全告警，它给出 What / So What / Now What 三层处置路径，不只是"去查规程"。

**不处理的范围**：系统漏洞修复、代码安全审计、网络攻防技术操作（超出本 Skill 本体覆盖范围，遇到此类问题应明确说明并转交专业团队）。

## 2. 触发条件

```
字段分级查询类：
- "身份证号属于哪个敏感等级？"
- "这个字段需要加密存储吗？"
- "id_card_number 字段是 L 几？"
- "手机号和邮箱属于什么分类？"

组合风险评估类：
- "这几个字段一起导出，整体是什么级别？"
- "手机号 + 位置 + 姓名组合是什么等级？"
- "可以把这批数据给第三方吗？"

安全事件处置类：
- "这个批量导出告警怎么处理？"
- "有员工越权访问了 L3 数据，下一步怎么办？"
- "发生数据泄露了，要向监管上报吗？"
```

## 3. 本体引用（Skill 的知识骨架）

### T-Box · 数据安全运营概念体系

```
数据安全运营核心实体：

DataAsset（数据资产）           ← 表 / 库 / 接口级，数据的存储单元
  属性：asset_id, asset_type, owner, classification
  关系：[包含] → DataField（一个资产包含多个字段）

DataField（数据字段）           ← ★ 核心推理对象，运营专员最常查的层级
  属性：field_name, data_type, sensitivity_level, category
  关系：[属于] → DataCategory（字段归属某个分类）
        [具有] → SensitivityLevel（字段对应某个敏感等级）

DataCategory（数据分类）        ← 分级标准的分类体系（代码 1-x-x-x / 2-x-x-x）
  属性：category_id（如 1-1-1-1）, name（如 自然人身份标识）
  典型实例：
    1-1-1-1 自然人身份标识（姓名/身份证号/驾照号/银行账户）
    1-1-1-2 网络身份标识（手机号/邮箱/IP/社交账号）
    1-1-1-3 用户基本资料（年龄/性别/学历/职业）
    1-1-1-4 实体身份证明（证件影印件/生物识别信息）
    1-1-1-5 用户私密资料
    1-2-1-1 服务内容数据（通话/短信内容）+ 密码类
    1-3-1-1 业务订购关系
    1-3-1-3 消费信息和账单
    1-3-1-4 位置数据
    1-3-2-1 终端设备标识
    2-1-2~4 网络资源/运维/安全管理类（企业数据）

SensitivityLevel（敏感等级）   ← 推理的核心输出
  属性：level（L1/L2/L3/L4）, label（低/中/高/极敏感）
        handling_requirements（处理规程要求）
  关系：[触发] → SecurityPolicy（等级决定适用哪些安全策略）

SecurityPolicy（安全策略）      ← 等级对应的处理要求和控制手段
  属性：policy_id, applicable_levels[], control_type
  典型内容：
    L4：加密存储 + 严格访问控制 + 全程审计 + 禁止明文传输
    L3：加密存储 + 访问日志 + 脱敏后方可共享 + 对外须经审批
    L2：访问控制 + 操作日志 + 最小权限原则
    L1：常规访问控制

SecurityIncident（安全事件）    ← 告警/异常/泄露事件的处理对象
  属性：incident_id, incident_type, severity, status
  关系：[涉及] → DataField（事件影响了哪些字段）
        [违反] → SecurityPolicy（事件违反了哪条策略）
```

### R-Box · 关键规则摘要（★ Skill 的灵魂）

> 完整规则见 `references/rbox_rules.md`，此处列最高频判断场景。

```
★ 高频规则 1（身份证类场景必用）

IF DataField.category = 1-1-1-1（自然人身份标识）
AND 数据形式 = 号码字段（字符串）
THEN SensitivityLevel = L3 高敏感
REASON 可直接识别自然人身份；号码字段可修改，危害低于生物特征

IF DataField.category = 1-1-1-4（实体身份证明）
AND 数据形式 = 影印件 / 电子照片 / 生物识别
THEN SensitivityLevel = L4 极敏感
REASON 生物特征不可撤销；影印件含多维要素可被直接冒用
⚠️ 关键区分：身份证号码 = L3；身份证影印件 = L4；同一证件，形式不同，等级不同

★ 高频规则 2（组合风险场景必用）

IF 多个 DataField 单独等级均 ≤ L2
AND 字段将被组合使用（关联分析/联合导出）
THEN 组合后整体风险 = 各字段中最高单字段等级，不因组合自动升级
REASON 数据分类分级标准按字段本身数据类型定级；组合使用风险通过审批流程管控，不改变字段本身等级

★ 高频规则 3（安全事件处置必用）

IF SecurityIncident 涉及 DataField.sensitivity_level = L3 以上
AND 批量异常导出 / 泄露告警触发
THEN 30 分钟内向数据安全负责人内部上报（无外部监管上报义务）
REASON 内部上报时限源自企业安全应急规程；PIPL 第 57 条外部监管上报不适用本场景

完整判定规则 19 条见：references/rbox_rules.md
```

## 4. 执行流程（分析型 Pipeline）

```
用户输入（查询描述 / 告警信息）
  ↓
Step 1 · 意图识别 & 实体提取
  ├── 字段分级查询？→ 提取字段名 / 数据类型描述
  ├── 组合风险评估？→ 提取所有涉及字段
  └── 安全事件处置？→ 提取事件类型 / 涉及数据 / 严重程度
  ↓
Step 2 · DataCategory 匹配
  将字段映射到分级标准代码（1-x-x-x 或 2-x-x-x）
  IF 用户描述含"身份证"→ 追问：号码字段 还是 影印件/扫描件？（高频混淆点）
  IF 无法匹配 → 触发「未知字段处理流程」（见下方）
  ↓
Step 3 · R-Box 规则推导
  应用 rbox_rules.md 判定规则 → 输出 SensitivityLevel
  IF 组合查询 → 额外检查通用规则-03（组合识别风险）
  IF 安全事件 → 进入安全事件处置子流程（见下方）
  ↓
Step 4 · SecurityPolicy 关联
  查找该等级对应的处理规程要求
  IF L3 以上 + 异常告警 → 提示 30 分钟内内部上报（无外部监管上报义务）
  ↓
Step 5 · A-Box 案例检索
  匹配 cases.json 中的相似历史案例
  有匹配 → 引用案例编号和结论辅助作答
  无匹配 → 纯规则推导，注明"暂无历史参照"
  ↓
Step 6 · 四层输出（What / So What / Now What / Learn What）
```

**子流程 A · 未知字段**

```
IF 字段无法匹配任何 DataCategory
THEN
  1. 说明"该字段类型在分级标准中暂无明确对应"
  2. 给出最相近类别及等级作为参考上限
  3. 标注"建议人工确认，待确认期间按参考上限等级处理"
  （不得随意定级，按就高不就低原则）
```

**子流程 B · 安全事件处置**

```
IF 输入描述安全告警或异常事件
THEN
  1. 识别涉及的 DataField 及 SensitivityLevel
  2. 确认违反了哪条 SecurityPolicy
  3. 按四层格式输出处置路径（见输出格式 · 安全事件版）
  4. IF 涉及等级 L3 以上
     → 30 分钟内向数据安全负责人内部上报（无外部监管上报义务）
```

## 5. 输出格式

### 字段分级查询输出

```
【字段名】[field_name 或用户描述的字段]
【数据分类】[category_id] [category_name]
【敏感等级】[L1/L2/L3/L4] [等级标签]

What：
  [该字段是什么，属于哪个分类，分级标准代码是什么]

So What：
  [这个等级意味着什么风险，不当处理会有什么后果和合规影响]

Now What（处理规程要求）：
  - 存储：[加密要求]
  - 访问：[控制和日志要求]
  - 传输：[传输安全要求]
  - 共享/导出：[对外共享的审批要求]

---
⚠️ [如有容易混淆的相关情况，在此单独说明]
📋 参考案例：[如 A-Box 中有相关案例，标注 CASE-DS-00X]
```

### 组合风险评估输出

```
【评估字段】[字段1] / [字段2] / [字段3]

各字段单独等级：
  - [字段1]：[L?] — [category_name]
  - [字段2]：[L?] — [category_name]
  - [字段3]：[L?] — [category_name]

组合风险等级：[L?]（[与单字段相比是否升级，升级原因]）

Now What（组合使用规程）：
  [按组合后最高等级适用的处理规程给出建议]
  [如需对外共享，说明审批路径]

---
📋 依据：PIPL 第 4 条（组合识别风险）
```

### 安全事件处置输出

```
【事件类型】[incident_type]
【涉及数据等级】[L?] [等级标签]
【紧急程度】[高/中/低]

What：
  - 发生了什么（事件描述 + 涉及数据字段 + 数量规模）
  - 违反了哪条安全策略（policy_id + 控制要求）

So What：
  - 数据安全风险（该等级数据泄露可能导致什么）
  - 合规风险（适用哪条法规，潜在处罚后果）

Now What（处置步骤，按优先级排序）：
  1. 即时处置：[账号冻结/访问切断/告警确认]
  2. 调查取证：[日志取证/范围确认/数据流向追踪]
  3. 上报判断：[是否触发内部 30 分钟上报义务（无外部监管上报义务）]
  4. 修复加固：[防止再次发生的机制改进]

---
📋 参考案例：[相关 A-Box 案例编号]
⚖️ 法规依据：[PIPL / 等保 等适用条款]
```

## 6. KSTAR 闭环

```
每次问答 = 一次完整 KSTAR 学习循环：

  Situation  → 运营专员的查询描述 / 系统告警输入
  Task       → Skill 识别的任务类型（字段查询 / 组合评估 / 事件处置）
  Action     → 本体匹配 + R-Box 推导 + 四层输出
  Result     → 专员评估：答案是否准确、是否够用
  δR         → 答错/答偏 → 定位哪条 R-Box 规则出问题
  Learn      → 修正该规则，更新 rbox_rules.md，下次同类问题更准
```

**δR 记录格式**（运行后填写）：

| 测试问题 | Agent 给出等级 | 专家确认等级 | δR 描述 | 涉及规则 | 修正动作 |
|---------|--------------|------------|---------|---------|---------|
| 身份证影印件字段 | L3 | L4 | 混淆号码和影印件 | R-L4-01 | 补充追问逻辑 |
| 手机号+位置+姓名 | L2 | L3 | 未触发组合风险规则 | 通用-03 | 强化组合检测 |

**δR 归因三问**（每轮迭代必问）：
1. 字段分类匹配错？→ 检查 DataCategory 代码是否映射准确
2. 等级判定错？→ 对应 R-Box 规则的条件或 REASON 有误 → 修 `rbox_rules.md`
3. 处置建议不够？→ SecurityPolicy 关联遗漏 / A-Box 案例未被检索到 → 补充

## Skill Gate 契约

- `use_when`：运营专员查询数据字段敏感等级（如“身份证号属于哪个敏感等级”“id_card_number 是 L 几”）、组合风险评估（字段一起导出整体级别）、安全事件处置（批量导出告警/越权访问 L3 数据/数据泄露是否上报监管），基于《数据分类分级标准》与处置规程推理。
- `do_not_use_when`：系统漏洞修复、代码安全审计、网络攻防技术操作（超出本体范围，转交专业团队）；标准未覆盖的新字段直接拍等级（需走规则确认）；把推理结论当监管批复；组合风险只按单字段最高级判断而不看组合。
- `positive_examples`：`身份证号属于哪个敏感等级？要加密存储吗？`；`手机号+位置+姓名组合导出是什么级别？`
- `negative_examples`：`帮我做系统漏洞修复。`；`这个新字段标准里没有，你直接定 L2。`
