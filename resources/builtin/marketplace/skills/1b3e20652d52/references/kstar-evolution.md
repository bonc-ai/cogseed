# KSTAR evolution hook — customer-profile-presales

技能是活的、可演进的资产，但演进守纪律。本文件**声明**演进钩子；真实闭环（ΔR/ΔA、
reflect→distill→gates）跑在 `metaskill` 引擎里，脚手架不跑。

## 信号
- **K/S/T → Â/R̂ → A/R → ΔA/ΔR**
  - K = 画像→打法映射知识（RBox 路由 + 钩子/异议库指针）；S = 本次客户画像情境；T = 产出本场作战方案。
  - Â/R̂ = 预测：预测选中的版本/钩子/场景/异议能"讲到位"（负责人抽检通过）。
  - A/R = 实际：这一场真实用了什么、客户实际问了什么、负责人抽检结论。
  - **ΔR = R − R̂**（核心学习信号）：抽检"没讲到位"、或现场冒出未预置的异议 = 正向 ΔR，提示映射可改进——但 ΔR ≠ 发布指令。
  - **ΔA gates ΔR**：若售前临场手改了版本/话术（执行走样，ΔA≠0），本次 ΔR 不可信，只诊断路由/画像，不用于学习。

## 学习假设 → 候选 → 有界补丁
- **单证据单信号**：一场交流 AAR → 一条学习记录 → 至多一个学习假设；单条永不直接更新知识。
- **符号聚合**：假设按符号稳定键聚合（如"能源×P2×效果痛→应加 Qx 异议"），达最低支持度（≥2 条独立 AAR）方进提案。
- **有界补丁**：`edit_budget ≤ 2`，只触碰**可变面**（画像→版本/颗粒度映射阈值、钩子库指针、QA 库引用），
  **永不触碰保护面**（R4 承诺分级/R5 不点名/R6 未定价不报价的规则结构、HITL 要求、审计机制）。
- **神经只起草**：LLM 可起草新钩子/异议措辞候选，绝不写 `formal`/`config_key`/`value`，绝不裁决良构性或门禁通过。

## 三门后提交
补丁过 `验证门 → 治理门 → 金丝雀门` 后才回写知识资产，回写伴随版本递增与审计；任一门失败即拒绝并入拒绝缓冲（永久留痕，防重复提交）。

## 与《销售 QA 库》的狗粮回路
子能力④画像模拟练兵产出的新问题/新异议，回填《销售 QA 异议应答库》；成熟条目毕业进 FAQ/Battlecard；
**触及口径的条目走回流纪律进冻结表**——这条回路是本 Skill"越用越准"的来源，但每一步都受三门与人工评审约束。

> 诚实边界：以上为**声明的钩子**，非真实运行。真实 KSTAR 学习需 metaskill 引擎；本脚手架只到 staged 候选结构。
