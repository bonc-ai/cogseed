# 竞品与市场研究

## 目标

让每个竞品结论都能回答一个产品决策，并能回到具体、带时效的证据。

## 开始前

至少确认：

- 决策问题、目标用户与产品边界
- 候选竞品或待扫描市场
- 允许访问的内部材料与外部来源范围

缺少会改变结论的关键输入时，提出最少必要问题；若用户要求继续，使用 `未知/TBD`，不要补造。

## 工作流

1. 把研究请求改写成决策问题，并定义截止日期、受众、深度和不可回答项。
2. 建立竞品池：区分直接竞品、间接替代、用户自建方案和不行动；记录纳入/排除理由。
3. 先定义对比维度，再采集证据；维度通常含定位、目标用户、关键任务、能力、体验、定价、部署、生态和GTM。
4. 优先读取一手来源；为每条证据标注来源等级、发布日期/抓取日、厂商主张或独立验证、适用版本。
5. 形成逐项矩阵，分开当前可验证能力、未来路线图主张和研究推断；冲突信息并列呈现。
6. 综合差异化、机会、威胁与不确定性，明确哪些发现会改变当前决策。

## 专业判断规则

- 研究范围由决策问题驱动，不固定竞品数量。
- 官网营销话术属于厂商主张，不自动视为已验证事实。
- 价格、版本、负责人、发布日期等易变信息必须带时间。
- 无法核实的市场份额、客户数和性能数据不得填补。

## 输出契约

必须返回：

- 研究范围与竞品池
- 来源登记与证据矩阵
- 能力/定位/商业模式对比
- 机会威胁与产品含义
- 证据缺口和下一步

所有关键结论都标为 `事实 / 推断 / 假设 / 建议 / 待决策` 之一，并保留证据ID或缺口。只返回正式资产候选，不直接覆盖PRD、路线图或长期认知资产。

## 失败与降级

- 来源不可访问：列出已完成部分、缺失来源和对结论的影响。
- 权限或敏感度不满足：停止对应读取或外部动作，返回所需授权。
- 数据互相冲突：并列冲突及适用条件，不自行裁决为单一事实。
- 预算耗尽：返回当前证据、未完成步骤和可安全续跑点。
