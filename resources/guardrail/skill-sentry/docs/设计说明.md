# Skill Security Scanner 设计说明

## 1. 定位

单一职责的 **Skill 安全扫描器**，作为 Skill Factory / Agent Factory /
Companion Agent / Task Agent 的强制安全入口。与原 `artifact-security-review`
的区别：原实现是四维治理评测（Validation / Security / Red-team / Business
Correctness）中的一维，且混入了 Agent 专属的 P3394、治理平台专属的 KSTAR。
本扫描器**只做 Skill 安全**，彻底剥离其他维度。

## 2. 架构

```
scan(artifact_path)                     ← 对外调用契约（工厂系统集成用）
  └─ safe_extract()                     ← zip 安全解压（防路径穿越）
  └─ locate_skill_roots()               ← 以 SKILL.md 为根定位 Skill 边界（收窄扫描范围）
  └─ 对每个 Skill: scan_one_skill()
        ├─ collect_evidence()           ← 收集文本文件（二进制交给 binary_scan）
        ├─ scan_regex_rules()           ← 密钥/危险命令/注入/持久化/外联/一票否决
        ├─ scan_forbidden_files()       ← 敏感文件名
        ├─ enhance_with_gitleaks()      ← 可选：gitleaks 增强密钥扫描
        ├─ enhance_with_dependency_audit() ← 可选：osv-scanner CVE 扫描
        ├─ binary_scan.scan_binaries()  ← 二进制静态行为分析
        ├─ build_profile()              ← 权限/审计/HITL/外联/供应链 语义画像
        ├─ evaluate_sr_items()          ← SR-01~08 判定
        └─ build_report()               ← 打分 + 分级 + 9 字段输出
```

## 3. 设计取舍

### 3.1 自包含、渐进增强
不硬依赖 pyyaml / Docker。规则内置默认值（DEFAULT_*），有 pyyaml 则用 02_rules
下的 YAML 覆盖；外部工具（gitleaks/osv-scanner/strings）有则增强、无则降级并
在 tool_status 标注。保证任何环境都能跑出结果，不会因缺依赖直接崩溃。

### 3.2 打分模型
从 100 分起扣，按 severity 加权（critical=40, high=20, medium=8, low=3）。
分级：hard_block 或极低分 → CRITICAL；有 critical → HIGH；<70 → MEDIUM；否则 LOW。
**分数是启发式度量，不是绝对安全度**——底层是正则匹配，分数精确但存在伪精度，
需配合误报率验证解读。

### 3.3 一票否决（hard_block）
对应会议要求“持续外传认知资产的第三方工具，核心环境禁止安装”。命中即直接
DO_NOT_INSTALL，不参与加权打分，独立于分数模型。

### 3.4 阻断契约
CLI `--fail-on` 控制在何种部署建议等级返回非 0 退出码，供 CI / 发布流程拦截。
`scan()` 返回结构化 dict，供 Python 系统直接 import 调用，不必解析文件。

## 4. SR 检查项映射

| SR | 名称 | required | 判定依据 |
|---|---|---|---|
| SR-01 | 密钥与敏感信息 | 是 | 密钥正则 + gitleaks + 敏感文件名 |
| SR-02 | 权限最小化 | 是 | 权限声明关键词 |
| SR-03 | 危险命令/注入/破坏性 | 是 | 危险命令/动态执行/SQL注入/持久化规则 |
| SR-04 | 外部网络与数据外发 | 是 | 外联 findings + 是否有审计/权限约束 |
| SR-05 | 写操作与人工确认 | 是 | 副作用关键词 + 是否声明 HITL |
| SR-06 | 供应链可复现性 | 否 | lockfile / 版本 pin / latest 依赖 + osv CVE |
| SR-07 | 提示注入与系统信息保护 | 否 | Prompt Injection 载荷正则 |
| SR-08 | 审计与可追踪 | 否 | 审计/日志关键词 |

相比原项目：删除了 SR-09“外部扫描器融合 P3394”对 Agent 专属检查的依赖；
SR-07 从“是否声明防护”升级为“是否检出实际注入载荷”。

## 5. 局限与后续（诚实边界）

1. 文本检测=正则/关键词，误报漏报都存在；Score 需配合真实样本基线解读。
2. 二进制仅静态层（binary_scan.has_dynamic_sandbox() 恒 False），无法确认运行时
   真实读写/外发行为——这是 3.3“二进制扫描要求”里最关键但最不成熟的部分，
   需单独立项接入动态沙箱。
3. 恶意代码特征、威胁情报地址库建议接现成方案（YARA / 情报 feed），不自建。
4. 企业级强制入口还需：误报率验证、规则变更审批、例外申诉、扫描器自身可观测性。
