# Skill Sentry 规范符合性声明（Compliance Statement）

> 目的：把《Skill 安全检测机制调研文档》（需求源）逐条设计原则，映射到
> skill-sentry 的**真实代码位置**与**证据状态**，避免「凭文档存在就声称
> 能力已实现」。证据状态采用四级能力成熟度：
>
> `declared_target_state → packaged → engine_bound → evidence_validated`
>
> - **packaged**：有文档/schema/配置声明，但未必有真实代码路径
> - **engine_bound**：有真实可执行代码路径
> - **evidence_validated**：有测试 / 回归向量 / 结构化证据佐证
>
> 版本：skill-sentry 2.0.0 ｜ 规则包 v1.0.0 ｜ 生成日期 2026-07-27

## 二、本轮加固（2026-07-27，对齐原则 1 与 7）

调研文档最硬的「fail-closed」要求在加固前存在两处 fail-open 缺口，已修复：

1. **引擎内部异常不再向上冒泡**：`scan()` 顶层与单 Skill 层均包 try/except，
   任何崩溃返回 `status=ERROR` + `DO_NOT_INSTALL` + `security_score=0`，
   并保留 ERROR 状态不被单 Skill 分支覆盖为 OK。
2. **请求不存在的规则版本不再静默降级**：`load_rules` 仍回退内置规则以
   保证「有规则可扫」，但通过 `_ruleset_resolved=False` 显式标记，报告透传
   `ruleset_resolved` 字段，供上层审计（避免「以为扫 vX、实际扫 builtin」）。
3. **agent_gate 降级路径异常转人工复核**：降级扫描内部 ERROR → `verdict=review`
   而非放行；`_run_degraded` 包 import 兜底，绝不抛异常。

验证：`python3 -m pytest tests/ runtime_trust/tests/` → 60 passed；
`tests/conformance/v1.0.0/run_conformance.py` → 2/2（正常行为未被加固改变）。

## 三、明确未实现（诚实边界，非缺陷）

以下为调研文档二期/三期内容，当前**未实现**，不声称具备：

- **LLM 自建 Skill 的语义校验**（调研文档第四节、方案 C）：检测 markdown body
  中诱导未来会话绕过检查的模式。当前仅覆盖 marketplace 静态扫描路径。
- **安装风险等级与运行时门禁联动**（方案 D）：把扫描风险等级写入元数据、
  运行时读取以提高默认风险。
- **动态沙箱行为分析**：二进制/脚本仅静态层（strings + 指标），未确认真实
  运行时读写/外发行为（`capabilities.yaml` 已声明）。
- **大规模误报率基线**：尚未在真实 Skill 样本集上校准 FP/FN 率。

## 四、与上游技能规范的关系（为何不照搬）

上游 skill-creator 面向「可自我进化的能力单元」，要求本体 TBox/RBox/ABox
映射、KSTAR 因果进化钩子、EvolutionCampaign 等。skill-sentry 是**确定性安全
扫描器**，其本质要求「规则命中即命中、行为可预测可审计、fail-closed」，与
「自我进化」相悖。因此本声明**仅借鉴其证据校准精神**
（`declared → packaged → engine_bound → evidence_validated`，不得凭文档声称
能力），不引入其本体/进化框架，避免把扫描器过度工程化成它不该成为的东西。
