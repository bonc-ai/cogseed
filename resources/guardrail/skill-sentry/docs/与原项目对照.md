# 与原项目（artifact-security-review）对照

## 一句话

原项目是「四维治理评测套件」的一个维度（且混入 Agent/治理平台专属检查）；
本扫描器把安全维度**摘出来、收窄到只针对 Skill**，重组为可独立集成的强制入口。

## 复用 vs 新建 vs 删除

### 直接复用（方法论/规则搬运）
- 密钥正则库（原 `security_patterns.yaml` → 本 `02_rules/secret_patterns.yaml`）
- zip 安全解压 `safe_extract()`
- “以 SKILL.md 为根定位 Skill 目录”的思路（原 `scan_skillspector` 内 → 本 `locate_skill_roots`）
- 危险命令 / 权限 / 审计 / HITL / 供应链 的关键词判定思路（原 `static_security_profile`）
- gitleaks 调用方式

### 新建（原项目没有）
- SQL 注入、隐蔽持久化、可疑网络地址、Prompt Injection 载荷 规则
- 依赖漏洞 CVE 扫描（接 osv-scanner）
- 二进制静态行为分析子模块 `binary_scan.py`
- 9 字段结构化输出（Security Score / Risk Classification / Attack Surface /
  Permission Summary / Data Access Summary / Dangerous Action List /
  Vulnerability Findings / Required Mitigations / Deployment Recommendation）
- 加权打分 + 风险分级 + 一票否决 模型
- `scan()` 可编程调用契约 + `--fail-on` CI 阻断契约

### 删除（不属于 Skill 安全扫描）
- P3394 Agent 公共接口检查（Agent 专属，Skill 无 channels/handle_message）
- KSTAR K0-K6（治理平台专属）
- Validation / Red-team / Business Correctness 三个维度整体
- Promptfoo 红队工具链（Node.js 依赖）
- `evaluate_dimensions()` 四维编排框架
- SR-09 对 P3394 状态的依赖

## 对照需求 3.3 的覆盖度

| 3.3 要求 | 原项目 | 本扫描器 |
|---|---|---|
| 危险系统命令 | 有 | 有（增强） |
| Shell 注入 | 有 | 有 |
| SQL 注入 | 无 | 新增 |
| 文件删除/批量修改 | 部分 | 新增批量删除模式 |
| 明文密钥 | 有（强） | 复用（强） |
| 恶意代码 | 无 | 部分（模式级；建议接 YARA） |
| Prompt Injection 载荷 | 仅“是否声明防护” | 升级为“检出实际载荷” |
| System Prompt 抽取 | 弱 | 新增载荷检测 |
| 依赖漏洞 | 无（仅版本pin） | 新增（osv-scanner） |
| 过度权限声明 | 有 | 有 |
| 隐藏网络调用 | 弱 | 有（文本+二进制线索） |
| 可疑网络地址 | 无 | 新增 |
| 未授权外部下载 | 部分 | 有 |
| 动态代码执行 | 有 | 有 |
| 隐蔽持久化 | 无 | 新增 |
| 数据外传 | 弱 | 有（文本+二进制线索） |
| 破坏性动作 | 部分 | 有 |
| **二进制行为分析** | **无** | **静态层有，动态层待立项** |
| 9 个输出字段 | 无 | 全部新增 |

## 诚实结论

文本类风险（密钥/危险命令/权限/注入模式）已达到可用水准；行为类风险
（二进制真实运行时行为、恶意代码深度检测）仍是静态近似，要达到 3.3 完整目标
需要动态沙箱和专业引擎，属于后续独立项目，不是本次改造能一次补齐的。
