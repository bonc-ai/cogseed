## 3. 未完成任务分发

### 3.1 牛保康：远程入口、导入、确认层

协作方式：

- 以**异步交付**为主：录屏、截图、文档、确认记录、日志都要能独立验收。
- 不依赖线下同场；每个输出都必须可回放、可复核。
- 需要和张照航保持每日一次短同步，只对齐阻塞项，不做长会。

负责任务：

- **US-01 Mac端快速启动**（补齐正式启动体验和启动证据）
- **US-02 导入项目并掌控上下文**
- **US-04 执行前确认目标和 Context**
- **US-10 Personal Ontology 确认**

交付重点：

- 启动录屏、环境记录、Known Issues
- 固定 Repo / 固定 Commit 导入
- ReferenceManifest
- TaskContract 确认页或确认记录
- PersonalOntologyRef 展示与修订记录

为什么归牛保康：

- 这些任务最偏入口体验、产品感知和用户确认流程。
- 远程状态下尤其适合做成“可录屏、可截图、可文档闭环”的交付。
- 需要把“能看懂、能确认、能继续”先做稳。

### 3.2 吴嘉宇：理解、运行、评估层

负责任务：

- **US-03 校准系统对项目的理解**
- **US-05 启动真实 Agent 并掌握运行状态**
- **US-11 Skill 展示与评价基线**
- **EN-01 统一 KSTAR 运行与评估记录**（主责）
- **反假调度 / 失败可见**（必须并入 US-05 前置）

交付重点：

- ProjectContext：目标、技术栈、关键文件、来源、不确定项
- AgentRun、RunEvent、真实日志
- 失败状态可见，不可伪装成功
- SkillManifestRef、SkillRun、EvaluationRecord
- 统一 Schema 样例和字段规范

为什么归吴嘉宇：

- 这部分是“理解 → 执行 → 评估”的主链路。
- 需要把真实运行和结构化证据做扎实。
