# P3394 会议对照与 Dashboard 后续事项

日期：2026-08-16  
来源：P3394 协议提出者、开创者今日会议内容整理  
适用范围：CogSeed / P3394 Bridge Runtime

## 1. 今日会议要点

### 1.1 P3394 作为底层通信标准

项目将采用 P3394 作为底层通信标准，使本地、远程、Web 等不同形态的 Agent 能够互联互通。协议核心包括：

- Universal Message Format（UMF）：统一消息封装与语义传输格式；
- Manifest：Agent 身份、角色和能力声明；
- Session：会话及任务上下文管理；
- Channel：Agent 之间的通信通道。

### 1.2 本地优先与安全

本地运行的 Agent，包括本地模型和插件，应托管在用户本地沙箱或等价的本地主权边界内，以保障数据安全和隐私。远程连接、Web 接入和跨节点协作不能绕过本地身份、Session、Runtime、凭据、权限和审计边界。

### 1.3 后续 Dashboard 方向

后续可考虑建设一个 P3394 Dashboard，用于统一管理和监控多个正在运行的 Agent 及其 Session 状态。该事项是协议核心闭环完成后的产品化方向，不改变当前 Bridge Runtime 的协议实施顺序。

## 3. Dashboard 后续建议

### 3.1 目标

在 P3394 核心闭环完成后，为用户提供一个本地优先的运行态控制面，集中查看和管理已授权的 Agent、Node、Channel、Work Session 与 Task，不取代各 Agent 的本地 Session Authority 和 Runtime Authority。

### 3.2 第一版候选范围

- Agent / Node 列表：`agent_id`、alias、node kind、locality、在线状态、Manifest 摘要；
- Channel 状态：Channel Instance、连接状态、认证状态、最近心跳、重连状态；
- Session 总览：`session_id`、goal 摘要、参与者、当前状态、关联 Task、最近活动时间；
- Task 运行态：排队、执行、成功、失败、取消、恢复状态；
- 事件与审计：response、event、error、artifact、cancel、resume 及恢复结果的可追溯摘要；
- 控制操作：在已有权限和人工确认规则下执行暂停、恢复、取消、重连和查看详情。

### 3.3 必须保持的边界

- Dashboard 是观察和受控操作面，不是新的 P3394 Session Store；
- Renderer 不能声明或覆盖 Agent Identity、Manifest、Capability、用户范围或权限；
- 展示数据必须来自 Backend、Runtime Controller、Event Store、Audit Journal 和 Registry 等事实来源；
- 不展示 token、secret、完整模型上下文或未授权长期记忆；
- 高风险操作继续保留人工确认；
- Web Dashboard 若实施，应先经过认证、授权、资源限制、审计和远程披露评审，不默认开放公网。

### 3.4 进入条件

满足以下条件后再立项设计和开发：

1. 真实 Runtime Adapter 已接通 Session、Task、Event 和 Recovery 事实来源；
2. 两个独立 Local Bridge 已完成双向闭环；
3. 同机 Channel 已具备认证、重连、幂等和恢复证据；
4. Doctor、Conformance 和审计边界达到可支撑运行态展示的程度；
5. 明确 Dashboard 是本地桌面控制面，还是未来受控 Web 控制面。

## 4. 当前结论

P3394 的协议方向与现有实施指挥书一致，本次会议内容属于对既定架构边界的再次确认和产品化延展。当前优先级仍是 UMF、Manifest、Session、Channel、真实 Runtime Adapter、双 Local Bridge、安全和 Conformance；Dashboard 记录为后续规划，不作为当前“P3394 Bridge Runtime 已完成”的依据。
