# 报销 Task Agent 接入 Mate 说明

> 状态：Mate 内嵌工作台已接入并处于开发验收阶段。独立浏览器工作台是否退役需单独完成迁移、回归与发布评审，本说明不把它视为已经退役。

> 需求依据：`docs/superpowers/plans/` 和 `docs/superpowers/specs/` 保存的是实施过程稿与待评审设计稿，用于追溯讨论，不等同于已批准需求。生产边界以已合入代码、自动化测试、人工验收和正式评审结论为准。

## 接入方式

报销能力以 Mate 内置 marketplace Agent
`resources/builtin/marketplace/agents/c045605cb916/` 分发。它声明
`management_surface: "expense_workbench"`，因此 Agent 详情页会显示“管理”入口。
其他 Agent 不会显示该入口，也不会加载报销业务模块。

用户流程是：

```text
AI 团队
  -> 本地报销准备助手
  -> 管理
  -> 选择报销项目目录（首次使用）
  -> Mate 内嵌报销工作台
```

工作台保留七个区域：报销助手、报销申请、预审会话、工作台、人工复核、连接配置和审计记录。
它在 Mate 当前窗口内渲染，不打开浏览器、不导航到 localhost，也不启动报销项目的 HTTP 服务。

## 进程与数据边界

Mate 主进程通过受控的 JSONL stdio 入口启动报销项目：

```text
<project>/.venv/bin/python3 -m expense_reimbursement.task_agent.stdio_bridge
```

项目目录必须是用户选择的绝对目录，包含 `.venv` 和
`src/expense_reimbursement/task_agent/stdio_bridge.py`。Mate 会校验目录、解释器和桥接文件边界，
并按当前用户与项目复用一个串行桥接进程。进程退出、超时、无效 JSON 和超过响应上限都会变成可操作的错误；
不会通过 shell 拼接命令，也不会创建 HTTP 监听端口。

报销申请、不可变草稿版本、材料、预审、人工复核和审计记录仍由报销项目的统一 Application 服务和数据库维护。
Mate 只保存本地工作台项目配置和页面状态，不复制业务事实到聊天 JSONL 或 Mate 数据库。

## 工作台操作

- “报销助手”可以创建或选中案件，并执行受控的检查或预审动作。
- “报销申请”可以创建申请、编辑 JSON 草稿、登记受控材料、保存新版本和生成草稿报告。
- “预审会话”展示与当前申请版本绑定的预审结果和原因。
- “工作台”显示申请统计；“人工复核”显示待处理的复核任务；“连接配置”只显示安全的项目/连接状态；“审计记录”显示脱敏事件。

草稿、预审结果和草稿报告永远不等同于提交、审批、验真或付款。提交、审批、外发和付款仍停在人工确认闸门之后。
项目不可用、材料缺失、模型或外部连接不可用时，界面保留已有事实并显示 `needs_review` 或明确的错误，不猜测成功。

## 飞书审批流程

当申请的目标是 `feishu` + `feishu-approval` 时，工作台会按以下顺序开放动作：

1. 用户在“连接配置”中主动点击飞书预检。页面加载不会自动访问飞书；Mate 主进程先显示外部访问确认，只有用户明确允许后才调用报销项目，并且只把脱敏状态返回页面。Mate 不保存或显示 App Secret，也不启动 HTTP 服务。
2. 在“报销申请”保存草稿、登记材料并执行预审。只有当前不可变版本为 `ready_for_confirmation` 时才显示“确认并提交飞书审批”。
3. 用户点击提交后，Mate 主进程再次读取申请版本、哈希、目标和预审结果，弹出人工确认；确认通过后才生成一次性、短时有效的主进程凭证。
4. 凭证只经 Mate 主进程传给 stdio bridge。报销项目消费凭证、记录确认，再调用现有 `FeishuApprovalAdapter` 创建飞书审批实例；凭证不会返回 renderer，也不会写入聊天内容。
5. 页面显示飞书实例已提交并等待人工审批。后续外部状态查询、恢复或重试只能由界面上的明确动作触发，并再次经过主进程确认；状态以飞书查询/回调为准。

提交结果为 `submission_unknown` 或请求超时时，不要直接再次提交；先刷新状态或按报销项目的恢复流程核对原实例，避免重复创建审批。

保存草稿必须使用当前申请版本的 `expected_version`。版本冲突不会自动覆盖，界面要求重新读取并核对当前版本。
材料只能由 Mate 文件选择器提供，桥接只接受验证过的 `workspace://` 引用和材料类别。

## 桥接协议

桥接使用一行一请求、一行一响应的 JSONL 信封：

```json
{"request_id":"opaque","operation":"applications.get","user_id":"host-bound","payload":{"application_id":"RA-..."}}
```

成功响应为 `{"request_id":"opaque","ok":true,"result":{...}}`；失败响应包含稳定的
`code`、安全消息和 `retryable`。桥接会拒绝空行、重复请求号、未知操作、超大请求、非法材料和越权申请。
返回结果经过安全投影，不包含 user id、绝对路径、凭据或确认能力。

当前操作族覆盖 manifest/health、申请列表/详情/创建/草稿/预审/报告、材料列表/登记、人工复核、审计、
连接状态和案件内助手检查，以及只读飞书预检、显式确认后的提交和外部实例状态刷新。旧 `new` / `answer` / `status` / `report` 会话命令不是 Mate 工作台协议。

## 安装与验收

报销项目只需准备 Python 虚拟环境和依赖：

```bash
cd '/path/to/报销智能体'
python3 -m venv .venv
.venv/bin/python3 -m pip install -r requirements.txt
```

真实飞书审批只能按报销项目自身的部署文档，在其受控、用户私有的运行环境中配置。不要把凭据路径、App Secret 或其他认证材料写进 Mate 文档、仓库或页面。stdio bridge 只消费报销项目已经安全管理的配置并执行权限校验；renderer 只接收脱敏状态。

启动 Mate 后按“AI 团队 → 本地报销准备助手 → 管理”进入。首次选择项目目录后，按顺序验证：创建申请、保存一笔有效费用明细、运行预审、查看人工复核/审计、生成草稿报告。
验证期间可以用 `lsof -nP -iTCP -sTCP:LISTEN` 检查没有由 Mate 或 stdio 桥接产生的报销 HTTP 端口。

## 安全边界

- Renderer 只经 `window.orkas.invoke`/`window.orkas.stream` 调用工作台；不调用报销 HTTP API。
- 当前用户和 Agent 管理界面由主进程重新校验；renderer 不能传入 user id、shell 命令、确认 token 或任意路径。
- 页面加载不自动连接飞书；预检、提交、状态查询、恢复和重试均需用户从对应界面发起，并由主进程执行外部操作确认。没有安全界面入口的兼容操作一律拒绝。
- 项目绝对路径只留在主进程配置中，不进入页面报表、聊天、审计标签或材料说明。
- 领域服务仍是 T-BOX、R-BOX、A-BOX、规则、材料授权和审批闸门的唯一业务真相。
- 外部适配器返回不确定或失败时，不会被包装成已提交、已批准、已验真或已付款。
