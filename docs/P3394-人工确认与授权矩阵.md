# P3394 人工确认与授权矩阵

日期：2026-08-16  
适用：CogSeed P3394 Bridge Runtime  
来源：`docs/P3394-Bridge-Runtime-实施指挥书.md` §5/§8/§9、Conformance Matrix S-07

## 原则

认证（你是谁）≠ 授权（你能做什么）≠ 人工确认（需要人拍板）。

- **认证**：Bearer token / 注册表身份解析，fail-closed；
- **授权**：Manifest capability + performative + node_kind 准入，fail-closed；
- **人工确认**：写入长期记忆 / 学习治理、改变信任与权限、突破本地主权边界、
  高风险控制操作——保留人工确认点，不因"对端已认证"而自动放行。

## 操作映射矩阵

| 操作 | 来源 | 风险 | 认证 | 授权 | 人工确认 | 强制点 |
|---|---|---|---|---|---|---|
| 入站 task/message 执行 | 已注册 peer | 中 | 是 | 是（handle_message + performative） | 否 | `bridge.ts::validateRecipientAdmission` |
| 跨节点 cancel | 已注册 peer | 中高 | 是 | 是 | 否 | Kernel 准入 + `executor.ts` `control.cancel` 审计（谁取消了什么任务，可追溯） |
| resume / 恢复续读 | 自动恢复控制器 | 中 | 本节点内部 | — | 否 | `recovery-controller.ts` maxAttempts + 持久化游标，不重新 deliver |
| §11 自动回发 | 本节点 | 中 | 对端 token | 否 | 否（对端先开口 + 端点白名单） | `executor.ts` reply_endpoint allowlist（loopback / 已注册 peer 端点），防 SSRF |
| peer 自注册（hello） | 未注册 sender | 高 | 是（本机回环 Bearer） | 否 | **是**：仅回环认证者可自注册；更广网络需显式配置 | `app-wiring.ts` hello 处理 + `http-channel.ts` authToken |
| 对象拉取（resource endpoint） | 已注册 peer | 中 | 是 | 否 | 否 | `http-channel.ts` digest 白名单 + Bearer auth |
| Session close → KSTAR/Recall | 本节点 / 对端 | 高（写入学习治理） | 是 | 是 | **是**：`proposed_updates` 只提案不自动晋升；晋升走既有 Recall governance 人工确认 | `kstar-close-hook.ts` + `recall-bridge.ts` |
| 信任升级（trust_policy 变更） | 本机配置 | 高 | — | — | **是**：默认固定 `p3394-bearer`，更高级信任需显式配置 | `registry.ts` trust_policy / expected_identity |

## 边界

- Renderer 不能声明或覆盖 Identity、Manifest、Capability、user scope 或权限；
- 认证过的 peer 不等于获得全部能力：capability discovery ≠ authorization；
- 高风险操作的审计必须包含 actor、目标 task/session 与结果，且不泄露 secret；
- Dashboard（后续产品化）在既有权限、策略和人工确认约束下只做观察与受控操作。
