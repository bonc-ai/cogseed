## 1. 八列对比表

| 维度 | WorkBuddy（腾讯云） | Codex（OpenAI） | Mate Agent 伴侣智能体（本项目目标形态） |
|------|---------------------|------------------|------------------------------------------|
| **① 产品定位** | 全场景职场 AI 智能体桌面工作台（面向非技术办公人群：HR/行政/运营/分析师） | 开发者软件工程智能体（CLI/IDE/App/云端并行任务） | 面向**各行各业**的个人伴侣智能体（学生为首个场景案例）：身份授权 → 资源选择 → 本体确认 → 执行汇报 |
| **② 执行位置** | 本地桌面客户端执行（数据不强制上云）；远程指令亦触发本地执行 | 双轨：本地 CLI/IDE 执行 + 云端环境执行（云任务/workspace agents，关掉电脑仍运行） | 本地单进程 Electron 执行（PC 主进程）；无云端 agent 执行（release 线明确不做） |
| **③ 接入触点** | 微信（客服号/小程序/ClawBot）、企业微信、QQ、钉钉、飞书、Slack、Discord、元宝；多平台同时可绑 | Slack（@Codex 线程）、GitHub（PR/issue）、Linear（issue 委派）；WhatsApp 触点经 1-800-ChatGPT 消费入口（非任务分发） | 飞书主页会话（MVP）；微信/邮件为二期预留（ConnectorProvider 接口就位不实现） |
| **④ 身份绑定/认证** | 扫码免凭证：微信/企微扫码即绑，指令经腾讯安全网关代理（无需公网 IP/内网穿透）；企微/QQ 需应用配置 | 需 ChatGPT 付费套餐 + GitHub 连接 + 云环境配置（开发者级设置）；Slack 需管理员审批安装 | 双身份分离：机器人令牌（现有注册体系）+ 用户 OAuth（`tenant+union_id` 稳定键、open_id 兜底）；双向绑定（机器人侧 + 桌面端） |
| **⑤ 上下文获取** | 远程任务固定「助理专属文件夹 + 完整对话历史不可清空」；本地任务可指定工作目录 + `@` 引用文档 | 线程即上下文：@Codex 自动读取所在线程历史，无需重述；云端环境基于 GitHub 仓库 | 本体治理后上下文：新会话只出现「已确认事实」；回答带来源引用；飞书话题内提问自动带会话上下文 |
| **⑥ 主动触达/自动化** | 自动化模块：定时/监听触发，交付物推送（企微/邮件/本地）；2026-03 起支持后台自动生成日报/周报 | 云任务完成在 Slack 线程回结果链接；push 通知；GitHub 自动 PR 评审（@codex review/fix）；定时/计划任务较弱 | auto_tasks 每日定时（30s tick、claim 防重）；今日简报推主页会话（数据缺失降级通用简报）；主动触达以只读展示为界 |
| **⑦ 权限与安全模型** | 授权目录制：仅操作主动勾选文件夹；系统敏感目录拦截；高危操作二次确认；指令经安全网关语义解析+权限校验 | 云环境隔离（沙箱）；管理员可关 Slack 回帖、监控环境；「always review diffs」免责；本地记忆默认关闭 | 默认只读 + 写入需确认；资源级 scope-manifest 可审计；按范围遗忘（/遗忘 预览→确认）；令牌不落日志/账本/本体；任务 Agent 走 P3394 执行边界 |
| **⑧ 生态与扩展** | 兼容 OpenClaw/Claw 技能生态；20+ 内置技能包；Skill/MCP/Hook/Agent/Rule 五类插件；腾讯文档/ima/微云生态打通 | 开源 CLI（Apache-2.0）+ Skills/插件/MCP server 生态；Codex SDK（TS 起）；GitHub Action 进 CI/CD；workspace agents 可共享 | 场景注册制（新场景=技能/auto_task+本体查询模板，不碰连接器）；SkillLoader + MCP 连接器（现有能力）；候选确认流水线复用 |

> 注：WorkBuddy 微信/企微等 IM 触点是「远程控制台」，指令在本地执行，与「IM 内 AI 回复」是两种形态；Codex 的 Slack 集成则是把任务**委托给云端执行**并回链。两者恰好覆盖「本地执行+IM 遥控」与「云执行+IM 分发」两种主流路径。

## 2. 三条可复制模式

### 模式 1：IM 即遥控器（扫码免凭证，零配置上手）
WorkBuddy Claw 把「手机 IM 发消息 → 本地电脑执行 → 结果回传 IM」做成了三步配置（设置 → 选平台 → 扫码/按指南接入），微信客服号直接扫码绑、无需公网穿透，指令走腾讯安全网关代理。
**可复制点：** 我们的飞书机器人已有 QR 绑定先例；「用户 OAuth 授权个人数据」也应做成**扫码/链接免凭证**而非手动填 token——降低使用者的认知负担（对不熟悉 OAuth 回调/密钥的人群尤其重要，学生场景只是其中之一），身份绑定（tenant+union_id）在扫码瞬间完成。

### 模式 2：线程即上下文（@Codex 免重述）
Codex Slack 集成让用户在一个线程里自然对话，@Codex 自动读取该线程历史作为任务上下文——「像跟同事说话一样」下任务，不必重述背景。
**可复制点：** 飞书主页会话内连续追问（「下周三之前有什么要交的？」→「那周三的课呢？」）应**隐式继承会话上下文**，而不是每次开新 PC 会话丢背景；同时保持「本体已确认事实」注入、原始对话不外泄到系统提示词（现有 session-kind 隔离思路延续）。

### 模式 3：后台自动化 + 结果送达（简报/日报交付闭环）
WorkBuddy 自动化模块支持定时任务并把交付物推送到企微/邮件；Codex 云任务完成后在 Slack 线程回结果链接。两者都验证了「定时触发 → 执行 → 结果主动送达到用户所在处」的闭环价值。
**可复制点：** 今日简报 = auto_tasks 定时 + 本体/日历聚合 + 主页会话推送（设计稿 §5.6 已是此形状）；**关键差异在于我们的简报是只读展示 + 数据缺失降级**，不需要用户确认，比 WorkBuddy「任务交付物」更轻、更适合作每日默认体验。

## 3. 差异化机会

1. **本体治理层（竞品空白）**：WorkBuddy 是目录级授权（勾选文件夹），Codex 是云环境/仓库级授权，二者都是「授权即全读」；没有任何一家做「资源 → 候选实体 → 用户逐条确认 → 进入上下文」。我们把「本体确认流水线」做成用户可感知的治理体验（待确认卡片 + /权限 + /遗忘），这是从「AI 替你看文件」到「AI 只记得你确认过的事」的定位差异，也是隐私叙事的主战场。
2. **人群不锁死的通用个人上下文（结构优势）**：WorkBuddy 锁定职场办公人群、Codex 锁定开发者，二者都按人群垂直化。我们的连接器框架 + 本体治理 + 场景注册制**不锁人群**——学生（学期地图、课程-截止推理、空闲时段建议）只是首个场景案例，职场交付、个人效率等场景通过「场景 = 技能/auto_task + 本体查询模板」注册制扩展，连接器与本体代码零改动。竞品要覆盖到我们这种「个人数据治理 + 多场景注册」形态，需要先重构其人群绑定架构。
3. **开源 + 本地 + 数据自理**：WorkBuddy 绑定腾讯云账号与网关、Codex 绑定 ChatGPT 订阅与云端执行，两者都深度绑定厂商云。我们是 open-source 本地优先、个人数据（OAuth 凭据机器私有 + 云同步用户私有）可迁移、可撤销——对隐私敏感用户（学术/个人生活场景等）是结构性优势；配合「撤销 OAuth → 停同步 + 资源失效」的可退出承诺，可做成信任卖点而非功能卖点。

## 4. 对 MVP 的取舍建议（供组会讨论）

- **保留**：飞书单一触点（竞品多触点靠的是各自生态与人力，MVP 聚焦主页会话足够验证闭环）。
- **借鉴**：WorkBuddy「扫码免凭证绑定」降低 OAuth 接入摩擦；Codex「线程上下文」强化飞书会话内追问体验。
- **不学**：Codex 的 Slack 云任务分发（我们 release 线无云端执行）；WorkBuddy 的多 Agent 并行（当前无此需求）。
