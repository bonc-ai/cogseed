# 命令草案：`/权限` 与 `/遗忘`（个人上下文治理命令）

**日期：** 2026-08-10
**作者：** 牛保康（C 线）
**状态：** 草案（供组会评审，不进入本分支实现）
**关联设计：** `docs/superpowers/specs/2026-08-10-feishu-companion-context-design.md`
§2.2（持续治理）、§6（权限与治理）
**结论先行：** 两条命令一读一写，共享同一个**范围模型**（scope 文法），
`/权限` 只读展示授权全景，`/遗忘` 读后写（预览 → 确认 → 删除/失效），
默认只读原则下 `/遗忘` 是 MVP 唯一允许的用户主动删除入口。

---

## 1. 设计原则

1. **默认只读**：`/权限` 无副作用；`/遗忘` 必须先预览后执行，执行需用户在飞书会话内二次确认（与现有确认卡片交互一致）。
2. **范围即语法**：两条命令的操作对象都是「范围」，范围文法统一（§3），避免各写各的。
3. **可追溯**：遗忘不是物理删除来源（provider 上的原始数据用户自行处理），而是**在本机语义层失效**——删除/失效注册表引用与派生候选，本体已确认事实按策略保留或降级（§4.4）。
4. **命令接入点**：复用 messaging 入站 slash 命令先例（`manager.ts::isNewSessionCommand` 拦截 `/new`、`/reset` 的同一位置模式）；新命令由 `personal_context` 侧注册，不修改 messaging 文件。

## 2. `/权限`（只读）

### 2.1 语义

展示当前用户对伴侣智能体的**授权全景**，一句话回答「AI 现在知道什么、能动什么」：

```
/权限
```

### 2.2 输出结构（文本/卡片，缺什么不渲染什么）

| 区块 | 内容 | 数据来源 |
|------|------|----------|
| 已连接实例 | 飞书实例名、租户品牌、连接状态（connected/error） | `messaging.proactive.listTargets` 视图 |
| 已授权数据 | 接入资源清单：类型（日历/文档/文件夹）、数量、最近同步时间 | `cloud/context/registry.json` |
| 待审批事项 | 本体候选池条数、写操作审批队列条数（二期） | `personal_ontology_candidates` 池 |
| 生效中的简报任务 | 每日简报任务与目标会话（可一键暂停） | `auto_tasks` 列表 |
| 撤销入口 | 每个 OAuth 授权的撤销按钮/命令（`/权限 撤销 <provider>`，草案二期） | oauth-manager |

### 2.3 边界

- 只读、无确认流程；输出不含令牌、不含 open_id 明文（隐私）。
- 无任何授权时输出空态引导文案（"尚未连接飞书，私聊机器人发起绑定"）。

## 3. 范围模型（两条命令共用）

### 3.1 scope 文法（草案）

```
scope        := provider | type | resource | time | all
provider     := 'feishu'
type         := provider ':' resourceType            # feishu:calendar | feishu:document | feishu:folder | feishu:chat
resource     := type ':' stableId                    # feishu:calendar:cal_xxx
time         := type ':' 'since:' date               # feishu:calendar:since:2026-07-01
all          := 'all' | provider ':all'
```

- `stableId` = `ExternalResource.resourceId` 的尾段（幂等键规范格式，见设计稿 §5.1）。
- **缺省 scope**：`/遗忘` 不带参数 → 拒绝执行，回显语法帮助（防误删）。
- 未来 provider 扩展（wechat/email）文法不变，前缀即命名空间。

### 3.2 可遗忘单元（范围 → 影响的本地数据）

| 范围 | 注册表引用 | 派生候选 | 本体已确认事实 | 同步游标 |
|------|-----------|----------|---------------|----------|
| `feishu:calendar` | 删除全部日历资源 | 失效来源=日历的候选 | 保留（标记来源失效） | 重置该类型游标 |
| `feishu:calendar:cal_xxx` | 删除该资源 | 同上（限定来源） | 同上 | 单资源游标 |
| `feishu:document:since:…` | 按时间裁剪 | 同上 | 同上 | 回退水位 |
| `feishu:all` | 全部 | 全部候选失效 | 保留（标记来源失效） | 全部重置 |
| `all` | 全部 provider | 全部候选失效 | 保留 | 全部重置 + 撤销 OAuth（需额外确认） |

> 「本体已确认事实」是用户治理后的资产，默认**保留但标记来源失效**（`source_ref` 失效标注，
> 不删除语义事实）；显式 `--hard` 才删除事实本体（默认不提供，防误删，二期评审后开放）。

## 4. `/遗忘 <scope>`（读后写）

### 4.1 语义

```
/遗忘 <scope>          # 第一步：只预览，不执行
/遗忘 确认             # 第二步：在预览上下文内确认执行（绑定预览快照）
/遗忘 取消             # 取消
```

- 预览输出：受影响资源数、候选数、本体事实数、游标重置说明——**与确认执行用同一 scope 快照**，
  确认期间 scope 变化（新同步到达）不扩大执行面（快照隔离）。
- 执行输出：完成清单（每类受影响项的实际处理数）+ 撤销指引（如需恢复 → 重新授权 + 增量回填）。

### 4.2 执行动作（幂等、可重复执行）

1. 注册表：删除/标记失效匹配的 `ExternalResource` 条目；
2. 候选池：匹配来源的候选**失效**（进 blocked/回收位，不静默消失）；
3. 本体事实：`source_ref` 前缀匹配的条目标注来源失效（保留语义文本）；
4. 游标：按范围重置（重授权后从回填窗口重新拉取）；
5. 撤销 OAuth（仅 `feishu:all` + `--revoke` 显式要求）：停同步、令牌删除、实例状态置 disconnected。

### 4.3 与撤销 OAuth 的区别

| 操作 | 影响 | 是否停同步 |
|------|------|-----------|
| `/遗忘 <scope>` | 本地语义层失效（引用/候选/游标） | 否（其余资源继续同步） |
| 撤销 OAuth（`/权限` 入口） | 停同步 + 令牌删除 + 全部资源失效 | 是 |

### 4.4 数据保留策略

| 数据 | 默认 | 说明 |
|------|------|------|
| 外部来源原始数据 | 不动 | provider 侧由用户自行处理，本机不越权删 |
| 注册表引用 | 删除 | 语义层不再引用 |
| 派生候选 | 失效回收 | 避免「已遗忘」内容通过新候选回流 |
| 本体已确认事实 | 保留+标记失效 | 场景层查询时过滤失效来源（不污染新会话上下文） |
| 令牌/游标 | 按范围处理 | 见 §4.2 |

## 5. 安全与边界（红线）

- 命令只在**绑定会话（归属人主页会话/私聊）**生效；群聊中仅归属人本人可执行 `/遗忘`，其他人收到无权限提示。
- `/遗忘` 执行前必须二次确认；确认令牌绑定预览快照，防「预览后新数据被一并删除」。
- 命令输出与操作日志不落令牌、不落 open_id 明文。
- 本草案不修改 `messaging/`、`personal_ontology_*` 文件：候选失效/本体标注经由其既有 API
  （`rejectCandidate` / 来源标注）完成，接入点由 `personal_context` 命令处理器注册。

## 6. 实施顺序建议

1. 阶段 2（连接器框架落地后）：`/权限` 只读展示（registry + candidates + listTargets 已有数据）。
2. 阶段 3：`/遗忘` 预览 + 确认 + 执行（scope 解析与快照为纯函数，可先行单测）。
3. 二期：`--revoke`、`--hard`、写操作审批队列在 `/权限` 中展示。
