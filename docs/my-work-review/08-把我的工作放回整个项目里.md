## 1. 这是个什么东西

CogSeed 是一个 **Electron 桌面伴随式 Agent**。

```
┌──────────────────────────────────────────────────────────────┐
│  Electron 单进程应用（不是 C/S，没有 HTTP server，不占端口）    │
│                                                               │
│  ┌──────────────────┐          ┌──────────────────────────┐  │
│  │  Renderer 进程    │   IPC    │      Main 进程           │  │
│  │  （浏览器沙箱）    │◄────────►│    （Node 后端）         │  │
│  │                  │ 唯一通道  │                          │  │
│  │  纯 HTML/CSS/JS   │          │  TypeScript              │  │
│  │  无框架、无打包器  │          │  完整 Node 能力           │  │
│  └──────────────────┘          └──────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

**几条会直接影响你写代码的硬约束**（来自 AGENTS.md）：

- 渲染层**没有** TypeScript、没有 JSX、没有打包器 —— 只有 classic script
  → 这就是为什么 `skills.js` 是 7991 行的一个大文件，而不是拆成组件
- `src/main/preload.js` **必须是 `.js`**
- 用户数据主要是 **JSON/JSONL 文件**，不是数据库（sqlite 只留给向量库）
- LLM 调用走进程内的 `core-agent`，**动态 import**

## 2. 分层规则（你必须记住这个）

```
ipc/         只校验参数、调 feature          绝不含业务逻辑
features/    业务工作流                      可用 storage/paths/prompts/model/util/兄弟 feature
model/       模型调用适配器                  不读写 data/ 下的业务数据
util/        纯函数、基础设施                 绝不反向 import features/model
storage.ts   存储/路径的收口点
i18n.ts      可读 locales，但不 import features/model
```

**依赖方向永远单向**：`ipc → features → util`。

**为什么**：如果 `util` 能 import `features`，就会循环依赖，
而且 `util` 就不再是「可以在任何地方安全调用」的东西了。

## 5. 我的上游与下游

```
        ┌──────────────── 上游（给我原材料） ────────────────┐
        │                                                    │
   chats/messaging        personal_ontology_*      kstar/task-closure
   （会话内容）            （个人本体候选）          （任务闭环沉淀）
        │                        │                          │
        └────────────┬───────────┴──────────────────────────┘
                     ▼
        ┌────────────────────────────────────────┐
        │         ★ features/recall/ ★           │
        │  candidate → asset → selection → proof  │
        └────────────────────────────────────────┘
                     │
        ┌────────────┴───────────┬────────────────────────┐
        ▼                        ▼                        ▼
  group_chat/bus.ts      cogseed_backend/        p3394/capability-pack
  （注入到会话）          runtime-asset-context    （打包给外部执行端）
                        （注入到 Runtime）
        │                        │                        │
        └────────────┬───────────┴────────────────────────┘
                     ▼
        ┌─────────── 下游（消费我的数据） ───────────┐
              Agent 的提示词里真的出现了这条认知
                     │
                     ▼
              执行 → 效果 → 回传证据给我
```

**读懂这张图 = 读懂你的位置。**

上游给「原材料」（会话、本体、任务结果），
你负责「把它变成可信、可治理、可追溯的认知资产」，
下游负责「在正确时机用起来，并把结果回传给你做证明」。

**注意这是一个环，不是一条线。** 下游的执行结果会变成新的证据回到你这里
（transfer proof / effectiveness proof）——这就是为什么经历 4 的回执缺失
会让整个环断掉。
