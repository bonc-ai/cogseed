```bash
# 某一天的工作
git log --all --author='shiyuxuan581@gmail.com' --no-merges \
  --since=2026-08-17 --until=2026-08-18 --format='%h %s'
```

## 8.2 查一个 commit

```bash
git log -1 --format='%B' <hash>          # 完整 body（最有价值）
git show <hash> --stat                    # 改了哪些文件
git show <hash> -- <某个文件>              # 单文件 diff
git log --oneline <hash>..HEAD -- <文件>  # 这个改动后来有没有被再改
```

## 8.3 查一个文件

```bash
git log --oneline -- <path>                    # 完整历史
git log --diff-filter=A --oneline -- <path>    # 谁创建的
git log --diff-filter=D --oneline -- <path>    # 谁删的
git blame <path>                               # 每一行是谁写的
git log -S '某行代码' --oneline -- <path>       # 这行何时引入/删除
```

## 8.4 查分支关系

```bash
git merge-base --is-ancestor <分支> origin/develop && echo "已并入" || echo "未并入"
git rev-list --count origin/develop..<分支>    # 领先多少个提交
git branch -a --contains <hash>                # 这个提交在哪些分支上
git worktree list
```

## 8.5 查身份归属

```bash
# 全仓所有作者
git log --all --format='%an <%ae>' | sort | uniq -c | sort -rn

# 本机真实创建的提交（reflog 证据）
git reflog --format='%h|%gs' | grep -E '^[0-9a-f]+\|commit' | cut -d'|' -f1
```

# 十、本次分析的方法说明

## 10.1 归属判定原则

1. **`--no-merges`** —— merge commit 里包含大量他人代码，全部排除
2. **reflog 优先于 author** —— 判断「本机创建」用 reflog，不用 author 字段
3. **diff 优先于 commit message** —— 结论来自实际改动，不来自标题
4. **创建者优先于修改者** —— 「谁创建了这个文件」比「谁改过它」更能说明归属

## 10.2 「我当时的判断」是怎么还原的

| 来源 | 可信度 | 标注方式 |
|---|---|---|
| commit body 里的原文 | 高 | 直接引用 |
| 代码注释里的原文 | 高 | 直接引用 |
| 从修复路径倒推 | 中 | 标注「从提交和修复路径推测」 |
| 无法证明的 | — | 标注「当前证据不足」，不写 |
