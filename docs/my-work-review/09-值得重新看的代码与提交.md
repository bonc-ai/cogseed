# 第三部分：怎么读一个 commit

不要只看 diff。按这个顺序：

```bash
# 1. 先读 body（你当时的诊断记录，这是最有价值的部分）
git log -1 --format='%B' <hash>

# 2. 再看改了哪些文件（判断影响范围）
git show <hash> --stat

# 3. 挑一个最核心的文件看 diff
git show <hash> -- src/main/features/recall/candidate-capabilities.ts

# 4. 看它有没有配套测试
git show <hash> --stat | grep test

# 5. 看这个改动后来有没有被再改
git log --oneline <hash>..HEAD -- <改动的文件>
```

**每读一个 commit，问自己四个问题**：

1. 当时用户看到的现象是什么？
2. 我是怎么从现象定位到根因的？（body 里通常写了）
3. 如果现在让我重新修，我会怎么修？
4. 这个改动**没有**做什么？（往往比做了什么更重要）
