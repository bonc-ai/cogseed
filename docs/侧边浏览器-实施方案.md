# 侧边浏览器（Side Browser）实施方案

| 项 | 值 |
|---|---|
| 目标 | 在侧栏预览本地 HTML 等可视文件，与追问栏共用右侧区域、标签切换 |
| 定位 | 只读本地预览，**不能上外网** |
| 成文日期 | 2026-08-06 |

---

## 1. 现状：已有 80%

项目里**已经能在应用内看 HTML** —— `chat-file-viewer.js` 的 `_renderHtmlBody()`，走 `chat-media://local/<abs>` 协议 + 沙箱 iframe。

安全也已就位：

```js
const sandbox = 'allow-scripts';   // 仅此一项
```

不给 `allow-same-origin`（拿不到 cookie / localStorage / 同源 fetch）、不给 `allow-popups`、不给 `allow-top-navigation`。且 `chat-media://` 与渲染进程 `file://` 不同源，同源策略已挡住 `parent.*`。

**"不能上外网"是这个方案的天然属性** —— 它加载的是本地文件字节流，不是网页。不需要额外加限制。

产物芯片右侧**也已经有「打开文件」按钮**（`chat-msg-produced-open-btn`）。

### 因此本期不需要做的

- 不需要起 HTTP 服务
- 不需要 `WebContentsView`
- 不需要改主窗口 `webPreferences`（不开 `webviewTag`）
- 不需要新的文件读取通道或协议

**真正缺的只有一件事：现在是全屏覆盖层，不是侧栏面板。**

---

## 2. 已确认的设计决定

| # | 决定 |
|---|---|
| 1 | 接受能力边界：有刷新 / 缩放 / 外部打开 / 文件夹显示；**无前进后退、无地址栏、无多标签** |
| 2 | 入口：产物芯片 + 项目文件树，且可视文件在卡片中标注并带打开按钮 |
| 3 | 与追问栏**共用右侧区域**，顶部标签切换 |
| 4 | 只读本地文件，不能上外网 |

### 2.1 关于「前进/后退」

做不到，原因是 iframe 跨域拿不到导航历史 —— 这是浏览器安全模型限制，不是实现取舍。对本地单文件预览也基本无意义。已确认接受。

---

## 3. 右侧面板容器化（核心改动）

### 3.1 问题

追问栏（`chat-aside-panel`）和 md 抽屉（`chat-md-drawer-panel`）现在各是独立 `<aside>`，各自 `hidden` 开合。再加一个浏览器面板，三者会互相挤压主对话列。

### 3.2 方案：共享侧栏宿主 + 标签栏

新增一层容器，三个面板作为它的"页签内容"：

```
┌─ 侧栏宿主 (chat-side-host) ─────────────┐
│ [浏览器] [追问]              [宽度] [×] │  ← 标签栏
│ ─────────────────────────────────────  │
│                                        │
│   （当前激活面板的内容）                │
│                                        │
└────────────────────────────────────────┘
```

- 同一时刻只渲染一个面板（决定 3）
- 标签栏只显示"有内容"的页签：没打开过文件就不显示「浏览器」页签，避免空标签
- 关闭宿主 = 收起整个右侧区域
- �puppet 宽度沿用 `chat-md-drawer-panel` 的既有取值（`min(560px, 50vw)`）

### 3.3 迁移策略

追问栏已上线且有 76 个测试，**不改它的内部实现**，只把它的 `<aside>` 挪进宿主容器、开合改为"激活页签"。

`openChatAside()` / `closeChatAside()` 的外部签名保持不变，内部转为调用宿主的 `activate('aside')` —— 这样 `conversation.js` 里的调用点不用动。

## 4. 浏览器面板

### 4.1 复用而非重写

`_renderHtmlBody()` 目前把 iframe 塞进全屏 overlay。抽出一个可指定挂载容器的版本：

```
renderFilePreviewInto(container, absPath, name, opts)
```

全屏 overlay 与侧栏共用它，**sandbox 串与 `chat-media://` URL 构造完全复用**，不复制安全逻辑。

### 4.2 工具栏

| 按钮 | 实现 |
|---|---|
| 刷新 | 重设 iframe.src（带 cache-buster） |
| 放大 / 缩小 / 重置 | CSS `transform: scale()` + `transform-origin` |
| 在外部浏览器打开 | 走 `shell.openExternal`，需主进程按工作区范围校验路径 |
| 在文件夹中显示 | 复用既有 `workspace.revealPath` |
| 全屏 | 切到现有 overlay |

缩放用 CSS 而非 iframe 内部 zoom：跨域改不了 iframe 内部样式。

### 4.3 支持的文件类型

沿用 `_kindOf()` 的既有分类，侧栏支持 `html` / `pdf` / `image` / `markdown` / `text`。视频音频留在全屏 overlay（侧栏太窄，且播放控件需要空间）。

## 5. 卡片中标注可视文件（决定 2 后半）

### 5.1 现状

产物芯片已有「打开文件」按钮，但**不区分文件是否可视**。用户点一个 `.zip` 才发现打不开。

### 5.2 改动

在 `_iconForProduced` 旁增加一个可视性标记：

- 可视文件（html/pdf/image/md/text）→ 显示「预览」标记 + 打开按钮指向侧栏
- 不可视文件 → 按钮改为「在文件夹中显示」

判定复用 `_kindOf()`，不新写扩展名表 —— 两处各自维护必然漂移。

## 6. 入口（决定 2）

| 入口 | 位置 | 本期 |
|---|---|---|
| 产物芯片「打开」 | `conversation.js` | ✅ 可视文件改为开侧栏 |
| 会话信息面板 | `conversation-info.js` | ✅ 同产物芯片 |
| 搜索结果 | `search.js` | 保持全屏（跨会话场景，侧栏上下文不匹配） |
| 项目文件树 | `project-detail.js` | ❌ **移出本期**，见 6.1 |

`openChatFileViewer()` 增加 `opts.target = 'side' | 'overlay'`，默认 `overlay` 以保持既有 4 个调用点行为不变。

### 6.1 为什么项目文件树移出本期

项目文件**不走 `chat-file-viewer`**，而是 `project-detail.js` 里另一套独立查看器
（`_showProjectTextViewer` / `_showProjectPdfViewer` / …），按后端返回的
`kind` 分派。

而后端的分类里没有 html：

```ts
// features/project_files.ts
export type ProjectFileKind = 'text' | 'pdf' | 'docx' | 'spreadsheet' | 'presentation' | 'image' | 'video';
```

`kindOfName()` 对 `.html` 落到兜底的 `return 'text'`，所以项目里的网页文件
**当前打开看到的是源码而非渲染结果**。

要支持它需要动后端共享类型：

| 改动 | 文件 |
|---|---|
| `ProjectFileKind` 增加 `'html'` | `project_files.ts` |
| `kindOfName` 识别 `.html/.htm` | `project_files.ts` |
| `maxBytesFor` 为 html 定上限 | `project_files.ts` |
| 新增 html 查看分支 | `project-detail.js` |

`ProjectFileKind` 是跨模块共享类型，改动前需先摸清全部消费者；且 `.html`
现在按 `MAX_BYTES_TEXT` 限流，独立成 kind 后上限要重新定（定小了大页面打不开，
定大了有内存风险）。

这条与"让用户方便看到 AI 做出来的页面效果"这一核心场景无关 —— 那些产物走的是
对话侧的芯片。因此本期只做对话侧闭环，项目文件作为下一期增量。

## 7. 安全

复用既有机制，**不新增攻击面**：

- sandbox 串与现有 HTML 预览完全一致（`allow-scripts` only）
- `chat-media://` 的路径校验在主进程侧已实现（工作区 + 附件 + 项目范围）
- 外部打开走 `safeExternalHttpUrl` / `revealPath` 的既有校验
- **不引入** `webviewTag`、不引入 `WebContentsView`、不监听端口

### 明确不做

- 不允许输入网址（无地址栏）
- 不允许 iframe 内导航到 http(s)：sandbox 无 `allow-top-navigation`，且 CSP 层面本地文件无法发起顶层跳转

## 8. 分层落位

| 文件 | 职责 |
|---|---|
| `renderer/modules/chat-side-host.js` | 侧栏宿主：页签注册、激活、宽度、关闭 |
| `renderer/modules/chat-side-browser.js` | 浏览器面板：渲染 + 工具栏 + 缩放 |
| `renderer/modules/chat-file-viewer.js` | 抽出 `renderFilePreviewInto()` 供两处复用 |
| `renderer/modules/chat-aside.js` | 改为向宿主注册页签（内部逻辑不动） |
| `renderer/modules/conversation.js` | 芯片可视标记 + 打开走侧栏 |
| `renderer/index.html` / `style.css` | 宿主容器 + 标签栏样式 |
| `locales/{zh,en,ja,pt}.json` | 文案 |

主进程侧**零改动** —— 这是本方案成本低的根本原因。
