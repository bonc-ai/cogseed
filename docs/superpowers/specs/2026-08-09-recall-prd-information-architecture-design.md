# Recall 内页 PRD 对齐与信息架构简化设计

- 日期：2026-08-09
- 状态：待用户书面复核
- 设计范围：只简化 Recall 内页，不调整现有“工作空间”和“连接”一级入口
- PRD 依据：`P3394_CogSeed_PRD_doc-v0.6_Review(1).docx`
- 当前页面依据：Recall 认知工作台截图及现有 `panel-recall` 页面

## 1. 背景与问题

当前 Recall 内页使用九个并列入口：

1. 总览
2. 数据来源
3. 沉淀任务
4. Brain
5. Context Pack
6. Ontology
7. 候选审核
8. 正式资产
9. 复用证明

这些入口混合了四种不同层级：

- 用户任务：查看来源、审查候选、治理资产；
- 后台流程：沉淀任务；
- 技术对象：Brain、Context Pack、Ontology；
- 结果 Evidence：复用证明。

用户必须先理解内部对象模型，才能判断下一步操作。该结构不符合 PRD 的以下原则：

- 首次使用不要求用户先学习专业术语；
- `RecallView`、`Context Projection` 和最小能力包是派生或运行时对象，不是一级资产；
- Personal Ontology、规则、模板和 Skill 才是正式能力资产分类；
- 用户的主线应是“发现并确认值得保留的认知 → 形成能力资产 → 真实复用并查看证明”。

## 2. 设计目标

1. 将九个主 Tab 收敛为三个用户目标导向入口。
2. 统一认知候选与正式能力资产的分类语义。
3. 隐藏不需要用户理解的英文技术对象名称。
4. 保留现有来源、任务、候选、资产、认知树、能力包和复用证明能力。
5. 不移动工作空间和连接页面，不扩大本轮改造范围。
6. 在不改变正式资产治理规则的前提下，降低用户理解和操作成本。

## 3. 非目标

本设计不包含：

- 调整应用侧边栏整体信息架构；
- 合并或重做现有工作空间页面；
- 合并或重做现有连接页面；
- 改变候选生成、资产晋升、Evidence 或 KSTAR 的业务规则；
- 将候选自动晋升为正式资产；
- 修改底层 `RecallView`、`ContextProjection`、Ontology 或 Receipt 数据结构；
- 新增无 PRD 依据的资产类别。

## 4. 核心信息架构

Recall 外部入口保持不变。Recall 内页主导航调整为：

```text
Recall
├── 总览
├── 认知沉淀
└── 能力资产
```

### 4.1 总览

回答：“现在发生了什么，我下一步该做什么？”

主要内容：

- 当前最重要的下一步；
- 认知沉淀链路摘要；
- 最近工作及处理状态；
- 四类能力资产数量；
- 最近复用证明或待确认复用证明。

### 4.2 认知沉淀

回答：“有哪些内容值得保留？”

内部使用紧凑二级视图：

```text
[待确认] [整理任务] [认知来源]
```

默认打开“待确认”。二级视图不进入主导航，不与能力资产类型混排。

### 4.3 能力资产

回答：“我已经拥有什么，它从哪里来，在哪里被使用？”

包含：

- 四类能力资产列表；
- 认知树摘要；
- 资产版本、作用域和控制；
- 资产使用记录与复用证明；
- 某次复用所用的最小能力包。

## 5. 统一四分类

认知候选与正式能力资产必须使用完全相同的四个平级分类：

```text
关于我
规则与判断
模板与范例
技能与方法
```

“全部”可以作为列表筛选，但不是第五类。

### 5.1 关于我

用户侧含义：

- 长期角色与职责；
- 稳定偏好；
- 工作方式；
- 长期关系；
- 经确认的长期事实。

内部映射：

- 候选：`OntologyDelta`；
- 正式资产：`PersonalOntology`。

产品页面不直接向普通用户显示 `Ontology` 或 `ABox`。

### 5.2 规则与判断

用户侧含义：

- 判断原则；
- 约束和边界；
- 决策规则；
- 适用条件；
- 禁止范围。

内部映射：

- 候选：`RuleCandidate`；
- 正式资产：`Rule`。

### 5.3 模板与范例

用户侧含义：

- 文档模板；
- 检查表；
- 报告结构；
- 可复用范例；
- 结构化输出样式。

内部映射：

- 候选：`TemplateCandidate`；
- 正式资产：`Template`。

### 5.4 技能与方法

用户侧含义：

- 稳定 Action Plan；
- 多步骤工作方法；
- 可复用执行流程；
- 工具调用组合；
- Skill 改进建议。

内部映射：

- 候选：`SkillEvolutionCandidate`；
- 正式资产：`Skill` 或方法型能力资产。

### 5.5 Evaluation 的归类

`EvaluationCandidate` 不形成第五类：

- 判断标准或成功边界 → 规则与判断；
- 评分表、检查表 → 模板与范例；
- 验证流程和方法 → 技能与方法；
- `OutcomeEvaluation` 本身作为 Evidence，不作为资产类别。

### 5.6 分类与状态分离

分类描述“它是什么”；状态描述“它处于什么阶段”。

分类在候选确认和资产晋升过程中默认保持不变，只有用户明确修改分类时才变化。

生命周期状态包括但不限于：

```text
待确认 → 已确认未验证 → 已验证 → 暂停 / 弃用
```

不得将“待确认”“复用证明”“已验证”等状态或 Evidence 混入四类资产统计。


## 7. 页面设计

### 7.1 总览

```text
┌──────────────────────────────────────────────────────────┐
│ CogSeed                                  [刷新]           │
│ 跨 Agent 的个人能力资产层                                │
│                                                          │
│ [总览] [认知沉淀 4] [能力资产]                           │
├──────────────────────────────────────────────────────────┤
│ 下一步                                                   │
│ 4 条认知等待确认                            [开始审查]    │
├──────────────────────────────────────────────────────────┤
│ 认知沉淀进度                                             │
│ 61 个认知来源 → 2 个整理任务 → 4 条待确认认知            │
├──────────────────────────────────────────────────────────┤
│ 最近工作                                                 │
│ AI 产品迭代复盘模板                 等待会话完成          │
│ 个人项目复盘模板                    1 条认知待确认        │
├──────────────────────────────────────────────────────────┤
│ 我的能力资产                                             │
│ 关于我 3｜规则与判断 4｜模板与范例 3｜技能与方法 2      │
├──────────────────────────────────────────────────────────┤
│ 最近复用                                                 │
│ 暂无复用证明 / 1 条复用证明待确认                        │
└──────────────────────────────────────────────────────────┘
```

规则：

- “下一步”只显示优先级最高的一项行动；
- 候选、整理任务和复用证明待确认数量可以显示 Badge；
- 四类能力资产统计只统计正式资产，不混入候选和 Evidence；
- `RecallView` 不显示在沉淀链路中；
- 无数据区块显示清晰的下一步，而不是技术空状态。

### 7.2 认知沉淀

```text
认知沉淀                                      4 条待确认

[待确认 4] [整理任务 2] [认知来源 61]

类型： [全部] [关于我] [规则与判断] [模板与范例] [技能与方法]
```

#### 待确认认知卡

每张卡固定使用 PRD 结构：

```text
我的判断
来源与依据
不确定性
建议分类与作用域
你的选择
```

操作：

```text
[保存] [修改后保存] [暂缓] [拒绝]
```

拒绝后，同一来源和同一内容不得反复提示，除非出现新的 Evidence。

#### 整理任务

任务状态统一为用户语言：

```text
等待会话完成
等待整理
正在整理
等待确认
已完成
失败
```

任务列表展示：

- 来源标题；
- 当前状态；
- 产生的候选数量；
- 创建或完成时间；
- 与状态匹配的唯一主要操作。

#### 认知来源

来源按 PRD 五类展示：

1. 会话；
2. Artifact 与文件；
3. 执行与评价；
4. 用户教学信号；
5. 授权外部系统。

来源类型用于筛选，不作为主导航。

### 7.3 能力资产

```text
能力资产                                        共 12 项

[全部 12] [关于我 3] [规则与判断 4] [模板与范例 3] [技能与方法 2]
```

桌面端采用列表与详情双栏：

```text
┌─────────────────────────┬────────────────────────────┐
│ 资产列表                │ 资产详情                   │
│                         │                            │
│ AI 产品迭代复盘模板     │ 分类：模板与范例           │
│ 已确认 · 尚未验证       │ 版本：v1                   │
│                         │ 作用域：产品项目            │
│                         │ 来源与依据                  │
│                         │ 适用条件 / 禁止范围         │
│                         │ 版本记录                    │
│                         │ 使用记录与复用证明          │
│                         │ [限域] [暂停] [撤销]        │
└─────────────────────────┴────────────────────────────┘
```

详情包含：

- 分类；
- 成熟度；
- 来源与 Evidence；
- 当前版本和版本谱系；
- 作用域；
- 适用与禁止条件；
- 最近使用记录；
- 复用证明；
- 暂停、限域、撤销、回滚等控制。

## 8. 技术对象的用户侧归宿

### 8.1 认知树

`Brain` 不再作为主 Tab，而作为总览或能力资产页的摘要组件。

树固定使用四个分支：

```text
我的认知树
├── 关于我
├── 规则与判断
├── 模板与范例
└── 技能与方法
```

认知树成长只来自真实资产状态变化，不以会话数量、Token、打开次数或使用时长驱动。

### 8.2 最小能力包

`Context Pack` 不再作为主 Tab，而出现在某次复用证明详情中：

```text
本次最小能力包
├── 关于我：1 项
├── 规则与判断：2 项
├── 模板与范例：1 项
└── 技能与方法：1 项
```

### 8.3 复用证明

复用证明不是资产类别。它作为：

- 总览中的最近活动或待确认行动；
- 能力资产详情中的使用记录；
- 某次任务的独立详情抽屉或详情页。

默认只回答：

1. 用了什么；
2. 来自哪里；
3. 目标 Agent 的 Action Plan 发生了什么变化。

技术日志、完整作用域、目标 Session 和 Evidence 进入展开层。

## 9. 交互规则

1. 主导航只在“总览、认知沉淀、能力资产”之间切换。
2. 从总览点击待确认数量，直接进入“认知沉淀 / 待确认”。
3. 从整理任务点击候选数量，进入对应来源过滤后的待确认列表。
4. 候选确认后，从“认知沉淀”移除，并出现在同分类的“能力资产”中。
5. 用户修改候选分类后，正式资产使用修改后的分类。
6. 从资产详情点击复用证明，打开证明详情，不切换到新的主 Tab。
7. Context Projection、RecallView、内部 ID 和技术状态默认不出现在首层页面。
8. 所有长时间操作显示进度；刷新不清空用户当前 Tab、筛选和选中资产。

## 10. 空状态与异常状态

### 总览无资产

显示：

```text
还没有能力资产
先从最近工作中确认一条值得保留的认知。
[沉淀最近工作]
```

### 无待确认认知

显示：

```text
目前没有需要确认的认知
你可以整理最近会话，或继续当前工作。
[整理最近工作]
```

### 整理任务失败

显示用户可理解的失败原因和单一恢复操作：

```text
这次整理没有完成
原会话暂时无法读取。
[重试]
```

### 资产详情降级

列表仍可展示时，单个详情读取失败不得让整页不可用。详情区显示重试按钮。

## 11. 响应式与可访问性

- 桌面宽屏：资产列表与详情双栏；
- 窄屏：列表与详情改为前后层级，详情提供返回操作；
- 类型筛选支持键盘导航和明确选中状态；
- Badge 不作为唯一状态表达；
- 四分类同时使用文字和图标，不只依赖颜色；
- 待确认、失败、已验证等状态满足可辨识对比度；
- 动态刷新后保持焦点与屏幕阅读器通知合理。

## 12. 兼容与迁移原则

1. 本轮优先复用现有数据和 IPC，不迁移业务数据。
2. 旧页面路由可映射到新页面和二级视图：
   - `sources` → 认知沉淀 / 认知来源；
   - `captures` → 认知沉淀 / 整理任务；
   - `candidates` → 认知沉淀 / 待确认；
   - `assets` → 能力资产；
   - `brain` → 能力资产 / 认知树摘要；
   - `context` → 对应复用证明的最小能力包；
   - `ontology` → 能力资产 / 关于我；
   - `receipts` → 能力资产 / 复用证明详情。
3. 旧 deep-link 或引导步骤应跳转到对应新位置。
4. 用户偏好的当前页如果指向旧 Tab，应在首次加载时映射，不报错。

## 13. 验收标准

### 信息架构

- Recall 主导航只显示“总览、认知沉淀、能力资产”。
- 工作空间和连接页面保持原位置和现有行为。
- Brain、Context Pack、Ontology、RecallView 不再作为 Recall 主 Tab。

### 分类

- 认知候选和正式能力资产只使用四个平级分类：关于我、规则与判断、模板与范例、技能与方法。
- “全部”仅为筛选项。
- 候选确认后默认保留分类。
- Evaluation 不形成第五类。

### 命名

- 用户首层页面不出现 `Brain`、`Context Pack`、`Ontology`、`RecallView`、`Candidate` 等未解释技术词。
- 用户侧统一使用“认知来源、整理任务、待确认认知、能力资产、认知树、最小能力包、复用证明”。

### 行为

- 总览可直接进入最重要的下一步操作。
- 认知沉淀的待确认、任务和来源视图均可访问。
- 能力资产可按四分类筛选，并查看来源、版本、作用域和复用证明。
- 原有候选审查、资产控制、复用证明和刷新能力不丢失。

### 测试

- 新旧路由映射测试；
- 四分类映射与统计测试；
- 候选确认后分类保持测试；
- Evaluation 三种归类路径测试；
- 总览优先行动选择测试；
- 空状态、失败和重试测试；
- 语言切换后标题、分类和动态内容重渲染测试；
- 键盘导航和焦点保持测试；
- 现有 Recall 业务流程回归测试。

## 14. 已确认设计决策

1. 只简化 Recall 内页。
2. 工作空间和连接保持现状。
3. 使用三个主入口：总览、认知沉淀、能力资产。
4. 认知候选与正式能力资产使用同一四分类。
5. 四分类是平级关系：关于我、规则与判断、模板与范例、技能与方法。
6. 分类与生命周期状态、Evidence 分离。
7. Brain、Context Pack、Ontology 和 RecallView 不作为主导航。
8. 复用证明保留为用户可见概念，但下沉到总览行动和资产使用详情。
