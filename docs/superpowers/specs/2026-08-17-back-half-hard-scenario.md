# 高难度对抗场景：KStar 沉淀后半段压力测试

- 日期：2026-08-17
- 构建：`d32b1ec9`
- 目的：**专门找茬**——验证异常路径、防御机制、幂等性和边界情况。前面那份场景测"正常能用"，这份测"坏的情况下不乱"
- 前置：实机已重启；全程我盯后台日志/数据；每场景失败都值得记录（可能是真 bug）
- 时长：约 20-30 分钟

## 场景 H1：语言硬闸对抗（故意让模型产出错语言）

**目的**：验证英文 lesson 拦截的确定性（不是碰运气）。

**操作**（新会话，中文任务但内容偏英文语境）：

```
用英文风格写一段关于 AI ethics 的说明，300 字
```

**再试一个**（同一会话继续）：

```
Translate this into English and explain: 帮我写一份城市资料
```

**预期**：
- [ ] 任务正常完成，无报错
- [ ] 「认知 → 待我处理」**不出现**英文判断的候选
- [ ] 后台日志可见 `kstar review lesson dropped for language mismatch`（拦截生效证据）

**后台确认**（我查）：
```
- review.lesson 被丢弃（taskLanguage=cjk, lessonLanguage=latin）
- 候选池无英文主导 judgment
- 若任务有中文 lesson，正常沉淀
```

## 场景 H2：语义查重——几乎相同的两个任务

**目的**：验证同义资产去重（不产生双份），且不同资产不被误并。

**操作**（同一会话连续）：

```
帮我写一份 南昌城市 的资料，500 字
（等完成）这个完成了，帮我写一份 南昌城市 的资料，600 字   ← 近乎相同任务
```

**再试不同的**：

```
帮我写一份 苏州城市 的资料，500 字
```

**预期**：
- [ ] 南昌两次任务只沉淀 **1 条**相关候选/资产（指纹或语义去重）
- [ ] 苏州的独立沉淀（不被南昌经验误并）

**后台确认**（我查）：
```
- 候选池按 judgment 过滤：南昌经验 1 条（confirmed），苏州 1 条
- 若触发语义查重：mergedIntoAssetId / mergedIntoCandidateId / update 候选记录
```

## 场景 H3：注入 vs 回执的真实性（injected = used）

**目的**：验证 receipt 只记**真正进入 prompt** 的资产，不记投影计划里的。

**操作**：连续跑 3 个不同主题的任务（制造多资产注入场景）：

```
帮我写一份 拉萨城市 的资料，500 字
（等完成）帮我总结一下这个会话的要点      ← 不同主题，注入集应不同
（等完成）帮我写一份 呼和浩特城市 的资料，500 字
```

**预期**：
- [ ] 每个任务的引用资产集合不同（主题不同，注入不同）
- [ ] 后台 receipt 的 reusedRefs 与当次 citations 一致（不多不少）

**后台确认**（我查）：
```
- 每张 receipt.reusedRefs = 当次 citations 的 assetId 集合（精确相等）
- 投影冻结清单 ≠ receipt（投影是计划，receipt 是实际）
- 多回合任务：多张 receipt 并集覆盖 → 全部升档（B4 验证）
```

## 场景 H4：任务失败/取消——不得升档

**目的**：验证负向终态不产生"假升档"。

**操作**（制造失败/取消）：

```
帮我写一份 银川城市 的资料，500 字
→ 回复到一半时点「停止」（abort）
```

**或**（若可操作）：发一个注定失败的任务（如要求读取不存在的文件并报错）。

**预期**：
- [ ] 任务被取消/失败后，「使用与证明」**没有**新增 succeeded 证明
- [ ] 被注入的资产成熟度**不升档**

**后台确认**（我查）：
```
- transfer-proof status = rejected（非 succeeded）→ 不升档
- 无新 effectiveness-proof
```

## 场景 H5：幂等性——重复操作不产生重复资产

**目的**：验证重复闭环/重复确认不会双写。

**操作**（同一任务触发多次闭环）：

```
帮我写一份 乌鲁木齐城市 的资料，500 字
（等完成）再写一份 兰州城市 的资料，500 字      ← 触发乌鲁木齐闭环
（马上再发）等等，兰州先不写，帮我写 西宁城市 的资料  ← 再次触发乌鲁木齐闭环？
```

**再试**：在「待我处理」对同一条候选**连续点两次确认**（如果 UI 允许）。

**预期**：
- [ ] 乌鲁木齐经验只沉淀 1 条
- [ ] 同候选重复确认不产生第 2 个资产（幂等）

**后台确认**（我查）：
```
- 候选池按 judgment：乌鲁木齐 1 条
- 资产 id 稳定（createdAssetId 确定性）
- handoff receipt 幂等（重复 promote 返回同一资产）
```

## 场景 H6：规则无边界——必须卡在候选池

**目的**：验证 PRD 3.1 规则边界门槛（缺边界的 rule 不能晋升）。

**操作**：造一条"规则但没给边界"的候选。如果 UI 能手动建候选：

```
认知 → 手动添加候选：
  judgment: "写东西前要先想清楚再动手"
  类型: 规则（rule）
  适用范围: （留空）
```

**预期**：
- [ ] 该候选**不能晋升**（缺边界，系统线/user 线都被拦）
- [ ] 候选停留在池中，有明确提示（如"规则需要适用与禁止范围"）

**后台确认**（我查）：
```
- 尝试 promote 报 rule_boundary_required（系统线）或 advisory（用户线）
- 候选 status 不变（pending_review / weak_observation）
```

## 场景 H7：暂停/回滚治理——纠偏真的生效

**目的**：验证治理动作影响注入行为（不是摆设）。

**操作**：

```
1. 找一个已有资产（如"城市资料按板块组织"）
2. 打开「版本与治理」→ 暂停使用
3. 再发一个同类任务：帮我写一份 郑州城市 的资料，500 字
4. 观察引用资产：被暂停的资产是否还出现？
5. 回「版本与治理」→ 恢复使用 → 再发一个任务验证恢复
```

**预期**：
- [ ] 暂停后，后续任务**不再引用**该资产（引用列表里消失）
- [ ] 恢复后，重新可被引用
- [ ] 暂停期间资产的 maturity/版本不受影响

**后台确认**（我查）：
```
- 暂停：asset.status = paused（或被 omittedRefs 记 asset_paused）
- 恢复：status 回 active
- 注入日志：暂停期间该资产被 omitted
```

## 场景 H8：0 资产投影——合法空结果 vs 系统故障

**目的**：验证"选了 0 个资产"与"投影坏了"的区分（spec 8）。

**操作**：发一个与任何已有资产都无关的全新主题任务：

```
帮我写一份 量子计算入门 的科普短文，500 字
```

**预期**：
- [ ] 任务正常完成（无资产注入也正常执行）
- [ ] 「使用与证明」无异常报错
- [ ] 若投影存在但 0 资产：尊重空结果，不注入

**后台确认**（我查）：
```
- 投影存在 + 0 资产 → 尊重（不 fallback 到 automatic 双选）
- 投影缺失/无效 → fallback automatic（spec 8 正确分支）
- 无 "projection unavailable" 类错误
```

## 场景 H9：中文 lesson 里混英文术语——放行不误杀

**目的**：验证语言硬闸的边界（中英混合中文主导 → 放行）。

**操作**：任务涉及大量英文术语但整体中文：

```
帮我写一份关于 RESTful API 设计规范的中文总结，包含 HTTP 状态码的使用建议
```

**预期**：
- [ ] 沉淀的 lesson 是中文主导（含 API/HTTP 术语可接受）
- [ ] **不被**语言硬闸误杀（lessonLanguageMismatches = false）

**后台确认**（我查）：
```
- dominantScript(lesson) = cjk（中文主导）→ 不拦截
- 若 lesson 被误杀（日志出现 dropped），是真 bug——立即报告
```
