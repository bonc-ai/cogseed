# 场景测试：提取质量防线（P0 平凡性闸门 + 输入抽样 + prompt 硬规则）

- 日期：2026-08-16
- 构建：`748b9261`（宿主侧平凡性闸门 + 两端/中间抽样 + 提取 prompt 硬规则）
- 目的：验证提取质量改动的**实际效果**——套话被拦、规则不误伤、复述被拦、长会话信息不丢
- 方式：用户在 GUI 跑任务，我盯候选池/日志验证
- 配套：`scripts/audit-kstar-precipitation.mjs`

---

## 防线全景（本次验证每一层）

```
模型提取（prompt 硬规则：禁套话/禁复述）
  → 宿主闸门（P0 确定性：platitude_restates_task / platitude_no_specifics）
  → 质量评估（value/action/scope/证据/复用信号）
  → 命中 → forceWeakObservation（弱观察，不沉淀）
  → 晋升时语义去重 + 质量融合
```

---

## 场景 A：资料类任务（验证不误伤 + 正常提取）

**操作**：新会话，发送：

```
帮我写一份 南昌城市 的资料，500 字
```

**你可见的预期**：Commander 正常交付。

**后台验证**（我盯）：
```
【提取】候选 judgment 应为"城市资料模板"类（含 结构/字数 等信号）
【闸门】不应命中 platitude_restates_task（judgment 带可复用结构，非纯复述）
【状态】候选 pending_review（或自动晋升），不是 weak_observation
```

**判定**：✅ judgment 具体（"开头注明字数+分块组织"）；❌ 误伤（变 weak）

---

## 场景 B：规则陈述任务（验证不误伤——用户消息本身即知识）

**操作**：新会话，发送：

```
以后所有架构决定都必须记录来源和理由
```

**你可见的预期**：Commander 确认/执行。

**后台验证**：
```
【闸门】judgment"所有架构决定必须记录来源"与用户消息一致 → 不应命中
       platitude_restates_task（消息是规则陈述，不是任务请求）
【状态】候选应正常（rule 类）
```

**判定**：✅ 正常沉淀；❌ 被平凡性误伤 → 闸门过严，需放宽

---

## 场景 C：简单任务后的套话（验证拦截）

**操作**：新会话，发送一个极简任务（如"1+1 等于几"或"把这段话翻译成英文"），等提取。

**后台验证**：
```
【闸门】若模型输出"认真完成了任务/已按时交付"类 judgment → 应命中
       platitude_no_specifics → 降级 weak_observation
【候选池】该候选 status=weak_observation（或未进 review 列表）
```

**判定**：✅ 套话被降级；❌ 套话进了 pending_review（闸门没拦住）

---

## 场景 D：长会话（验证中间抽样）

**操作**：同一会话连续多轮（≥6 轮）完成一个任务（如"先写资料，再改格式，再补充数据"），让会话消息超过提取窗口。

**后台验证**：
```
【提取输入】selectCaptureMessages 输出 首条 + 中间抽样 + 尾部
【中间消息】中途的"改成散文/补充历史沿革"类消息应在输入里（judgment 能引用）
```

**判定**：✅ 中途变更被提取模型看到（judgment 含变更相关经验）；❌ 只看到首尾（中间丢了）

---

## 场景 E：审计对比（整体质量）

**操作**：跑完 A-D 后告诉我。

**后台验证**：

```bash
node scripts/audit-kstar-precipitation.mjs --since-hours 2
```

|---|---|

| lesson 具体性 | 抽样 judgment 无套话、含具体信号 |
