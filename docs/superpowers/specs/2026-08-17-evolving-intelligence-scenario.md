# 高难度场景：「越用越聪明」——渐进式自我进化验证

- 日期：2026-08-17
- 构建：`9232d65e`
- 目的：通过**跨 8 轮渐进式任务**，验证系统真正"越用越懂你"——不是每轮独立工作，而是**经验逐轮累积、注入逐轮精准、反馈驱动纠偏、最终复杂任务一次到位**
- 核心叙事：你是一位每周写周报的团队负责人，CogSeed 从第 1 周的"通用回答"进化到第 8 周的"完全懂你的周报风格"
- 时长：约 30-40 分钟（建议留出轮次间隔看沉淀）

---

## 第 1 轮：冷启动（基线）

**操作**（新会话）：
```
帮我写一份本周工作周报，我是团队负责人
```

**预期**：
- 周报能写出来，但**格式通用**（可能用普通段落）
- 「引用资产」：可能无相关经验或很少（冷启动）

**记录**：回复里引用了哪些资产？（预期：少/无）

---

## 第 2 轮：第一次沉淀 + 用户风格输入

**操作**（同一会话继续）：
```
这个完成了。顺便说一下，我以后的周报都要按这个格式：
  1. 本周完成（分项目列出）
  2. 数据指标（用表格：项目/指标/数值/对比上周）
  3. 风险与阻塞
  4. 下周计划
  以后都用这个模板
```

**预期**：
- 「待我处理」出现候选（lesson 应包含周报模板结构）
- 若 lesson 提炼不完整（缺表格/四段结构），**手动编辑候选补全**后确认

**后台确认**：候选 confirmed；资产 A 诞生（maturity=seed）

---

## 第 3 轮：复用验证——模板注入生效

**操作**（同一会话继续，不重复说明格式）：
```
帮我写本周周报：完成了订单系统重构、修复 3 个线上 bug；上线了新的支付网关
```

**预期**：
- **不需要重复说明格式**，回复已按四段模板 + 表格组织（资产 A 被注入）
- 引用资产里能看到第 2 轮的经验
- 若格式仍不对 → 说明注入未生效，**记录为失败**

**后台确认**：receipt 含资产 A；终态 proof succeeded → 资产 A maturity → **已迁移验证**

---

## 第 4 轮：变体挑战——风格偏好累积

**操作**（继续，引入新偏好）：
```
这个周报的「风险与阻塞」部分写得太平淡了。以后风险部分要：先说影响等级（高/中/低），再给应对措施。另外表格里加一列「负责人」
```

**预期**：
- 本轮产生**新候选**（lesson 关于风险表述 + 负责人列）
- 旧资产 A 仍在（未被覆盖）

**后台确认**：候选 B 诞生（maturity=seed）；资产 A 版本不变（或 update 候选出现）

---

## 第 5 轮：组合复用——多经验协同

**操作**（继续，信息量加大）：
```
写本周周报：订单系统完成灰度发布（50%流量）、支付网关接入银联；数据库慢查询优化了3条；下周要上线促销活动，预估流量翻倍，需要提前扩容。风险：促销活动可能压垮支付服务
```

**预期**：
- **一次到位**：四段模板 + 表格（项目/指标/数值/对比/负责人）+ 风险带影响等级和应对措施
- 引用资产**同时包含**资产 A 和资产 B（多经验组合注入）
- 若缺任何一部分 → 记录失败点

**后台确认**：两张 receipt（或一张并集覆盖 A+B）；双资产各升档/使用记录

---

## 第 6 轮（对抗）：错误经验纠偏——越用越准

**操作**：
```
1. 打开「认知 → 版本与治理」，找一个"周报"相关资产
2. 故意把它改坏（例如把负责人列改成不存在的列名），版本+1
3. 再写一次周报：帮我写本周周报：完成客户反馈系统上线
4. 观察：引用的是改坏前的版本还是改坏后的？（版本冻结应防止注入漂移）
5. 回「版本与治理」→ 回滚到上一版本
6. 再写一次周报验证恢复
```

**预期**：
- 改坏后：注入仍用**冻结的旧版本快照**（不注入漂移内容）
- 回滚后：正常注入正确版本

**后台确认**：projection 冻结 assetVersions；改坏后注入用快照版本；回滚后 asset.version 回落

---

## 第 7 轮：效果反馈——锁定最优经验

**操作**：
```
打开「认知 → 使用与证明」
给第 5 轮周报的证明记录评价「有用」（positive）
```

**预期**：
- 相关资产成熟度 → **效果已验证**（顶档）
- 后续周报任务优先注入顶档资产

**后台确认**：effectiveness-proofs 出现；资产 maturity → effectiveness_validated

---

## 第 8 轮：终极验证——跨周记忆

**操作**（新会话，完全不加说明）：
```
帮我写本周周报：完成了数据看板开发；修复了 2 个权限 bug；下周要支持多语言
```

**预期**（**这是"越用越聪明"的终极证明**）：
- **完全不需要重复任何格式/风格说明**，一次到位（四段模板 + 表格含负责人 + 风险带等级）
- 引用资产包含之前沉淀的顶档经验

**后台确认**：注入资产集合 = 前几轮沉淀的最优资产；receipt 精确记录

## 结果记录表

| 轮次 | 验证点 | 结果 |
|---|---|---|
| 1. 冷启动 | 通用格式（无经验基线） | ☐ |
| 2. 首次沉淀 | 模板候选诞生 | ☐ |
| 3. 复用生效 | 免说明按模板输出 + 升档 | ☐ |
| 4. 风格累积 | 新偏好沉淀为候选 B | ☐ |
| 5. 组合复用 | A+B 协同一次到位 | ☐ |
| 6. 版本纠偏 | 改坏不漂移 + 回滚恢复 | ☐ |
| 7. 效果反馈 | 顶档锁定 | ☐ |
| 8. 跨轮记忆 | 新会话免说明一次到位 | ☐ |

**成功标准**：第 8 轮的输出质量 ≥ 第 5 轮，且**零重复说明**——这就是"越用越聪明"的可测量定义。

---

## 为什么这份场景是高难度的

1. **跨会话记忆**（第 8 轮新会话）：验证经验不是"同一会话内凑合"，而是跨会话真实生效
2. **多经验组合**（第 5 轮）：验证注入系统能同时携带多条互补经验（不是单条）
3. **版本冻结对抗**（第 6 轮）：验证改坏内容不会漂移进注入（防投毒）
4. **反馈闭环**（第 7 轮）：验证用户评价真的改变未来行为
5. **可量化**：每轮都有明确"预期输出"可对照，失败点可精确定位

---

## 测试说明

- 每轮操作后等回复完成（触发闭环沉淀）再进下一轮
- 第 6 轮「改坏」是故意行为，测完必须回滚
- 失败判定：第 3 轮格式不生效 / 第 5 轮缺组件 / 第 8 轮需要重复说明 = 注入链路问题；候选不诞生 = 沉淀问题；升档不到 = 证明问题——都能精确定位
