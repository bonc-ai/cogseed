# 报销工作台迁入 Mate 设计

状态：待用户评审

日期：2026-08-02

## 决策摘要

将报销项目当前的独立 Web 工作台迁入 Mate Agent 的 Electron renderer，作为“本地报销准备助手”详情页中的管理入口。迁移后的页面保留现有工作台的主要页面结构和业务操作，但把浏览器 `fetch('/api/...')` 数据层替换为 Mate IPC；报销项目继续拥有 T-BOX、R-BOX、A-BOX、数据库、规则、材料、证据和审批闸门的业务真相。

迁移完成并通过回归验证后，删除报销项目的浏览器工作台资源和 `/`、`/admin` 页面入口。Mate 不启动报销项目的本地 HTTP 服务，不新增端口，也不把报销业务数据复制到聊天记录或 Mate 自己的数据库中。

## 目标与非目标

### 目标

- 在现有 Agent 详情页为声明了管理界面的 Agent 提供“管理”入口；本次只有报销 Agent 声明 `expense_workbench` 管理界面。
- 在 Mate 内提供现有工作台的七个功能区：报销助手、报销申请、预审会话、工作台、人工复核、连接配置、审计记录。
- 复用现有报销工作台的交互语义和页面层级，避免做一个只显示状态的简化替代品。
- 所有 renderer 请求都经 `window.cogseed.invoke` 或 `window.cogseed.stream`，由 main 校验并调用受限报销适配器。
- 保证 Mate 和报销项目使用同一份受控业务数据；版本冲突、材料授权、人工确认和 `needs_review` 语义继续由报销领域核心决定。
- 迁移完成后，用户不需要启动浏览器或本地报销 Web 服务即可完成 Mate 内的报销工作台流程。

### 非目标

- 本次不创建所有 Agent 共用的通用管理后台；管理界面只是一个可选的 Agent 控制面扩展点。
- 不重写报销领域核心、三盒子本体、数据库模型或规则引擎。
- 不让 Mate 代替报销领域核心执行审批、提交、付款或外发。
- 不在聊天 JSONL 中保存报销草稿真相，不把附件复制成另一套业务材料。
- 不在迁移完成前删除现有 Web 工作台资源。

## 现状与迁移约束

报销工作台当前位于报销项目的 `src/expense_reimbursement/api/admin_templates/`，由 `index.html`、`admin.css` 和 `admin.js` 组成，约 3,200 行，包含七个页面区块和大量 API 交互。Mate renderer 使用 classic scripts，不能引入 JSX、TypeScript 或新的 renderer npm 依赖；现有 IPC 入口是 `window.cogseed.invoke` / `window.cogseed.stream`。

报销项目目前同时拥有旧会话命令和新版 `application-*` 命令。迁移后的控制页只能使用统一的新版应用契约，不再复制或复活旧 `new` / `answer` / `status` / `report` 会话协议。涉及草稿的请求必须携带宿主读取的 `expected_version`，材料必须来自当前用户已授权的材料清单及明确的材料类别。

## 方案选择

### 方案 A：在 Mate 中嵌入原 Web 页面

通过 iframe 或本地 WebView 继续加载报销项目页面。

不采用。它保留 HTTP 服务和端口，形成两个前端安全边界，无法直接使用 Mate 的 IPC、用户作用域和附件授权，也会违反 Mate 的单进程 renderer 约束。

### 方案 B：在 Mate renderer 原地迁移视觉和交互，重写数据适配层

把现有 HTML/CSS/JS 拆为 Mate 的 classic renderer 模块，保留页面结构和交互状态；将所有网络请求替换为 `expenseWorkbench.*` IPC 调用。

采用。这最接近用户要求，能保留现有工作台能力，同时让权限、用户作用域、路径访问和错误处理回到 Mate 的主进程边界。

### 方案 C：只迁移报销任务卡和对话，删除工作台的大部分页面

只在 Mate 中提供状态、追问和草稿摘要。

不采用。它会丢失批量材料、人工复核、审计和连接配置等现有工作台能力，不符合“直接把现在网页端前端搬过去”的目标。

## 用户体验

### 入口

Agent 详情页继续保留“使用”“编辑”“停用”。当 Agent spec 声明 `management_surface: "expense_workbench"` 时，显示“管理”按钮；没有该声明的 Agent 不显示新入口。平台代码只识别通用的管理界面能力，不硬编码报销 Agent 的目录 ID。

点击“管理”后，在现有主窗口中切换到管理面板，提供返回 Agent 详情页的按钮。页面不打开外部窗口、不导航到 localhost、不启动浏览器。

### 页面结构

迁移后的页面保留现有工作台的七个功能区和导航顺序：

1. 报销助手：当前任务摘要、下一步、独立对话入口。
2. 报销申请：创建、列表、筛选和打开申请。
3. 预审会话：运行预审、展示状态和检查证据。
4. 工作台：申请详情、材料清单、草稿版本和风险。
5. 人工复核：待复核项目、复核理由和允许的人工操作。
6. 连接配置：只显示是否配置和可安全编辑的非密钥设置；密钥由主进程保存，renderer 不持久化密钥。
7. 审计记录：按申请和时间读取脱敏审计事件。

现有页面中的 emoji 或手写 SVG 图标迁移时替换为 Mate 的 `modules/icons.js` 图标。页面使用现有 renderer 的 i18n、按钮、表单、对话框和进度样式，不引入第二套通用 UI 框架。

### 独立对话

“报销助手”区块提供案件内独立对话入口。对话绑定当前报销申请和当前用户，不另建一份报销事实；自然语言只能生成受校验的结构化操作建议，修改草稿前必须展示差异并由用户确认。对话失败、领域服务不可用或模型结果不可解析时显示可操作的错误和 `needs_review`，不伪造成功。

## 架构

### Renderer

新增 `src/renderer/modules/expense-workbench.js`，负责页面挂载、导航、表单状态、加载/空态/错误态、状态轮询和操作反馈。新增一组局部样式，沿用现有 `style.css` 变量和组件类，避免把 3,200 行脚本直接塞进 `agents.js` 或把报销页面塞进全局聊天模块。

`src/renderer/index.html` 增加管理面板容器和脚本引用。`agents.js` 只负责在 Agent 详情页渲染入口并传递管理界面 key；它不承载报销业务逻辑。renderer 只保存当前页面状态、申请引用和版本号，不保存 user_id、密钥、确认能力、报销业务数据或任意本地绝对路径。

### IPC

新增 `expenseWorkbench.*` 请求族并集中登记到 `src/main/ipc/index.ts`。初始能力覆盖：

- `manifest` / `health`：读取工作台能力和服务状态。
- `applications.list` / `applications.get` / `applications.create`：申请列表、详情和创建。
- `applications.draft` / `applications.precheck` / `applications.report`：草稿、预审和草稿报告。
- `applications.materials.list` / `applications.materials.add`：读取和登记宿主已授权材料。
- `applications.reviews.list` / `applications.reviews.decide`：人工复核允许的操作。
- `applications.audit.list`：读取脱敏审计事件。
- `settings.get` / `settings.update` / `settings.test`：安全的连接配置操作。
- `assistant.inspect` / `assistant.propose`：案件内对话和结构化操作建议。

每个 handler 都校验 payload、Agent 管理界面声明、当前用户作用域、申请引用、版本号和允许的操作；错误统一转换为带 code、message 和可恢复性标记的 IPC 错误。renderer 不得传入任意 shell 命令、用户 ID、确认 token、凭证路径或未经宿主签发的材料引用。

### 报销领域适配器

新增一个位于 `src/main/features/` 的报销适配器，作为 IPC 和报销项目之间的唯一边界。它负责：

- 解析并校验当前用户的报销项目配置。
- 将宿主用户和材料授权投影为报销项目需要的结构化输入。
- 使用版本化、机器可读的 stdio/CLI 桥接调用报销项目；不拼接 renderer 提供的 shell 字符串。
- 读取 JSON 结果并执行 schema 校验、脱敏和大小限制。
- 将超时、进程退出、JSON 无效、版本冲突、材料不可用和领域拒绝转换为稳定错误。

该适配器复用现有受控 CLI/子进程入口，不在新 feature 中直接调用 `child_process.spawn`。报销项目侧提供与 `ApplicationService` 同源的机器可读桥接，保留同一数据库、T/R/A-BOX 和审计路径；Mate 不启动报销项目的 HTTP server。

### 数据真相和用户作用域

报销申请、草稿、材料、证据、人工复核和审计仍存放在报销项目的数据根。Mate 只保存当前管理面板的 UI 选择、最近打开的申请引用和非敏感配置引用。每次 IPC 调用在 main 侧重新解析当前用户和配置，不缓存 uid 派生路径为模块级常量。

附件先由 Mate 现有附件授权机制登记为受控材料引用，再传给报销适配器。工作台不得直接读取用户任意本地路径；项目路径只能通过目录选择器设置，并经过路径沙箱、目录存在性和虚拟环境检查。

## 安全与错误处理

- 所有报销操作都绑定当前 Mate 用户和 Agent 管理面板上下文，不能跨用户读取申请或证据。
- 连接配置中的 API key、角色令牌和确认能力只在 main/报销项目受控边界内处理，禁止进入 renderer 日志、审计展示或 Artifact。
- 草稿、预审和正式报告状态严格区分；Mate UI 不把 `ready_for_report`、`confirmed` 或外部适配器回执显示成已审批或已付款。
- 版本冲突要求重新读取申请并显示差异，不自动覆盖或重试写入。
- 旧工作台 API 或桥接返回的未知字段不直接渲染；先经过安全投影和结果上限。
- 长操作显示进度和可重试状态；不可恢复错误提供诊断引用，不吞掉原始错误链。
- 当报销项目配置、桥接或模型不可用时，显示 `needs_review` 或草稿状态，保留用户已提交的事实，不生成替代事实。

## 迁移和删除顺序

1. 固化现有 Web 工作台的页面/交互基线和接口映射，确认七个区块的行为清单。
2. 在报销项目添加机器可读的非 HTTP 桥接，并为新版 `application-*` 契约补齐版本、材料和权限字段。
3. 在 Mate 添加管理界面声明、管理入口、renderer 工作台、IPC handler 和 main 适配器。
4. 在 Mate 中完成申请、材料、预审、复核、配置、审计和独立对话的端到端验证。
5. 在 macOS 和 Windows 验证安装后首次启动、项目目录选择、桥接启动、恢复和退出路径。
6. 删除报销项目的浏览器模板、静态资源挂载、`/` 和 `/admin` 页面入口以及仅供网页使用的退出逻辑；保留仍被外部系统需要的领域 API/适配器代码，除非依赖分析确认它们只服务旧网页。
7. 更新报销项目 README、Mate 接入文档和 manifest/测试基线，明确 Mate 工作台是唯一用户界面。

删除旧网页前必须确认：Mate 在无 HTTP 端口的情况下可以完成工作台验收，所有旧网页专属操作都有 IPC 对应物，且报销项目源码树中没有丢失业务入口。

## 测试与验收

### 单元和契约测试

- Agent spec 管理界面声明校验：只有声明合法 surface 的 Agent 显示管理入口。
- IPC payload 校验、用户隔离、路径沙箱、材料引用和版本冲突。
- 报销桥接的 JSON schema、脱敏、大小上限、超时、进程失败和未知状态。
- 领域结果到 renderer 状态的映射，包括 `collecting`、`needs_review`、`ready_for_confirmation`、`completed` 和错误态。
- 旧 Web API 与新桥接结果的关键字段 parity，覆盖申请、材料、预审、报告、复核和审计。

### Renderer 验收

- Mate 启动不监听报销本地 HTTP 端口。
- 从 Agent 详情页进入和返回管理面板，其他 Agent 页面不受影响。
- 七个功能区都有加载、空态、成功、错误和权限拒绝状态。
- 新建申请、上传受控材料、保存带版本的草稿、运行预审、查看证据和生成草稿报告。
- 版本冲突、缺件、未配置连接、桥接退出和重复点击不会造成重复写入。
- 独立对话只能提出结构化建议，不能绕过人工确认或写入未授权材料。

### 集成和平台验证

- macOS：目录含中文/空格、Python 虚拟环境、应用重启、文件选择和桥接进程回收。
- Windows：目录选择、进程启动/终止、路径转换和 renderer 布局；如果新版桥接仍只支持 POSIX，则 UI 明确显示平台不支持并停止调用。
- 安装后首次启动、升级覆盖、旧本地 Web 配置残留和异常退出恢复。

## 成功标准

用户只启动 Mate，就能在“本地报销准备助手 → 管理”中完成原独立工作台支持的核心报销准备流程；Mate 不需要浏览器、不占用本地 HTTP 端口；报销项目的领域数据和三盒子本体仍是唯一业务真相；旧网页删除后不存在功能回退、跨用户访问或状态伪造。
