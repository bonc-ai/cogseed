# 模型配置参考界面设计

## 目标

把“模型配置”恢复为截图中的直接操作模式：页面内选择供应商和模型、添加账号，并用可拖动优先级列表管理默认与兜底模型；自定义供应商使用独立的创建/详情界面，支持一个端点维护多个模型。

## 主配置页

- 顶部固定为“添加模型授权”，包含供应商选择器、随供应商联动的模型选择器和“添加账号”。
- 供应商来自 Main 的真实目录，显示认证能力副标题和推荐标记；现有自定义供应商也进入目录。不得在 Renderer 硬编码不可调用的托管供应商。
- 选择内置供应商后，沿用现有 API Key/OAuth 授权流程；选择已有自定义供应商后直接绑定其已保存凭据；选择“自定义（OpenAI 兼容）”入口后打开自定义供应商创建界面。
- 下方为按优先级排列的真实模型条目：第一项是默认模型，支持拖动排序、切换模型、测试和删除。自定义条目额外提供供应商管理入口。

## 自定义供应商

- 创建界面字段：名称、Base URL、API Key、API 格式、模型列表。
- API 格式支持 Anthropic Messages、Chat Completions、Gemini GenerateContent，并映射到现有 `anthropic/openai/gemini` runtime 协议。
- 一个供应商可维护多个模型。模型字段至少包含模型 ID、上下文窗口和最大输出长度；上下文/输出长度使用有界正整数校验，并提供安全默认值。
- 创建成功后自动把第一个模型加入优先级列表，避免出现已保存凭据但应用仍不可用的半完成状态；其余模型可在主选择器中继续添加。

## 自定义供应商详情

- 展示名称、启用状态、Base URL、API 格式、脱敏 API Key 和模型列表。
- 支持编辑供应商、启用/禁用、删除；禁用只停止运行态使用并保留条目，重新启用后恢复。
- 每个模型支持测试、编辑、删除；编辑模型 ID时同步更新关联优先级条目，删除模型时清理关联条目。
- API Key 不回传明文到 Renderer；眼睛按钮只控制用户本次输入的新密钥，已保存密钥始终只显示脱敏值。

## 边界与错误处理

- 供应商和模型配置继续存入加密的 `auth-profiles.json`，日志只记录 ID、协议和粗粒度状态。
- Base URL 只接受无内嵌用户名/密码的 HTTP(S) URL；模型 ID 去空白、去重并限制数量和长度。
- 删除、禁用、模型变更必须刷新模型守卫和优先级列表；网络测试失败不得丢失现有密钥或配置。
- 公开构建没有真实 `Orkas · LLM` 托管通道，因此本次不伪造该条目；未来 Main 返回真实托管 Provider 时，通用选择器可直接展示。

## 验收

- Renderer 契约测试覆盖主选择器、认证能力提示、自定义创建、多模型、详情操作和 IME 防护。
- Main 测试覆盖模型元数据归一化、启停、模型增删改、条目联动、加密存储和安全测试通道。
- 运行 `npm run typecheck`、专项测试和 `npm test`；随后重启 CogSeed，在真实 Electron 页面完成创建、选择、排序、测试入口和自定义详情的界面验证。
