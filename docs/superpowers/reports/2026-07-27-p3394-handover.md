## 三、关键概念

### 3.1 P3394 协议

P3394 协议定义了 Agent 与系统之间的消息规范：

- **角色关系**：owner / peer / client / anonymous
- **言语行为**：request / command / query / delegate / negotiate
- **安全上下文**：service principal、relationship、session lifecycle
- **协作引用**：workflow_run_id、context_id、context_revision

当前状态：协议生成是"记录型"的，每条 Agent 消息都会产生一个 P3394 Protocol Event
记录到抽屉里。张照航的任务是把它升级为"控制器型"，即协议不只是记录消息格式，
而是主动控制 Agent 的权限、可见性和行为边界。

### 3.2 KSTAR 学习模型

K — Knowledge（知识快照引用）
S — Situation（任务场景）
T — Task（任务内容）
A^ — Action Hat（预测动作）
R^ — Result Hat（预测结果）
A  — Actual Action（实际动作）
R  — Actual Result（实际结果）

每次 Commander 调度 Agent 时，会带上 kstar_expectation（预测）；
Agent 完成后，系统采集 actual_action / actual_result / evidence；
由 Meta Skill Engine 形成 KSTAR Episode。

### 3.3 多 Agent 协作流程

User -> Commander -> dispatch_to / hand_off_to / run_worker -> Agent -> Commander 汇总
                   bus.ts 状态机 -> workflow steps -> wake/resume/gate/abort -> KSTAR evidence

### 3.4 Meta Skill Engine

引擎是独立 ESM MCP stdio 进程，拥有：
- Episode/EvidenceBundle/Attribution/Patch/Governance 状态机
- Snapshot 生成 CAS
- 本体读取
- 遗留 PC 数据导入
- 兼容性投影

PC 侧只负责：用户隔离存储、snapshot 原子写、pending evidence、迁移归档、兼容 DTO、
Wake/Bus 和 UI。

## 十、协议面板说明（P3394 Protocol Tab）

当前协议面板在抽屉中显示的是 P3394 协议事件，每条 Agent 消息都会产生一条记录：

- agent_id / message_id — 谁发、哪条消息
- role — orkas_core 或 external_expert
- relationship — owner / peer / client / anonymous
- speech_act — request / command / delegate 等
- message_type / correlation_id — 消息类型和关联
- collaboration 引用 — workflow_run_id / context_id / step_id
- result — success 或 error
- runtime_kind — cli / model-backed

过滤功能：可按 agent、role、result 筛选。

张照航的控制器升级方向：让协议不只是"事后记录"，而是"事前控制"——
dispatch 前检查 relationship、speech_act、capability 是否匹配 P3394LiteManifest 的策略。
