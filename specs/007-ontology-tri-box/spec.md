# Feature Specification: 本体三盒归位与打通（tri-box）

**Feature Branch**: `认知资产迭代`
**Created**: 2026-09-20
**Status**: Implemented（授权切片交互方案待拍板：authorization-slicing-options.md——敏感性地基已入，注入裁剪未动）
**Input**: 用户需求原话：「我理解的是三个盒子是三个大的分类方式，也就是在大的还有小的本体部分都按这三个进行分类。就像个人本体，你直接对应一个 A box、R box 还有 T box，直接就有这三个分类，然后里面再有具体的内容。」随后拍板：「直接三档一起做，按 spec kit 规范来。」

**Source**: Richard《Personal Ontology v0.1.0（2026-09-08）》三盒蓝图（T-Box 概念 / A-Box 限定断言 / R-Box 规则）对照当前实现的差距分析（design/本体增强两天开发前后对比-20260920.html 与对话探索记录）。

## 背景与差距（探索实证）

三盒骨架在代码中已同源存在（词汇=组字段名、事实=字段值+personal 资产、规则=关系值+因果规则），世界模型消费层已完全三盒化。差距集中在三处：

1. **R 盒用户侧入口为零**：关系值（`A → B` 形状）只能手改文件——「关系字段」界面文案是语言文件里的孤儿（零代码引用）；界面上没有任何创建关系值的入口。
2. **A 盒双存储分裂**：同一性质内容（关于用户的事实）存两处两屏——本体组字段值（表格形态）与资产库 personal 资产（自由文本形态），无统一视图。
3. **结构层缺口**：断言核实只有一档（应两档）；「来源已删」误判（即时直投合成 id 对不上会话目录）；规则无分类无状态；本体值无敏感性分档、注入无授权裁剪；组文件无变更历史。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在组详情里看清三盒结构并亲手写规则（Phase 1, P1）

用户打开本体分组详情，看到的不再是混排的字段块，而是按「词汇（T）/事实（A）/规则（R）」分区的结构；用户第一次能在界面上亲手创建一条关系值（如「评审 → 先讲产品模型」），它自动成为规则进入世界模型；模板字段的说明文字可见。

**Why this priority**: R 盒入口为零是三盒中最大的功能缺口；分区呈现是用户三盒理解的直接落地，纯渲染层零风险。

**Independent Test**: 打开一个含普通字段与关系字段（或含 `A → B` 值）的组 → 详情视图出现规则分区；通过「添加值」写入 `A → B` 形状的值 → ontologyRules（世界模型 R 盒）出现该规则。

**Acceptance Scenarios**:

1. **Given** 组内存在模板声明的关系字段（isRelation: true）**When** 打开组详情 **Then** 该字段出现在「规则」分区，普通字段出现在「事实」分区，分区标题可读（不出现裸英文枚举）。
2. **Given** 普通字段（未声明关系型）**When** 用户在「添加值」写入 `评审 → 先讲产品模型` **Then** 值保存成功且该字段因值形状（含 → / ->）在读取侧被解析为规则，进入世界模型 ontologyRules。
3. **Given** 字段带说明文字（description，模板 T 盒声明）**When** 渲染字段块 **Then** 说明以弱化文字显示在字段名旁。
4. **Given** 新建字段弹窗 **When** 用户填写字段名 **Then** 可选择声明该字段为关系字段（界面提示 `A → B` 写法），声明与否不影响值形状驱动的解析兜底。

### User Story 2 - 一屏看全 A 盒与 R 盒，核实分两档，来源不再误报（Phase 2, P1）

用户打开「三盒总览」：A 盒一屏看全全部事实断言（组字段值与 personal 资产合并、同口径标记：来源/时间锚/核实/矛盾），R 盒一屏看全全部规则（关系值与规则资产合并），T 盒给词汇统计。核实话语从一档升两档。此前批量误报的「来源已删除的候选」恢复正常归组。

**Why this priority**: 双存储分裂与来源误判是当前用户可见的体验问题（截图实证：7 条候选被错误归组）。

**Independent Test**: 总览页 A 盒条目数 = 组字段值数 + personal 生效资产数；即时直投产生的新候选不再带 `immediate-` 前缀合成 id；存量 `immediate-` 前缀引用在渲染层剥前缀比对。

**Acceptance Scenarios**:

1. **Given** 组内有 5 条字段值、资产库有 6 条 personal 生效资产 **When** 打开三盒总览 A 盒区 **Then** 列表合并显示且条目可回溯到各自来源（组的标组名、资产的标资产）。
2. **Given** 组内 2 条关系值、资产库 3 条 rule 资产 **When** 打开 R 盒区 **Then** 合并显示 5 条，每条带类型标记（关系值/规则资产）。
3. **Given** 一条值落盘 `@verified`（裸标，存量兼容）**When** 渲染 **Then** 显示「有来源支持」章；落盘 `@verified:independent` **When** 渲染 **Then** 显示「独立核实过」章；两档均透出给世界模型。
4. **Given** 即时直投（模型当场记）发生在真实会话中 **When** 产生候选 **Then** 来源引用使用真实会话 id（可命中会话目录、界面可点开），不再产生 `immediate-<内部id>` 合成引用。
5. **Given** 存量候选带 `immediate-` 前缀引用且核心 id 可命中会话 **When** 渲染来源判定 **Then** 剥前缀后命中，显示真实会话标题；核心 id 无实体（runner 内部会话未落盘）**Then** 显示「模型当场记（无独立出处）」，**不**归入「来源已删除」分组、**不**提示「建议补充证据」。
6. **Given** 候选的 sourceRefs 与 evidenceRefs 含同 id **When** 统计证据可用性 **Then** 按 id 去重后计算（不因双份虚增翻倍）。

### User Story 3 - 规则可分类、敏感内容可分档、本体变更可回滚（Phase 3, P2）

规则（R 盒）带轻量分类（操作规则/偏好/约束）与状态（提议中/生效中）并可筛选；本体字段值可标敏感性（standard/restricted），restricted 值不进任务注入（授权切片的第一块地基）；本体组文件每次写入留版本快照，可查可恢复。

**Why this priority**: 结构对齐 Richard 蓝图的深水区；授权切片动注入链路，交互形态须先出小方案拍板。

**Independent Test**: 规则按分类筛选正确；restricted 值在任务注入块（画像/目录/ontologyFacts）中零出现；组文件修改 N 次后历史快照有 N 版且任一版可恢复原文。

**Acceptance Scenarios**:

1. **Given** 规则值/规则资产带分类标记 **When** R 盒视图按分类筛选 **Then** 仅显示该类；无标记规则归「未分类」不丢失。
2. **Given** 一条本体值标 restricted **When** 任务注入构建 **Then** 该值不进入注入块与世界模型 ontologyFacts；界面可见并带 restricted 标记。
3. **Given** 授权切片交互方案（裁剪维度：任务关键词/空间绑定/手动选择）**When** 方案未经用户拍板 **Then** 不动注入链路（本 spec 内仅落敏感性地基，切片实施另行确认）。
4. **Given** 组文件连续修改 3 次 **When** 打开组历史 **Then** 可见 3 个快照（时间+变更摘要），恢复任一版后文件内容与快照一致。

## 非目标（明确不做）

- 不做 OWL 级 T-Box 公理化（此前拍板维持「不追」）
- 不做 Richard 八类规则谱系（轻量三类起步）
- 不在未经拍板的情况下实施授权切片的注入裁剪逻辑
- 不改变世界模型三盒消费层（已对齐）
