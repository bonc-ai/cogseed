清单条目（原文编号）：
1. **API 连接异常（红圈卡死）**：连通性测试显示正常，但执行任务时出现红圈、模型不运行；需要重新测验连接后任务才能再次跑通。推测握手测试可通、长时间流式传输中途断流，测试接口与推理请求不是同一条链路。
2. **选项强制选择，无法留空 / 跳过**：界面底部三选一的答题控件必须选一个答案，不能不回答。根因：前端表单校验写死，缺少「不回答 / 跳过」选项。
3. **知识库问答输入框尺寸过小**：输入框很短，输入文字会向前滚动、看不到前面内容。根因：固定高度，没有自动扩容。
4. **任务状态错乱、后台延迟完成、重试状态冲突**：任务卡住后后台自动标记完成；点重试弹窗显示「正在运行」。前后端任务状态不同步、重试并发冲突。

> 编号 4 已在 `specs/001-reconcile-task-status` 完成实现；本特性将其纳入回归验证范围，不重复设计。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 连接测试正常时任务必须真正执行 (Priority: P1)

用户在设置里点「测试连接」显示成功，随后发起任务，但任务卡在红圈、模型没有任何输出。

**Why this priority**: 该问题让用户无法使用已配置可用的模型，且给出的手动解法（重新测试连接）证明凭证本身可用，属于可用性阻断。

**Independent Test**: 让某 profile 处于冷却状态（模拟上一次流式任务以可轮转失败告终），随后发起一次新的用户任务；系统不得因为「所有候选都在冷却」而直接判定模型不可用，应当把冷却候选作为兜底重试一次。

**Acceptance Scenarios**:

1. **Given** 唯一可用 profile 处于冷却中，**When** 用户发起新任务，**Then** 该 profile 被作为候选交给本次执行（重试一次），任务不会因「模型暂不可用」直接失败。
2. **Given** 存在健康候选与冷却候选，**When** 用户发起新任务，**Then** 健康候选优先，冷却候选仅在无其它可用候选时才作为兜底。
3. **Given** 兜底候选本次再次失败，**When** 轮转结束，**Then** 仍按既有逻辑重新进入冷却并向上抛出真实错误，不吞掉失败。

---

### User Story 2 - 表单可以跳过不回答 (Priority: P1)

三选一的提问表单必须选一个选项才能提交，用户希望能「不回答 / 跳过」。

**Independent Test**: 渲染一个包含必填单选字段的表单，点击「跳过」；提交必须成功，且提交内容显式标记为跳过、必填字段保持未作答。

**Acceptance Scenarios**:

1. **Given** 表单存在必填字段且用户未作答，**When** 用户点击「跳过」，**Then** 提交成功，不再被必填校验拦截。
2. **Given** 用户点击「跳过」，**When** 提交内容生成，**Then** 机器标签值包含显式的跳过标记，用户可见摘要包含跳过说明。
3. **Given** 表单没有必填字段，**When** 渲染表单，**Then** 不显示跳过按钮（可直接空提交，无需额外入口）。
4. **Given** 用户连续点击「跳过」，**When** 提交进行中，**Then** 只提交一次。

---

### User Story 3 - 知识库问答输入框随内容自动扩容 (Priority: P2)

在知识库问答框输入较长的多行问题时，文本会在一行内向前滚动，看不到前面的内容。

**Independent Test**: 触发输入事件并让内容高度增长；输入框高度必须随内容增大并封顶在既有最大高度，超过上限后才出现纵向滚动。

**Acceptance Scenarios**:

1. **Given** 输入框内容为多行，**When** 内容高度增长，**Then** 输入框高度随之增长。
2. **Given** 内容高度超过上限，**When** 继续输入，**Then** 高度封顶并出现纵向滚动条。
3. **Given** 问题已发送，**When** 输入框被清空，**Then** 高度复位到单行高度。

---

### User Story 4 - 任务状态与重试不再冲突（回归） (Priority: P2)

用户看到任务卡住，随后后台自动标记完成；点重试却提示「正在运行」。

**Independent Test**: 运行 `specs/001-reconcile-task-status` 对应的既有测试集，全部通过即视为回归通过。

**Acceptance Scenarios**:

1. **Given** 前端等待超过本地阈值而后台仍在排队/运行，**When** 页面同步状态，**Then** 不得仅因超时标记完成。
2. **Given** 原任务仍在运行，**When** 用户点击重试，**Then** 不创建重复执行，并提示原任务仍在处理中。

## Requirements *(mandatory)*

- **FR-001**: 会话任务的候选解析不得仅因「所有候选都处于冷却中」而返回空候选集并直接失败；当存在因冷却被排除、但其它条件均合格的候选时，应将其作为兜底候选返回。
- **FR-002**: 健康候选必须优先于冷却兜底候选；冷却兜底仅在主候选集为空时启用，不得削弱既有轮转优先级。
- **FR-003**: 冷却兜底候选本轮再次失败时，必须沿用既有冷却与错误上抛逻辑，不得静默吞错。
- **FR-004**: 聊天输入表单在存在必填字段时，必须提供「跳过 / 不回答」入口。
- **FR-005**: 跳过提交必须绕过必填校验，但保留其余字段的当前取值，并在提交标签中显式标记为跳过。
- **FR-006**: 跳过提交必须与普通提交共享同一提交/锁定路径，保证重复点击只提交一次。
- **FR-007**: 知识库问答输入框必须随内容自动增高，并受既有最大高度约束；超出后出现纵向滚动。
- **FR-008**: 发送问题后输入框高度必须复位。
- **FR-009**: 所有新增可见文案必须进入 renderer locales 并通过 `t()` 渲染。
- **FR-010**: 本批修复不得改变 IPC 契约、不得新增 npm 依赖、不得放宽既有安全边界。

## Success Criteria *(mandatory)*

- **SC-001**: 冷却兜底候选在「无其它可用候选」场景下被返回（单元测试覆盖）。
- **SC-002**: 存在健康候选时冷却候选仍被跳过（既有测试继续通过）。
- **SC-003**: 必填字段表单可经「跳过」成功提交，且重复点击只提交一次（单元测试覆盖）。
- **SC-004**: 多行输入时问答框高度增长，超上限封顶，发送后复位（单元测试覆盖）。
- **SC-005**: `specs/001-reconcile-task-status` 对应测试全部通过。
- **SC-006**: `npm run typecheck`、`npm run lint`、`npm run tokens:check`、`git diff --check` 通过。

## Edge Cases

- 同一个 (provider, model) 分组内多把 key，其中部分冷却：健康 key 仍优先。
- profile 已删除 / provider 被禁用 / key 无法解析：即使全部冷却兜底，也不得把这些条目当成可用候选。
- 冷却已过期：`isCooledDown` 返回 false，走正常主路径。
- 表单没有任何必填字段：不显示跳过入口。
- 表单包含文件字段且文件仍在上传：跳过不等待上传，直接按未作答提交。
- 问答框内容为空或仅空格：发送与扩容均不产生副作用。

## Out of Scope

- 不改动流式请求已产出内容后的重试策略（避免重复输出与重复副作用）。
- 不改动冷却时长、失败分类规则与轮转算法本身。
- 不重构聊天输入表单的编码契约（`<agent-input-submission>` 结构保持不变）。
