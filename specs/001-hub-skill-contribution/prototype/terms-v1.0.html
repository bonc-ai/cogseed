CogSeed 社区贡献条款

版本 v1.0

你（下称「贡献者」）在 CogSeed 客户端将一个 Skill 提交到 CogSeed Hub 之前，需要阅读并接受本《CogSeed 社区贡献条款》（下称「本条款」）。你在提交时勾选接受，即表示你已阅读、理解并同意受本条款约束；系统会记录你接受的条款版本与时间。不同意本条款的，请不要提交。

一、定义

• CogSeed Hub（下称「Hub」）：由 CogSeed 运营的 Skill 目录、分发与运营服务，包含 Hub 目录、Hub 后台及其客户端接口。

• CogSeed 客户端（下称「客户端」）：运行在 macOS / Windows 上的 CogSeed 桌面应用。

• 贡献者：以本人登录账号从客户端发起提交的用户。贡献者身份不是内容权限，不授予 Hub 后台的任何操作权利。

• Skill：你在客户端创建并验证过的、符合 Hub 包规则的技能包及其内容。

• 提交：你从客户端发起的一次贡献动作在 Hub 侧形成的待审核记录。

• 社区内容：经审核、发布并进入 Hub 目录的、来源标识为「社区贡献」的 Skill 内容，以稳定内容 ID（content_id）与版本号（version）标识。

• 官方副本：其他用户从 Hub 目录安装到本机、来源为 Hub 的内容副本。

• 派生副本：其他用户对社区内容执行「转为我的版本」后形成的、可自由修改的本机副本，携带 forked_from 溯源信息。

二、授权授予

2.1 你授予 Hub 的权利

在你保留全部知识产权的前提下，你就所提交的 Skill 及其后续修订版本，授予 Hub 一项非独占、不可转让、免许可费、全球范围的许可，允许 Hub 为运营社区目录之目的：

1. 存储与展示：存储该 Skill 的规范化内容树与发布物，在 Hub 目录、Hub 后台及其客户端界面中展示其名称、说明、版本、来源「社区贡献」与你的账号显示名；

2. 分发：通过目录接口向所有用户提供该 Skill 各已发布版本的下载，供安装、自动更新与后台核对下载；

3. 必要改写：在发布时向包内 _meta.json 写入后台版本号与时间戳（这是 Hub 唯一改写包内容的地方，名称、说明等其余内容一律不动）；

4. 检查与审计：对该 Skill 执行安全扫描、结构校验与内容检查，并记录审核、发布、停用等治理操作的审计事件（审计记录不含包正文）。

本许可仅在社区内容处于已发布状态且未被停用时支撑 Hub 的分发行为；你按照本条款第六节申请撤回并生效后，Hub 停止目录展示与新的分发。

2.2 你授予所有用户的权利

你同时向所有通过 Hub 获取该 Skill 的用户，授予一项非独占、免许可费、全球范围的许可，允许他们：

1. 下载、安装该 Skill 的官方副本并在客户端原有 Skill 入口中使用；

2. 接受官方副本的自动更新；

3. 执行「转为我的版本」，在本机形成派生副本并自由修改、保存、运行与卸载。

用户派生副本的修改、再创作由该用户自行负责，与 Hub 和你无关；但派生副本被再次提交到 Hub 时，同样按本条款（或提交时有效的更新版本）接受审核与授权。

2.3 无报酬

你知悉并同意：向 Hub 提交与维护社区内容不获得报酬，Hub 亦不因发布你的内容而向你收取费用。本条款不排除未来另行开展的激励计划，但那些计划另有规则，不构成本条款的一部分。

三、你的声明与保证

每次提交时，你须完成并保证以下事项真实、准确、完整：

3.1 来源声明

你须声明该 Skill 的来源属于以下之一：

• 原创：由你独立创作；

• 派生自 Hub 内容：基于 Hub 内既有内容修改形成（系统自动携带上游 forked_from 的稳定 ID 与版本，不可删除，你可补充说明）；

• 基于第三方材料：基于第三方代码、模型输出、文档或其他材料形成，你须补充说明。

3.2 权利保证

你保证：

1. 你是该 Skill 的权利人或已获得合法授权，有权按本条款授予上述许可；声明「派生」或「基于第三方材料」的，你的授权范围不超出你自己实际获得的权利范围；

2. 该 Skill 不侵犯任何第三方的著作权、商标权、专利权、商业秘密、隐私权或其他合法权益；

3. 该 Skill 不包含你没权分发的专有代码或许可证禁止再分发的第三方组件；含开源许可组件的，你遵守其许可证要求并保留其原有版权与许可声明。

3.3 内容保证

你保证该 Skill：

1. 不含真实凭据（密码、密钥、令牌等）、你的用户任务正文、提示词（Prompt）、私人实例 ID 或本机绝对路径——提交预览中识别出的此类敏感项必须剔除或处理后方可提交；

2. 不含恶意代码、后门、跟踪器或任何危害用户设备、数据或账号安全的机制；

3. 不含违反适用法律法规或公序良俗的内容，不用于传播违法信息、实施欺诈或侵害他人权益；

4. 符合 Hub 当时的包规则（形态、入口、元信息、安全边界、大小与文件数上限等，以 Hub 公布为准）。

3.4 账号使用

你保证提交使用你本人控制的有效登录账号；账号下的提交行为由你负责。你的账号被停用或注销后，你已发布的社区内容继续留存，内容负责人仍显示为你；新版本由运营按后台流程处理，来源声明保留你的原声明。

四、审核与发布

1. 审核是唯一准入闸门：任何登录用户均可发起提交，但所有提交须经 Hub 运营审核。Hub 有权接受或退回任何提交，且无需说明理由；退回时运营会尽量给出原因，供你修改后重新提交。

2. 接受不等于背书：审核通过只表示该提交转为版本草稿，仍须由具备发布权限的运营人员显式发布后才进入目录；Hub 及其运营人员对社区内容不作任何明示或默示的担保、推荐或背书。

3. 同名与检查：接受与发布时 Hub 会执行同名阻断与服务端安全检查（社区档阈值），不通过的提交被拒绝或保持待审核。

4. 提交管理：你可在审核前主动撤回提交；同一 Skill 在审核前重复提交的，新提交替换旧的待审核提交；每个账号同时保留的待审核提交数量有上限（默认 3 条，运营可配置）。

五、维护责任

1. 你在提交时确认愿意维护该内容的后续版本：包括提交修复版本、响应退回原因与配合治理处置。

2. 该承诺是社区协作的诚信承诺，不构成你与 Hub 之间的强制义务；你长期不响应时，运营可自行按 Hub 流程处理（停用该内容，或由运营后台导入修复版本，来源声明保留你的原声明），你不得以此主张 Hub 违约。

3. 你可随时对自己已发布的社区内容提交新版本（版本号须高于当前最高已发布版本），经审核发布后，已安装用户的官方副本自动更新到新版本，进行中的使用不受影响。

六、撤回

1. 申请与处置：你可对自己的已发布社区内容申请撤回并填写原因；撤回申请须经 Hub 内容治理角色处置后才生效。你不因贡献者身份获得直接停用权。

2. 撤回的效果：撤回生效等同于该内容全部版本的内容级停用——

• Hub 目录不再展示该内容，不能新安装；

• 已安装官方副本在客户端下次检查后阻断新的使用；不删除用户本机副本，不改动用户设置，不中止已开始的使用；

• 已形成的派生副本不受影响，用户在本条款下就其已取得的权利不被追回；

• 修复历史问题的正确动作是提交修复版本，而非撤回。

3. 不支持版本级撤回：你不能只撤回某一个版本；如需修复问题版本，请提交更高的修复版本。

4. 恢复：撤回生效后，恢复的唯一路径是你提交修复版本、经审核发布，再由内容治理角色执行恢复；你不能自行恢复。

5. 审核前撤回：尚未进入审核的提交，你可在客户端自行撤回，无需运营处置。

七、署名与展示

1. 社区内容在 Hub 目录中标识来源为「社区贡献」，并展示你的账号显示名；本版本不提供匿名贡献选项。你应确保显示名不冒充他人或官方。

2. Skill 的名称与说明以包内内容为唯一来源，Hub 不代为修改；你通过提交新版本更换它们。

3. Hub 对目录与分发保持匿名可访问；Hub 按稳定 ID、版本累计分发计数（源站成功返回一次计一次），不记录下载者的 IP、设备或账号。

八、数据与隐私

1. 提交发出什么：提交仅包含提交预览中向你展示的文件清单、文件内容与元信息（名称、说明、版本、来源声明、本条款版本、你的显示名）。预览之外的本机数据——安装清单、用户设置、任务正文、设备信息、其他 Skill——不会随提交发出。

2. 留存：提交记录、三项声明、审核与治理记录由 Hub 留存（留存期按 Hub 隐私口径执行）；审计记录不含包正文。

3. 删除的边界：Hub 对已发布内容没有删除权；撤回与停用均不删除服务端发布物与用户本机副本。
