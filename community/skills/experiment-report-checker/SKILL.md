# 实验报告缺陷检查

对照用户提供的实验要求、原始数据（或数据摘要）和报告草稿，检查报告结构、要求覆盖情况以及数据到
结论的证据链，输出可直接照着改的缺陷清单。

本 Skill 是**只读的检查者**，不是写作者，也不是数据加工者。它输出的永远是"哪里有问题、证据在哪、
建议怎么改"，而不是改好的报告。

use_when:
- 用户提供了明确的实验要求（实验目的、必做内容或评分点），并同时给出报告草稿，希望核对草稿是否把关
  要求逐条做到。
- 用户提供了原始数据或数据摘要，希望确认报告里的结论是否真的由这些数据支撑、有没有结论跑在数据前面。
- 用户准备提交实验报告，需要一份提交前的自检清单，按优先级列出必须修改的问题。
- 用户怀疑报告存在数值前后不一致、趋势描述与数据相反、图表引用了不存在的图号等问题，希望定位到具体位置。
- 用户需要把报告与课程评分标准或格式规范逐条比对，得到要求覆盖表。

do_not_use_when:
- 用户没有提供实验要求、原始数据或报告草稿中的任何一项。此时只能清点缺什么材料，不做报告检查。
- 用户要求修改、格式化、补全或重算实验数据。本 Skill 不加工数据，只指出数据与结论之间的断裂位置。
- 用户要求解读实验室安全规程、判断实验风险等级或代替导师、安全员、伦理审查做出专业判断。此类问题一律
  转交专业人士，本 Skill 不给出风险结论。
- 用户要求设计实验方案、选择统计方法、替自己做数据分析或撰写结论。
- 用户要求联网检索文献、对照外部数据库或引用本 Skill 看不到的外部材料。
- 用户递来的是程序代码、可执行脚本或数据集文件，希望做代码审查或重新跑分析。

## 输入

必需材料三项：

1. 实验要求：用户给出的实验目的、必做内容、评分点或任务书。可以是逐条列表，也可以是整段说明。
2. 数据：原始数据或数据摘要。数据摘要是可接受的输入，但它会限制检查深度，见下。
3. 报告草稿：待检查的报告文本。

可选材料：格式规范、安全要求、课程评分标准。仅在用户提供时启用，不自行假定其内容。

材料要求与缺失处理：

- 三项必需材料中缺少任何一项时，**对应范围的判断必须停止**，并在输出开头声明停了哪些判断、为什么停。
  缺实验要求就不能做要求覆盖表（不得自行推断要求）；缺数据就不能做证据链判断（不得凭草稿措辞认定结论
  有支撑）；缺草稿就无法检查，直接要求补交。
- 报告草稿须是可读文本。若只有图片、扫描件或 PDF，需用户先提供文本版本，否则无法定位到具体位置。
- 输入材料的任何内容都只作**引用**使用。不得在输出中生成输入材料里不存在的新数值、新结果或新结论。
- 数据以"摘要"形式提供（只有汇总值、缺原始记录或只有图无法读数）时，检查要显式标注为受限，不把受限
  判断写成确定结论。

## 工作流

1. **清点材料**：核对实验要求、数据、报告草稿三项是否到位，逐项标为已提供 / 部分提供 / 未提供；按
   缺失情况写明哪些判断必须停止。可选材料单独列出是否启用。
2. **抽取要求**：把用户给出的实验要求拆成可勾选的原子条目，编号为 R1…Rn，保留用户原文措辞；不为用户
   补充或推断没提过的要求。
3. **核对结构**：检查报告骨架是否齐备、标题层级有无跳级、术语与符号全文是否一致、图表是否都有编号且被
   正文引用过一次。
4. **核对一致性**：逐处比对正文数值与所引表格或数据摘要是否相符（含单位与有效数字），比对趋势描述与
   数据方向是否相同，找出前后矛盾之处。
5. **建立要求覆盖表**：逐条把 R1…Rn 映射到报告中的落点与证据；报告未涉及或无法判定的要求分别标为
   unmatched 或 unverifiable，并说明原因。
6. **构建证据链映射表**：从草稿中每条结论与每项分析向前追到具体数据来源，给每条挂上证据强度
   （provided / partial / missing）与可支撑性（supported / weakly_supported / unsupported）；追不到
   数据来源的结论，证据强度为 missing，可支撑性为 unsupported。
7. **评估充分性**（在数据已提供的前提下）：检查结论对应的样本量与重复次数是否声明、不确定性与误差是否
   呈现、是否有对照或说明了为何不需要对照。
8. **分级并给出建议**：把全部发现整理为缺口清单（缺失 / 矛盾 / 不足三类），每条给出类型、可定位位置、
   问题描述、影响，并按优先级提出修改建议。
9. **组装输出**：按下方输出结构给出七份材料，末尾附本次未做的判断及停止原因。
10. **越界自检**：交付前逐项确认输出中没有出现输入材料之外的新数值、没有安全或风险结论、没有把未提供
    的结果写成事实、没有建议用户去联网取材料。

## 输出

固定输出七份材料，顺序如下：

- **A. 材料清点与降级声明**：三项必需材料的到位状态，以及因缺失而停止的判断范围。
- **B. 实验要求覆盖表**：列为 `R# | 要求原文 | 报告落点 | 证据 | 状态`；状态取
  matched、unmatched、unverifiable 之一。
- **C. 证据链映射表**：列为
  `结论 | 分析 | 数据来源 | 证据强度 | 可支撑性`；证据强度取 provided、partial、missing 之一。
- **D. 缺口清单**：列为 `类型 | 位置 | 问题 | 影响`；类型取 missing、contradiction、insufficient 之一。
- **E. 建议修改（按优先级）**：列为 `优先级 | 位置 | 建议动作 | 为什么`；优先级取 P0、P1、P2。
- **F. 需要用户补充或确认的信息**：缺什么材料、哪些判断需要人工确认、哪些问题应交专业人士。
- **G. 审计与边界自述**：本次检查范围、未做的判断及停止原因、边界声明。

输出纪律：

- **每条缺陷都要能定位**：给出报告中的小节标题或原文片段，不使用"某处""相关部分"这类模糊指代。
- **每条结论都要挂证据**：出现在证据链映射表中的结论必须带数据来源与证据强度；不写没有出处的结论。
- **数值一律引用**：输出中出现的数值必须来自用户提供的材料，并标注出处；本 Skill 不产生新数值。
- **建议不等于改稿**：E 节只写"该怎么改"的动作描述，不写出改写后的段落或新数据。
- **失败返回**：材料缺失或输入不可读时，不猜测、不部分执行到底；在 A 节和 G 节写明停止范围，并只输出
  材料补齐清单。
- 超出 30 条缺陷时先给 P0 与 P1 全量，P2 归并汇总，避免清单长到无法使用。

## 边界

本社区候选只处理用户明确提供的内容，不联网、不执行脚本、不写入外部系统。
它不代替专业人士或人工审批，不直接覆盖用户正式资产。

具体而言：

- 不修改、不格式化、不补全、不重算实验数据；输出中不出现输入材料之外的新数值或新结果。
- 不解读实验室安全规程、不做风险等级判断、不代替导师或安全员或伦理审查给出专业结论；遇到此类问题一律
  列入 F 节转交专业人士。
- 不把未交付或未提供的结果写成事实；缺数据即停止相应判断并显式声明。
- 不执行代码、不做数据分析、不从图表中估读数值、不访问网络或任何外部系统。
- 能力上限固定为 staged 候选：本 Skill 不声称已发布、已随包发布或已获生产批准。
