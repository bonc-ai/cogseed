# 演进记录与知识累积（kstar evolution）

本文件记录 experiment-report-checker 的知识来源、当前能力边界，以及后续演进时的准入条件。任何演进都
不得突破 `references/governance-boundaries.md` 的边界；边界声明不在可演进面内。

## 1. 知识来源

| 来源 | 类型 | 用途 |
|---|---|---|
| 上游社区技能 Issue（实验报告缺陷检查器） | 需求规格 | 决定检查对象、输入、五类产出、四条红线 |
| 上游社区技能模板与提交规范 | 格式契约 | 决定包结构、frontmatter 字段、必需小节、封顶声明 |
| 实验报告写作与测量的通行做法 | 领域知识 | 决定一致性检查维度：单位、有效数字、样本量、不确定度、方向一致 |
| 本体切片方法 | 结构方法 | 决定 TBox / RBox / ABox 三层与十一条推理规则 |

本 Skill 不引入第三方材料，`provenance.json` 的第三方列表为空。作者声明为原创实现。

## 2. 当前能力面

- 能做：结构核对、要求覆盖、内部一致性核对、证据链可支撑性判定、缺口分级、人工交接项整理。
- 不能做：产生新数值（唯一例外是 `references/output-contract.md` §3 定义的、带 `对账推算` 标记的对照
  算式）、重算、格式化成稿、安全或风险判断、联网比对、执行脚本、写入外部系统。
- 已知残余差距：导入 CogSeed 时必然出现三条 MEDIUM 提示（无 `_meta.json` 与 `schemas.json` 所致），
  详见 `references/governance-boundaries.md` 第 6 节。

## 3. 演进方向与准入条件

| 候选方向 | 收益 | 准入条件 |
|---|---|---|
| 增加学科专用的一致性规则（如化学计量、电路参数） | 提升覆盖深度 | 规则必须有明确定义与可判定期望行为，且不引入外部标准 |
| 增加报告模板结构比对 | 结构检查更具体 | 模板由用户提供，不内置任何课程模板 |
| 与评分标准结合做分值影响排序 | 建议优先级更贴近课程 | 评分标准须由用户提供，不假定权重 |
| 支持多语言报告 | 适用面更广 | 不改变输出七节结构 |

以下方向明确不纳入：任何形式的写文件、联网、脚本执行、数据重算、安全或风险判断、代写正文。这些不是
待办事项，而是永久边界。

## 4. 演进流程

1. 提出变更时，先判定是否触及边界声明。触及即终止，不进入评审。
2. 变更必须同时更新用例：`evals/evals.json` 与 `references/eval-cases.yaml` 同步增删，保持一一对应。
3. 变更必须保持七节输出结构与追溯要求五条不变；若确需调整，视为破坏性变更并单独说明。
4. 变更后重新核对包内文件数与体积上限，并确认全文不含未替换占位符与机器绝对路径。
5. 两处封顶声明在任何变更后都必须保持原值。

## 5. 版本与状态

- 当前形态：社区候选包，纯文本声明式，无脚本。
- 当前状态上限：staged（社区候选已评审级别）。
- 生产发布：硬锁为否，不得声称已发布或已获生产批准。
- 风险等级：L2，前提是仅个人本地使用；共享或元技能化须上调至 L5，属治理工作。
