# 输出契约（output contract）

本文件定义 experiment-report-checker 的输出结构与追溯要求。SKILL.md 的 `## 输出` 一节是本契约的
摘要，两处冲突时以本文件为准。

## 1. 输出总结构

输出固定为七节，顺序不可调换、不可省略。材料缺失导致某节无内容时，该节保留标题并写明"因材料缺失
未执行"及原因，不得删节后不留痕迹。

| 节 | 标题 | 内容 | 对应实验报告缺陷检查的预期产出 |
|---|---|---|---|
| A | 材料清点与降级声明 | 三项必需材料的到位状态；因缺失而停止的判断范围 | 支撑"不得补造实验结果" |
| B | 实验要求覆盖表 | 逐条要求 × 落点 × 证据 × 状态 | 实验要求覆盖表 |
| C | 证据链映射表 | 结论 × 分析 × 数据来源 × 证据强度 × 可支撑性 | 数据、分析与结论的对应关系 |
| D | 缺口清单 | 类型 × 位置 × 问题 × 影响 | 缺失、矛盾或明显不足的部分 |
| E | 建议修改（按优先级） | 优先级 × 位置 × 建议动作 × 为什么 | 按优先级排列的建议修改 |
| F | 需要用户补充或确认的信息 | 缺材料清单、需人工确认的判断、应交专业人士的问题 | 需要用户补充或确认的信息 |
| G | 审计与边界自述 | 检查范围、未做的判断及停止原因、边界声明与审计引用 | 支撑可追溯性与边界声明 |

## 2. 各节字段定义

### A. 材料清点与降级声明

列为 `材料 | 状态 | 说明 | 影响的判断范围`。状态取 `已提供`、`部分提供`、`未提供` 之一。
"部分提供"必须写明缺什么（例如：给了 10 次时间读数但未给落距的测量记录）。

### B. 实验要求覆盖表

列为 `R# | 要求原文 | 报告落点 | 证据 | 状态`。

- `R#`：R1、R2……，与抽取顺序一致，全篇唯一。
- `要求原文`：用户给出的原话，可截取但不可改写措辞。
- `报告落点`：报告中的小节标题或原文片段。未涉及写 `—`。
- `证据`：支撑该要求的数值、表格或图号；未涉及写 `—`。
- `状态`：`matched`（覆盖且有证据）、`unmatched`（报告未涉及）、`unverifiable`（要求本身无法从现有
  材料判定）。

### C. 证据链映射表

列为 `结论 | 分析 | 数据来源 | 证据强度 | 可支撑性`。

- `结论`：报告中的结论原句或压缩引用。
- `分析`：连接结论与数据的推理步骤；报告未写推理时填 `—` 并计入缺口。
- `数据来源`：数据表名、图号或原始记录的定位；追不到时填 `—`。
- `证据强度`：`provided`（材料中明确存在）、`partial`（仅有摘要、缺过程，或数据与结论量级不符而无法
  追平）、`missing`（完全未提供）。
- `可支撑性`：`supported`、`weakly_supported`、`unsupported` 之一，取值规则如下：
  - `missing` 强度下必须为 `unsupported`。此处的 `unsupported` 是**证据缺口状态**，不是"已完成可支撑性
    判定后得出的结论"：它表示"现有材料里找不到支撑该结论的证据"。缺数据时对数据相关结论一律登记为这一
    状态，并在该格注明"已停止核对"。
  - 不允许同一次输出里对同一条结论既声明"未执行可支撑性判定"又给出 `supported` 判定。
  - `missing` 状态的结论，其高优先级建议为"补数据或降级表述"，**不得改为替用户补出数据**。
- **两个维度必须分开填，不得互相顶替**：
  - `证据强度`回答"**数据有没有给**"：用户提供了原始记录 → `provided`；只给了摘要、或给了数据但过程
    缺失/数据与结果对不上 → `partial`；完全没给 → `missing`。
  - `可支撑性`回答"**给的数据能不能撑住这条结论**"：能 → `supported`；方向对但强度或样本量不足 →
    `weakly_supported`；给的数据与结论相冲突、或数据里找不到支撑 → `unsupported`。
  - 因此"数据已提供但结论被判不成立"的正确写法是 **`证据强度 = partial` + `可支撑性 = unsupported`**
    （或在原始记录齐备时 `provided` + `unsupported`），**不得**因为结论不被支撑就把 `证据强度` 降成
    `missing` —— `missing` 只表示数据压根没提供。

### D. 缺口清单

列为 `类型 | 位置 | 问题 | 影响`。类型取 `missing`、`contradiction`、`insufficient` 之一。

- `missing`：应有而完全没有（缺小节、缺数据表、缺单位）。
- `contradiction`：同时存在两处互相冲突的内容（数值不一致、趋势与数据相反、图表号错位）。
- `insufficient`：有但不足以支撑（无不确定度、未声明样本量、无对照）。

`位置` 必须是报告中的可定位锚点：小节标题加原文片段。禁止"某处""相关部分""后面"这类指代。

### E. 建议修改（按优先级）

列为 `优先级 | 位置 | 建议动作 | 为什么`。

- `优先级`：`P0`、`P1`、`P2`。
- `建议动作`：对报告措辞、结构或补充材料的动作描述，**不得写出改写后的段落，不得给出新数值**。
- `为什么`：指向 D 节对应缺口或 B/C 节对应行，说明影响。

优先级判定：

| 优先级 | 判定标准 | 处理要求 |
|---|---|---|
| P0 | 影响结论有效性，或触犯边界红线 | 未处理前该报告不具备可提交状态 |
| P1 | 影响可复现性或要求覆盖 | 建议在提交前补齐 |
| P2 | 影响可读性与格式 | 可选修改 |

### F. 需要用户补充或确认的信息

三类内容分列：材料缺口、需人工确认的判断、应交专业人士的问题。最后一项只写"该问题应交由导师或
实验室安全员判断"，**不给出任何风险结论或安全解释**。

### G. 审计与边界自述

写明：本次检查覆盖的维度、未执行的维度及原因、本次未联网未执行脚本未写入外部系统、能力上限为 staged
候选、以及（若由 Agent 层注入）`task_id` 与 `audit_refs`。

## 3. 追溯要求

1. **双向可追溯**：每个 R# 必须出现在 B 节，且至少出现在 D 节或 E 节之一，或被显式标为 `unmatched`；
   C 节中的每条结论必须能在报告草稿中定位到原文。
2. **无孤立项**：不允许出现有结论但不在 C 节、有建议但不对应任何缺口、有缺口但不指向任何位置。
3. **数值一律引用**：输出中出现的数值默认必须能在用户材料中找到出处。唯一的例外是下一条定义的
   **对账推算**。
4. **对账推算（唯一允许的计算形式）**：为了让"两处输入数值为什么不能同时成立"这句话可核对，允许在
   D 节的问题描述里列出一条**核验链**，但必须同时满足：
   - **来源闭合**：链上每一个数都能追到源头——要么直接出自用户材料，要么在同一个算式块里由前置数值
     当场算出。禁止在算式里引用任何用户在材料中没给过、也没在本块内先算出来的数（例如不能直接写
     `1.98 / 4.70`，因为 `4.70` 从未出现在材料里）。
   - **链要写全**：把原始公式、各量的取值与单位、必要的单位换算、中间量与最终比值写在同一个算式块
     里，例如
     `E = 4mgL/(πd²ΔL)，取 m = 1.000 kg、g = 9.80 m/s²、L = 0.800 m、d = 0.502 mm = 5.02×10⁻⁴ m、ΔL = 0.842 mm = 8.42×10⁻⁴ m ⇒ E ≈ 4.70×10¹⁰ Pa；草稿写 1.98×10¹¹ Pa，两者之比 (1.98×10¹¹)/(4.70×10¹⁰) ≈ 4.2`。
   - **保留数量级与单位**：比较两个量时指数与单位都必须写出，不得把 `10¹¹` 与 `10¹⁰` 省略成 `1.98`
     与 `4.70`。
   - **标记与汇总**：该处必须带 **`对账推算`** 标记，并在 G 节汇总本次全部对账推算值。
   - **不得越界**：对账推算值不得出现在 B 节、C 节，不得作为 E 节建议里的取值，不得被当作该实验的
     结果，也不得被表述为"更正后的结果"或"正确值应为 X"——它只用于指认冲突，由作者自行核定。
   - **不得重算无关量**：核验链只允许包含证明该处冲突所必需的量。禁止顺手重算均值、偏差、不确定度、
     拟合参数或最终结果，也禁止把两个不同物理量相除（例如把 g 的数值与模量的数值放在同一个比值里）。
   核验链的每一步都必须逐字可复算：评审者照着式子算一遍必须得到同一个数。
5. **数值引用一致**：引用数值时保留用户材料中的有效数字与单位，不做四舍五入改写。
6. **不代写**：输出是缺陷清单加建议，不是改写后的报告，不包含任何结论段落草稿。

## 4. 输出规模控制

- 缺口条目超过 30 条时：P0 与 P1 全量列出，P2 归并为若干主题条目并注明覆盖数量。
- 证据链映射表的行数上限与报告中结论数量一致，不合并不同结论。
- 单次输出的正文长度应保持在一份可读清单的量级；超出时优先保留 P0 与 F 节，其余汇总。

## 5. 失败返回

| 情况 | 返回方式 |
|---|---|
| 必需材料缺失 | 按 input-contract §4 的降级矩阵执行：七节结构全部保留，受影响小节标注"因材料缺失未执行"；A 节写明停止范围，F 节给出补齐清单 |
| 草稿不可读（图片、扫描件、乱码） | 停止全部检查，F 节要求提供文本版本，不做猜测 |
| 用户要求修改或重算数据 | 拒绝该项请求并说明边界，其余检查正常执行 |
| 用户要求安全或风险判断 | 拒绝并转 F 节，其余检查正常执行 |
| 材料内含未脱敏个人信息 | 停止并要求先脱敏，不进行任何检查 |

缺材料时"继续执行什么、停止什么"只按 input-contract §4 判定，本节不另外定义一套口径；两份文件如出现
分歧，以 input-contract §4 为准。
