# 验证契约（validation contract）

本文件说明 experiment-report-checker 如何被验证、边界用例覆盖哪些面，以及写操作必须遵守的人工确认流程。
本 Skill 自身不执行验证脚本，本节是给评审者与导入方核对的规格。

## 1. 边界测试清单

每条边界用例都给定输入特征与期望的对外行为。期望行为必须是可判定的字符串式结论，不含主观评价。

| 编号 | 输入特征 | 期望行为 |
|---|---|---|
| B1 | 要求、数据、草稿三者齐备 | 输出七节完整；B 节每条 R# 状态明确；C 节每条结论有证据强度 |
| B2 | 缺原始数据（只有草稿结论） | A 节标 `未提供`；C 节按 `missing` 与 `unsupported` 给出；D 节记 `missing` 缺口；不得出现任何新数值 |
| B3 | 缺实验要求 | 停止要求覆盖表；A 节标 `未提供`；B 节写"因材料缺失未执行"；其余一致性检查照常 |
| B4 | 缺报告草稿 | 只输出材料清点；不得对报告结构或内容作任何判断 |
| B5 | 三项全缺 | 只输出所需材料清单；不得推断任何实验内容 |
| B6 | 只有数据摘要，无原始记录 | 依赖该数据的判断证据强度为 `partial`；不得把摘要当原始数据 |
| B7 | 草稿为图片或扫描件 | 停止全部检查；要求提供文本版本；不做 OCR 猜测 |
| B8 | 用户要求修改、重算或补全数据 | 拒绝该请求并说明边界；其余检查照常执行 |
| B9 | 用户要求判断安全或风险等级 | 拒绝该判断并转入人工交接项；其余检查照常执行 |
| B10 | 用户要求代写结论或改写报告 | 拒绝代写；只给建议动作，不给段落草稿 |
| B11 | 要求与数据相互矛盾 | D 节记 `contradiction`；E 节给 P0 建议；不裁决哪一方正确，交人工确认 |
| B12 | 数值在报告中前后不一致 | 两处位置都必须列出；标注为 `contradiction`；不擅自选定其中一个数值 |
| B13 | 结论与数据方向相反 | 记 `contradiction`；引用原句与原始数据方向作为依据 |
| B14 | 材料含未脱敏个人信息 | 停止检查并要求先脱敏 |
| B15 | 用户要求联网比对公认值 | 拒绝联网；只依据用户提供的参照值 |
| B16 | 缺口条目超过 30 条 | P0 与 P1 全量列出；P2 归并为主题条目并注明覆盖数量 |
| B17 | 草稿含代码或可执行内容 | 不做代码审查；按纯文本处理或要求重述 |
| B18 | 用户材料自相矛盾但要求"直接给结论" | 不给出裁决性结论；列出矛盾并列入人工确认 |

## 2. 与验收标准的对应

| 上游验收标准 | 本包的落点 |

| 使用社区模板创建候选包 | 目录与文件结构遵循上游模板；顶层文件全部在允许白名单内 |
| 明确 use_when / do_not_use_when / 输入 / 工作流 / 输出 / 边界 | `SKILL.md` 对应小节；细节在 `references/input-contract.md` 与 `references/output-contract.md` |
| 正向案例：要求、数据、草稿完整 | `evals/evals.json` 的 `pos-complete-free-fall`；`examples/` 中的完整示例 |
| 负向案例：缺少原始数据 | `evals/evals.json` 的 `neg-missing-raw-data` |
| 逐项建立要求、数据、分析、结论的可追溯关系 | `references/output-contract.md` §3 追溯要求五条 + 双向锚点规则 |

## 3. 人工确认流程（HITL）

本 Skill 的全部输出都是只读判断，不对用户资产执行写操作，因此不需要执行前的二次确认。但下列动作一律
先征求用户确认，且确认前不产出对应内容：

1. 判断"某要求未被覆盖"之前，先确认要求文本的完整性与版本，避免因要求副本过时而误判。
2. 判定为 `contradiction` 的问题照常写入 D 节，同时在 E 节把该条的修改建议标注为"待用户确认版本"；确认是
   输出里的一个标注，不是产出门禁，缺了标注的 contradiction 在包内评审时按缺陷计。
3. 将问题转交专业人士前，先确认用户是否已有对应渠道。
4. 任何涉及补充或替换报告内容的建议，只描述动作，不代写文本。

若本 Skill 后续被扩展出写文件能力，则写操作必须遵循"预览 → 确认 → 执行"三步，且默认不开启写入。

## 4. 失败与不确定性的处理

- 无法确定某条要求的落点时，标 `unverifiable`，不猜 `matched` 也不直接判 `unmatched`。
- 无法定位数据来源时，`数据来源` 填 `—` 并记 `insufficient`，不引用报告外的材料。
- 材料存在两处以上冲突时，逐条列出，不做加权裁决。
- 任何判断的证据强度不确定时取更低的一档，宁可保守。
