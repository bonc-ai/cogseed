1

结论先行

先说结果：这次迭代把认知资产从「文件记忆 + 整段注入」的旧模式，升级成一条统一的资产管线。

develop 上（合入 PR #291 后的现状）的认知资产是：记忆写在 USER.md / MEMORY.md 文件里，模型开始任务时自动整段注入一部分资产全文，资产平铺展示，模型很少主动去查；更新资产等于新内容整段覆盖旧内容；本体组（用户长期画像的结构化分组）只能手改文件。

迭代分支把它升级为：① 模型通过「目录 + 按 id 取用」主动查资产，每次取用留审计记录；② 模型写记忆直投统一资产管线，旧记忆文件自动迁入，记忆页退役；③ 写入线带语义去重与语句级融合，更新不再粗暴覆盖；④ 同类资产自动成族、可命名；⑤ 本体组获得界面化结构编辑、矛盾检测台账、时间锚与回流确认；⑥ 出身区分全链退役，只留单一「已确定」状态。

对模型：资产从「被塞进上下文」变为「按需查目录、按 id 取全文」 对用户：记忆页退役，本体组可视化编辑，资产面板新增目录视图与模型选用卡片 对数据：旧记忆文件已自动迁入资产库（真机验证 USER.md 清零）

① 目录化召回 —— 模型怎么看见资产

09-18 为主
召回 / 注入链
白话版：原来是「开始任务前先塞一摞资料给模型」，模型自己基本不翻；现在是「给模型一份目录，要哪条按编号取哪条」，而且取了什么都有账可查。开关实验发现：自动注入反而让模型更懒（开注入 12 轮里自发取用 3 轮，关掉后 5 轮），所以默认关注入、目录为主通道。

DEVELOP 现状

  • Top-N 语义投影整段注入资产全文
  • 模型不主动查询（工具说明改写后仍 0–1/3）
  • 取用行为无逐条记录，账目对不上

迭代分支

  • 资产目录进提示词：≤30 条全量内联（约 1KB）；大库取最常用 20 条 + 剩余数量提示，单条从 228 字压到 109 字，页头页尾 <250 字
  • 工具双模式：无参数返回整本目录（可筛选 / 翻页）；传 assetIds 返回全文（一次 6 条、单条 2000 字）
  • 目录按本轮任务文本做相关性排序，余弦 ≥ 0.40 打星；大库「两跳策略」（先查目录、再语义检索）写进工具说明
  • 内容真正进入模型上下文才记 agent_read 回执 + 使用记录（每轮幂等），显式读取不再被「适用场景」软提示否决
  • 自动全文注入默认关闭；COGSEED_RECALL_BASELINE_TOP>0 可开回（回退通道与实验复现保留）
关键提交：5523629b787208fcdd4db775d8db2914b7bc91340db2f78bdc044f100f3caba88b961249（注入总开关）

统一写入线

④ 写入线升级 —— 去重金字塔与语句级融合

09-19
更新不再覆盖
白话版：原来确认一条「更新」，新句子直接换掉旧句子，旧内容说没就没；现在先判断新内容和已有资产是什么关系——完全重复就不入库、高度相关就并进旧资产、确认更新就逐句融合（说得一样的取更全的版本，真有新信息才加进来），每一步可回溯。

DEVELOP 现状

  • 更新候选确认 = 整段覆盖旧 statement
  • 查重只判「是不是重复」，重复与相关之间没有处理
  • 同主题资产越攒越散

迭代分支

  • 去重金字塔 L1/L2：语义查重同时报告最佳「相关命中」（相似度 0.70–0.85 区间）；相关候选若质量明显更高，改写为「对既有资产的更新」而不是新建散资产（首次接通资产质量分门槛）
  • 语句级融合生成器（纯函数）：复述取更长的变体、同主题改写做替换、真增量才追加；复述判定用重合系数（中文长短句对不被句长稀释）
  • 更新晋升 = 融合而非覆盖，版本记录 reason 标 semantic-fusion，可识别可回退；限定范围的更新保留整段替换语义
  • 兜底修正：候选没有显式值时回退到判定文本而不是把标题泄进正文；家族关系直写不顶版本号，投影版本冻结不再被破坏

⑥ 本体组增强 —— 画像的界面化治理

09-19 下午→夜间
结构化编辑 / 矛盾 / 回流
白话版：本体组是「关于用户的长期事实」的结构化存放处（比如沟通偏好、答辩习惯，按字段一条条存）。原来改它要手改文件；现在有完整界面：增删改字段值、标时间、标核实，同一字段出现打架的两个值时进台账等用户裁决，转正的资产还能回流成本体候选。

DEVELOP 现状

  • 组字段值只能手改文件
  • 无矛盾检测：同字段新旧值打架无感知
  • 无时间信息：不知道这条「事实」是什么时候的
  • 资产转正与本体互不相通

迭代分支

  • 本体组子页：结构化编辑（字段列表 / 追加 / 移除 / 核实 IPC），矛盾标记、回流确认内嵌在界面里；组改名统一「本体组」；刷新后重拉状态，外部新建的组也能看到
  • @asof:YYYY-MM 时间锚：字段值可标「信息截至年月」，世界模型消费时对过期值给 stale 提示
  • 同字段矛盾检测：发现冲突进异步台账，等用户判定；台账事务串行化 + 判定超时守卫，坏台账不拖垮读取（读时自愈）
  • 回流双轨：资产转正后回流本体候选池，确认时可选择去向
  • 用户核实标记透出给世界模型；画像条目改裸文本存储（出身前缀只在显示层）；画像块来源修正为资产库并补齐四语文案

⑨ 作用域收严 + 稳定性 P0 修复

09-18 → 09-19
scope / 防炸
白话版：两件事：一是「谁能看见这条资产」（作用域）原来随便填句子，现在写入时自动归一成规范词，编辑器里有白名单输入框；二是修了两个能让整个面板卡死的 P0 缺陷——打开总览页就死循环、一条坏记录拖垮整条时间线。

DEVELOP 现状

  • scope 自由文本，「适用场景」句子混进受控词
  • applicableWhen / forbiddenWhen 允许存空数组（三态歧义）
  • 模型挂载徽章每次通知都重渲染并再通知 → 打开总览页死循环冻结整面板
  • 一条投影记录被删的转移证明能让整条时间线抛错

迭代分支

  • scope 写入三档归一：受控词自动规范；顿号 / 逗号组合词逐段校验；「……时」类用途句回退 general；读取侧不动，旧数据兼容
  • 资产编辑器新增「谁可以看」白名单输入（agent / space，走既有 scopePolicy，留空即解除限制），四语齐全
  • 空数组折叠为「未声明」，三态归二态
