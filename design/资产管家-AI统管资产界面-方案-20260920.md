# 资产管家（Asset Steward）——AI 统管资产界面的实现方案

- **日期**：2026-09-20（v2，同日按子安方向修正）
- **状态**：方案待拍板（拍板后按 spec kit 规范落 `specs/008-asset-steward/`）
- **v2 修正记录**：① 管家从「独立后台服务」改为**并入智能体主体**（对话即指挥）；② 确立**双入口并存**——对话指挥（入口 A）+ 模块自动巡检（入口 B），共享同一套底层与闭环；③ 新增出处诚实拆账（§0.1）
- **性质**：局外功能（站在现有各功能之上统管，不改各功能自身的业务逻辑）

---

## 0. 一句话结论

把散落在认知资产各功能里、写死在代码中的**参数与裁决规则**收口成一张「策略注册表」，然后给这套可调项开**两个入口**：你在对话里直接指挥主智能体调控（入口 A），模块也定期/按事件自己带着运行账本找 AI 判定、产出建议（入口 B）——两个入口产出的都是同一种**变更集**，走同一个「批准 → 执行 → 回滚 → 回验」闭环。**代码兜底、AI 调优、用户授权、全程可回滚**。

**为什么这样做**：固定算法的问题不是「不该自动」，而是「一个值对所有人、永远不变」（实测偏差见 §1）。但让 AI 直接改数据或改代码都不可接受（失控、不可回滚、与并行开发冲突），唯一安全形态是：**算法不变，参数与裁决点变成受控可调项，AI 只能在约束范围内提案，人保留否决与回滚**。

## 1. 问题定义：固定算法到底管了什么、哪些不合适

### 1.1 实测盘点（截至分支快照 0701d934，均带出处）

**A. 数值参数类**（写死的阈值/预算/窗口）：

| 参数 | 当前值 | 出处 | 固定算法的问题 |
|---|---|---|---|
| 语义查重阈值 | 0.85（重复）/ 0.70（相关） | `similarity.ts:19-21` | 0.70–0.85 之间是灰区，全靠用户人工评审，堆积过多 |
| 族聚类阈值 | 0.60，最多聚 200 条 | `family.ts:22,71` | 0.60 对每个用户语义空间不一定合适，聚不拢/聚过头都发生过 |
| 目录星标阈值 | 0.40 | `context-projection.ts:449` | 星标=「与本轮任务相关」，0.40 是拍的，漏用审计已在实测它的偏差 |
| 画像新鲜度窗口 | 72 小时 | `profile-block.ts:37` | 「刚教的偏好」多久算新，因人而异 |
| 目录内联规模 | ≤30 条全量，大库 Top-20 | `asset-catalog-hint.ts:23,123` | 30/20 对小用户浪费、对大用户不够 |
| 候选有效期 | 90 天 TTL、稍后处理冷却 7 天 | `candidate-service.ts:85-86` | 与用户整理频率强相关，固定值必然错配 |
| 语义选择条数 | Top-8 | `context-projection.ts:455` | 注入预算内最优条数应随资产平均长度动态定 |
| 融合语句上限 | 4000 字 | `statement-fusion.ts:15` | 固定截断，长偏好陈述被切 |
| 回流池/组数/规则数上限 | 20/48/64 | `ontology-backflow.ts:28`、`ontology-rules.ts:24-26` | 上限拍脑袋，满了即静默丢弃 |
| 目录缓存 TTL | 60 秒 | `asset-catalog-hint.ts:21` | 使用频率高时应更短 |

**B. 语义裁决类**（固定规则替 AI 做了判断）：

| 裁决点 | 当前固定做法 | 固定算法的问题 |
|---|---|---|
| 查重灰区处置 | 0.70–0.85 一律标记等用户评审 | AI 完全可以先给「建议合并/新建/忽略」预判 |
| 融合三分类 | 重合系数+句长规则判「复述/改写/增量」 | 边界 case 靠数值系数误判（中文表达灵活） |
| 族头命名 | 最多使用成员标题前 10 字硬截断 | 不是「起名」，是「截断」，命名质量差 |
| 矛盾裁决辅助 | 只标记矛盾进台账，无任何预判 | AI 可给「建议采信方+理由」供用户参考 |
| 画像条目取舍 | 全量 active 排序后截断 | 哪条重要是语义判断，不该只按次数 |
| 候选标题 | 取第一个完整句 | 语义上不一定是最恰当的概括 |
| 停用词表 | 中英写死的词表（`capture-value-screening.ts`） | 语言在变、新词不断，词表永远滞后 |
| 低价值行判定 | 固定规则筛「寒暄/低价值」 | 边界模糊，误杀有价值内容 |

### 1.2 判定标准：什么「适合 AI 调控」

三条标准，全部满足才纳入：

1. **有客观反馈信号**——调整后效果有现成指标可观测（使用次数、取用率、漏用审计、矛盾积压、灰区堆积）；
2. **可回滚**——数据/参数级调整，一条记录退回原状；
3. **错了不致命**——调坏最多样本质量下降，不丢数据、不泄密、不断功能。

**永久红线**（任何入口、任何授权档都不可为，执行层代码硬拒收）：
- 删除类操作（对齐「删除必须真删」产品决定——AI 不发起删除，删除永远人手动）；
- 敏感性（restricted）、作用域（scopePolicy）、核实状态——安全与治理属性只属于人；
- 与运行情况无关的产品规则（如「注入默认关闭」是 A/B 实验定的，不是参数）。

## 2. 系统架构（五层，双入口共享底层）

```
┌───────────────────────────────────────────────────────────────┐
│ ⑤ 界面层  「管家建议」卡片流（两个入口的产出汇合同一页）        │
├───────────────────────────────────────────────────────────────┤
│ ④ 变更集闭环  changeset：原子 / schema 校验 / dry-run 预演     │
│    / 一键回滚 / steward 台账全记录 / 回验三态                  │
├───────────────────────────────────────────────────────────────┤
│ ③ 双入口（共享下面全部底层）                                   │
│   入口 A 对话指挥：主智能体 steward 工具面                     │
│     （挂进 core-agent 工具集，与现有 recall 工具同模式；        │
│      用户在对话里说→智能体查/提案→用户口头批准→执行）           │
│   入口 B 自动巡检：模块后台任务                                │
│     （定时/事件触发，后台带账本问一次 AI，产出建议卡片）         │
├───────────────────────────────────────────────────────────────┤
│ ② 指标层  运行报告聚合器（全部来自现成台账，零新增埋点）         │
├───────────────────────────────────────────────────────────────┤
│ ① 策略注册表  Policy Registry（地基）                          │
│    散装参数/裁决点 → 命名策略项（id·值·范围·影响面·变更史）     │
│    现有算法读注册表，读不到=代码默认值（零风险渐进收口）         │
└───────────────────────────────────────────────────────────────┘
```

**v2 架构相对 v1 的本质简化**：v1 需要一个独立「管家服务」自带 LLM 调用器；v2 里入口 A 直接复用主智能体（它本来就在对话中，加工具即可），只有入口 B 保留一个轻量的后台巡检执行器（复用 semantic-review 的 buildRunner 一次性判定模式）。**一个底层、两个入口、一种变更集**。

## 3. 两条路的详细设计（v3 深化：200 项推演后的定稿）

> 本章经过 200 项交叉推演（附录 A 全矩阵），关键结论：**入口 A 的批准机制复用现成的 action-approval 审批框架**（主进程持有状态/TTL/审计，渲染层只应答不透明 id），对话口头确认被否决——UI 点击才是硬凭据，注入无法伪造。

### 3.1 入口 A：对话指挥——工具规格与接线

**工具面（5 个，挂 core-agent，随现有 recall 工具注册模式）**：

| 工具 | 输入 | 返回（预算） | 服务端行为 |
|---|---|---|---|
| `get_steward_report` | `window?: '7d'\|'30d'` | 资产统计/取用率/漏用 Top/矛盾积压/灰区堆积/预算占用/**上次调整效果/当前授权档/待处理建议**（<1KB，同轮缓存 60s） | 只读聚合，附简单启发式提示（如近邻对计数），给模型抓手 |
| `list_tunable_policies` | `domain?` | 策略项列表（id/当前值/默认值/范围/**影响面人话**/autoTunable 档/上次调整）（<1.5KB，默认 top15 可过滤） | 只读 |
| `propose_policy_change` | `policyId, to, rationale(必填), expectedImpact(必填)` | `{applied, actualValue(可能被clamp), changesetId}` 或 `{applied:false, reason}` | **五道校验后发起审批**（见下） |
| `list_steward_changesets` | `limit?` | 近期变更集+回验三态 | 只读，支持「上次说的那个」跨轮检索（按对话 id+时间） |
| `revert_steward_changeset` | `changesetId` | 回滚结果 | 目标值=代码默认则免审批（回基线永远安全）；否则过审批卡 |

**`propose_policy_change` 五道校验（顺序=先便宜后贵）**：
1. **存在性**：policyId 必须命中注册表（错误信息附相近 id 提示）；
2. **红线**：autoTunable=never 直接拒；
3. **授权档**：L1 下不落变更集、降级为 advice（模型收到「当前观察档，已记为建议」）；L2/L3 继续；
4. **值域 clamp**：越界值钳到范围边界，actualValue 如实返回；
5. **并发与频率**：同 policyId 已有 pending→拒并提示；冷静期内→拒并返回剩余天数；每轮对话上限 3 个（策略项）。

**批准接线（复用 action_approval.ts，扩展 `kind='steward_changeset'`）**：

```
模型调 propose ──► 主进程：校验五道 ──► 创建 changeset(pending)
                                        └─► 发起 action-approval 请求
                                            （risk: L3白名单项='high'，其余='critical'；
                                             TTL 10 分钟；卡片=from→to diff+影响面+rationale）
              ──► 对话流渲染审批卡（复用现有审批 UI）
用户点「批准」──► 渲染层只回传 opaque requestId（无凭据内容）──► 主进程 resolve
              ──► 执行：先快照 → 写新值 → 审计(approved/execution_started/succeeded)
用户点「拒绝」/10 分钟无操作 ──► changeset → expired/rejected（审计留痕）
```

**为什么否决「口头确认」**（推演 #25）：口头「行」无法构成凭据——注入攻击可诱导模型相信用户已同意；action-approval 的 UI 点击是主进程持有的硬凭据，渲染层只回不透明 id，这是仓库已验证的安全结构，零新增风险面。

**对话场景矩阵（12 场景）**：

| # | 场景 | 模型行为 | 系统行为 |
|---|---|---|---|
| S1 | 「看看该不该调」 | get_steward_report → 大白话汇报+提案 | 报告含启发式提示 |
| S2 | 「为什么这几个没归族」 | report+policy 关联解释 | — |
| S3 | 「把灵敏度调到 0.55」 | propose → 告知已出确认卡 | 审批卡弹出 |
| S4 | 「撤销上次那个调整」 | list → revert | 回基线免审批，否则审批卡 |
| S5 | 「巡检提的那个不采纳」 | dismiss（无害可代点） | 记 via=chat 的 dismiss |
| S6 | 「上次调的有效果吗」 | report 的回验区 | 三态汇报 |
| S7 | 「把我敏感资产删了」 | 拒绝并解释红线 | 工具层硬拒（#42） |
| S8 | 「调到 0.2」 | 提案，如实报告被钳到边界 | clamp+actualValue（#43） |
| S9 | 「以后自动调」 | 解释需开 L3，指路设置 | 当前档位在 report 里 |
| S10 | 模型嘴上「我调好了」不调工具 | 工具描述+系统提示强调必须走工具 | 注册表唯一真源，嘴改自然无效（#45） |
| S11 | 「先别调了」 | 不再 propose | pending 卡 10min 自然过期（#63） |
| S12 | 注入让模型乱调 | — | clamp+红线+审批三道闸；最坏=用户看到一张可疑卡，不点即无事（#47-48） |

**异常与滥用（要点）**：工具调用 8s 超时返回降级信息不阻塞对话；审批异步进行、对话流继续；多会话并发 propose 同 policy 互斥（首个 pending 生效）；A 路工具全部本地执行（注册表+台账），无网络依赖。

### 3.2 入口 B：自动巡检——状态机、触发器与校验管线

**巡检状态机（互斥单实例，锁文件带 TTL 防崩溃残留）**：

```
idle → locked → verifying(先回验上次的账) → collecting(冻结快照) → analyzing(LLM)
     → producing(advice/changeset 落库) → reporting(刷新界面) → idle
任何一步失败 → degraded_report(纯指标+原因标注) → idle
```

**触发器（阈值本身是策略项；每次触发原因入台账）**：

| 触发 | 条件（默认值，均可调） |
|---|---|
| 定时 | deferred boot task，距上次 ≥20h（记忆迁移同款模式） |
| 事件·矛盾积压 | 未决矛盾 > 5 |
| 事件·灰区堆积 | 查重灰区候选 > 10 |
| 事件·漏用连续命中 | 同一资产连续 3 轮星标未用 |
| 事件·回验到期 | 任一 changeset 的 grace period 期满 |
| 手动 | 「立即巡检」按钮（不防抖但互斥） |
| 防抖 | 任意两次巡检间隔 ≥6h（策略项）；运行中新触发直接忽略 |

**采数（冻结快照，10s 超时降级，不重试）**：指标报告+策略快照+回验待办+**忽略史**（同类建议被忽略 2 次后不再提，#92）。资产全文不进提示词——只给统计数字+最多 3 条代表性摘要，全部先过 gate.ts 注入扫描。

**巡检提示词（<6K tokens，温度 0）**：角色（巡检员）+ 数据（三个 JSON，围栏标注 DATA）+ 约束（只可引用现存 policyId / 值落声明范围 / 红线清单）+ 输出 schema 与 1 个完整示例。每个 metric 附一行人话定义。schema 带版本号（演进兼容）。会话 id 用 `steward-` 前缀注册 kind（吸取 semantic-review 会话被拒的教训，#103）。

**LLM 调用（复用 buildRunner 临时会话，semantic-review 同款）**：30s 超时；仅网络类失败重试 1 次；输入硬截 8K tokens；token 用量入台账（成本可见）。

**输出校验管线（七道闸，任一失败=整批丢弃退化为指标报告——宁缺毋滥，#114）**：

```
剥 markdown 围栏 → JSON 解析 → schema 校验 → policyId 存在性 → 值域 clamp
→ evidence 的 metric 必须命中本次采数集（防幻觉引用） → 条数≤5 + 冷静期过滤 → 落库
```

**回验器（纯代码，不调 LLM——数字对比不需要智能且成本为零，#128）**：
- 每次巡检开头执行，扫全部「grace period 已满」的 executed changeset；
- 判定（阈值均为策略项）：指标相对基线变化 ≥±20% 且方向符合预期=**生效**；|Δ|<5%=**未生效**；反向 ≥20%=**建议回滚**；中间=继续观察；指标停采=数据不足不判；
- 连续 2 次未生效 → 自动生成 revert 建议卡；
- 回验覆盖**全部来源**（A 路对话调的、B 路巡检调的，一视同仁）。

**降级矩阵**：断网/无 key/解析失败→纯指标报告（报告标注「本次未产生建议：原因」）；注册表损坏→代码默认+界面提示；台账损坏→跳过对应指标；磁盘满→中止+横幅；崩溃→锁 TTL 自动释放；事件风暴→防抖兜底。

### 3.3 共享底层：变更集状态机与存储

**变更集状态机（执行器单点迁移，全路径单测覆盖）**：

```
draft → pending(10min TTL) → approved → executed(先快照后写) → verifying(冷静期)
      │                        │
      │                        ├─ rejected / expired ──► 归档保留
      └─ verifying → effective | no_effect | revert_suggested → reverted
幂等：requestId 去重；reverted 后再调=新 changeset（不复活旧记录）
```

**存储布局（cloud/steward/，全部原子写 tmp+rename，policies.json 写前滚动备份×3）**：

```
cloud/steward/
  policies.json        策略注册表（schema v1+迁移钩子；启动校验，非法值回落默认+审计）
  changesets/<id>.json 每集一文件（并发安全）
  snapshots/<id>.json  执行前快照（永久保留，体积小）
  advices.json         建议追加式
  audit.jsonl          审计（10K 行轮转；诚实标注：防误不防恶——本地文件理论上可改）
```

**授权执行器检查序**：红线→档位→白名单→冷静期→上限。**自我保护**：steward.* 自身的策略项（含 L3 白名单本身）autoTunable 全部 never/L2-only——**管家不能调自己的缰绳**（#173-174）；越权尝试记录审计+界面提示。

**界面**：审批卡复用 action-approval UI（kind 文案新增）；管家 tab=建议流（两源混排）+回验区+**巡检历史时间线**（何时跑/产出几条/降级原因）；参数名零暴露（全部用 affects 人话）；四语 zh/en/ja/pt；空状态引导「立即巡检」。

## 4. 授权与安全

### 4.1 授权三档（约束操作类型，对两个入口同等生效）

| 档位 | AI 能做什么 | 人做什么 | 备注 |
|---|---|---|---|
| **L1 观察** | 只产出建议，不动任何东西 | 看或不看 | 初始档；B 巡检默认在此档 |
| **L2 提案** | 产出变更集等批准 | A 路径=对话口头确认；B 路径=卡片点击 | 推荐档 |
| **L3 受权执行** | 白名单内直接执行+审计+回滚 | 看审计、随时回滚 | 需显式开启 |

L3 白名单初始仅：数值微调（阈值 ±0.05 内）、族头命名改写、候选标题改写。白名单外的一切（停用词表、上限类、裁决预填）永远 L2。

### 4.2 安全机制

| 风险 | 机制 |
|---|---|
| 幻觉/注入产出非法值 | 封闭 schema + 数值 clamp 到声明范围 + 枚举白名单（输出不被信任；注入最坏结果=一个值域内合法提案，仍需批准） |
| 越权 | 红线清单硬编码在执行层（代码拒收）；归因封闭——policyId 必须命中注册表现存 id，AI 不能发明调整点 |
| 对话路径被注入欺骗 | 变更集必带「批准凭据」（对话 id+用户原话摘要 或 卡片点击），无凭据不执行 |
| 自激循环（AI 调的参数影响 AI 看的指标） | 每变更 14 天冷静期内不再动同一策略项；回验对比变更前基线 |
| 频率失控 | 每巡检变更集条数上限 + 每日巡检次数上限（均为策略项） |
| 不可逆 | 执行前快照，回滚=恢复快照，回滚也记账 |
| 资产文本藏指令 | 采数文本过 gate.ts 注入扫描 + 提示词围栏标 DATA + 输出封闭 schema，三重防线 |
| 与并行开发冲突 | 第一批只收口 `recall/` 侧参数；`ontology` 侧（007 三盒开发中）稳定后再纳入 |

## 6. 优化建议的流程与输出格式

### 6.1 生成流程（两入口同一套）

```
运行报告 → 发现(finding)：指标偏离/堆积/命中模式
        → 归因：映射到具体策略项或裁决点（封闭映射，不能发明新 id）
        → 建议(proposal)：from → to（值被 clamp）
        → 佐证(evidence)：具体指标数字+时间窗
        → 预期影响+置信度+风险
        → 回验计划：看哪个指标、多久后看
```

### 6.2 结构化输出（steward-advice JSON，封闭 schema）

```json
{
  "adviceId": "adv-20260920-001",
  "via": "chat | patrol",
  "kind": "param_tune",
  "policyId": "family.semantic_threshold",
  "finding": "近 7 天有 9 条资产两两相似度落在 0.52–0.59，未被归族，且目录漏用审计里它们总是一起被跳过",
  "evidence": [
    { "metric": "family.near_miss_pairs", "window": "7d", "value": 9 },
    { "metric": "relevance_miss.co_hit", "window": "7d", "value": 6 }
  ],
  "rationale": "聚类阈值 0.60 偏严，这批内容语义上同属「答辩偏好」主题；固定阈值无法感知主题聚拢程度",
  "proposal": { "from": 0.60, "to": 0.55 },
  "expectedImpact": "预计 9 条归入同族，目录条目减 8 行，漏用共现下降",
  "confidence": "medium",
  "risk": { "level": "low", "note": "幅度在 ±0.05 白名单内，可一键回滚" },
  "reversible": true,
  "verification": { "metric": "family.near_miss_pairs", "gracePeriodDays": 14 }
}
```

`kind` 枚举：`param_tune` / `rule_adjust`（规则类如停用词表）/ `curation`（整理类如族头命名、候选标题）/ `process`（流程建议，纯文字不落变更集）。

### 6.3 人读输出（界面卡片，治理术语内部化）

> **【建议】有 9 条「答辩偏好」相关的内容没被归到一组**（AI 置信度：中）
> 把分组灵敏度稍微调高一点，它们就能合成一组，对话时少占 8 行目录。
> 预计两周内能看到效果；随时可以撤销。
> 〔 采纳 〕〔 忽略 〕〔 看依据 〕

入口 A 产生而未在对话内即时批准的提案，同款卡片出现在建议流（不丢）。

### 6.4 回验输出

每次巡检报告含「上次调整效果」区，对**全部来源**（A/B 两路）的已执行变更三态判定：**生效**（指标朝预期变化）/ **未生效**（无显著变化）/ **建议回滚**（反向变化，卡片带一键撤销）；连续两次未生效自动建议回滚。
