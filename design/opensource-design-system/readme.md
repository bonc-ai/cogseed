# CogSeed 开源版 Design System

> 当前阶段：开源设计系统适配稿，待用户确认。基于已有组件调整主题、品牌与页面样例；本次不实施正式客户端。范围与顺序见 [设计适配 Handoff](HANDOFF.md)。

## 浏览预览

在本设计包目录运行（使用已有 Node.js，无需新增依赖）：

```sh
node tools/preview.cjs --port 4174
```

浏览器访问 **http://127.0.0.1:4174/**，即可搜索并浏览页面样例、组件库和设计规范。服务仅监听本机，根目录限定为本设计包；按 `Ctrl+C` 停止。端口被占用时为 `--port` 指定其他可用端口并访问对应地址。

HTML、CSS 和已生成 JS 保存后刷新页面即可生效；修改 JSX 或 tokens 后仍按下文运行 `node tools/build.cjs`，再刷新。预览服务不自动构建，也不提供业务后端。

[设计系统导航页](index.html)选中目录后在右侧预览，也可点击「新窗口打开」独立查看。页面样例分别提供登录、默认页面（首页）、工作空间、工作空间详情、认知资产、自动化、智能体 / 技能 / 连接、智能体管理工作台、智能体编辑、任务页、设置的独立入口（设置统一一个入口，进入后通过左侧菜单查看各项）；每个入口直接初始化对应页面，保留页内交互与完整流程跳转。新增预览页面时，同步更新 `catalog.js` 中的目录条目。 [输入台组件页](components/composer/composer.card.html)内纵向平铺基础入口、发送与排队、附件、语音、正文编辑和不可发送状态，无需跳转。

CogSeed 是跨 Agent 的个人能力资产层。本设计系统用于开源客户端的界面设计：复用已有布局与组件，保留 CogSeed 品牌，在任务、工作空间、认知资产和能力管理中形成一致的使用体验。

## CONTENT FUNDAMENTALS · 文案

**高保真展示**：页面与组件中的标题、字段、状态、反馈和无障碍标签均采用最终用户用语，不显示「设计预览」「示例数据」「演示流程」或实现缺口说明；文件预览等真实功能名称保留。场景标题可用于组件目录，业务页面不放人工状态切换器。数据与交互的模拟边界保留在开发文档及源码注释中，不表示已接入真实服务。

工作区域的统一名称为「工作空间」，适用于导航、页面名称、面包屑及规范示例。历史设计稿的来源名称保持原样以便追溯。

**语言**：简体中文（zh-CN）。数字、时间、文件名、代码一律半角，并统一使用系统非衬线字体。中英混排时英文与中文之间不加空格由字体处理，中文分组标签使用界面字体与轻微字距；英文标签可使用大写。

**四条铁律**（源自第一册「文案」卡片）：

1. **使用真实工作用语** —— 使用任务、工作空间、智能体、技能、资料库和认知资产等既有名称；不预设银行、组织管理员或企业授权流程。
2. **陈述事实与数量，不夸张** —— 「已读取 42 份项目材料，其中 7 份需要补充来源。」
3. **动作按钮用动宾短语** —— 允许一次 / 存入空间 / 重新运行 / 申请授权 / 使用模板。永不用「确定」「是」「好的」。
4. **不用叹号、不用 emoji、不称「智能助手帮您」**。

**人称**：系统不自称「我」；对用户用「你」而非「您」（「1 份产物等你确认」「需要访问…才能填入收件人」）。只有面向第三方的生成内容里出现敬语（提醒正文：「您负责的 3 项交付将于本周截止」）—— 即产品对用户说「你」，产品替用户写给客户时说「您」。

**占位符写清可输入的内容**：首页按安装版使用「输入 @ 选择智能体、技能」；对话内可使用 `描述一项工作，或粘贴一份材料。输入 @ 选择智能体与技能。` 绑定工作空间后，选择范围增加产物与资产；工作空间通过独立入口选择。

**标签与字段**：标签永不用冒号。可选项用「选填」以 text-muted 标注，不用「*」标必填。

**错误与拦截**：先说发生了什么，再说下一步。「日期不存在，请按 YYYY-MM-DD 填写。」「含个人联系信息，需在任务内单次授权后才能解析。」合规拦截不说「上传失败」。

**空状态**：图标、标题、说明与操作按钮水平居中对齐，说明文字居中，标题沿用界面字号。一句原因 + 一句办法。「这个空间还没有产物 / 任务完成后在产物页选择「存入空间」，团队成员即可按权限查看。」

**加载文案**：写正在做的那件事，不写「加载中…」。「正在核对第 5 / 7 步：逐户比对财报口径 / 已用 42s · 预计还需 1m10s」。

**对话框标题是问句**：「删除任务与全部产物？」正文必须说明什么会保留、什么不可恢复。

**权限边界要说出来**：无权限项保留可见但置灰并注明原因（「同业与投行（无权限）」「长期授权（需管理员）」「由管理员统一配置」）。全局搜索只接收宿主提供的可访问内容，不附加常驻权限页脚。

**引号**：中文书名号式引用用「」，如「授信台账_2026Q3.xlsx」。分隔符用 ` · `（空格中点空格），如「华东分行 · 对公一部」「1.2MB · 已就绪 · 只读」。

**vibe**：克制、事实密度高、贴近个人与项目的日常工作。它不表演智能，它汇报进度。

## VISUAL FOUNDATIONS · 视觉基础

顶部页面标题统一使用 `--cs-type-title`（15px / 500 / 1.5），由共享 [PageHeader](components/navigation/PageHeader.prompt.md) 管理；[查看组件样例](components/navigation/page-header.card.html)。首页问候语、登录品牌文字及正文标题保留各自层级。

三条底层原则（源稿开篇）：**开源绿色 + 中性界面**；**版式建立层级**（用字号、字重与分割线，而非阴影与色块）；**权限清晰**（权限与留痕收进设置与内联授权，不在主流程制造噪音）。

### 颜色

- **面**：工作区 `#FFFFFF`；页面底 `#FBFDFC`；侧栏 `#F4F8F5`；次级面 `#EDF3EF`。
- **墨**：主文字 `#14281E`，正文 `#243D30`，次级文字 `#4C685A`，可读辅助文字 `#5E7467`。禁用态使用独立浅色，不将低对比色用于正常说明。
- **绿色语义**：品牌识别 `--cs-brand: #0E9F6E`；主要操作与链接 `--cs-accent: #0A7A55`，渐变深端 `#086545`；选中底 `#E2F5EC`。深绿保证小字号白字可读，品牌绿不直接替代全部状态色。
- **状态独立**：success `#1E6E4E`、attention `#B5761F`（文字 `#8A5A14`）、critical `#A33A2B`；继续配合图标与文字，保留原有状态含义。
- 最多两个背景色同屏：白 + 一层 subtle。

### 背景与主视觉

**渐变雾仅用于默认首页背景**。登录、工作空间、任务页和侧栏使用纯色背景；按钮等控件沿用各自的颜色规范。首页主视觉：纯白主区右上角最亮、向下化开 —— 两层 radial（15% / 10%）+ 顶部 `#EDF8F1` 线性淡出至 48%。**不叠加在卡片上**，卡片与浮层一律纯白。背景不铺图片、重复纹理或噪点；现有松鼠品牌图形只放在输入台上缘，不遮挡文字、按钮与焦点。图表/产物缩略图位沿用 16/9 比例容器占位。

### 字体

全界面统一使用 **系统默认非衬线字体**，CSS 只声明 `system-ui, sans-serif`，不指定字体名称、不打包字体、不访问字体服务。实际字形由本机系统与浏览器选择，允许不同操作系统存在自然字形差异。

- **展示标题**：问候 34px、产物与文档标题 22px、对话框标题 18px。display 全局最多出现一次。
- **界面与正文**：标题 15px/500、正文 15px/1.75、界面 14px、紧凑界面 13px、辅助说明 12.5px。中文分组标签 12px/500，轻字距 .04em。
- **代码与数据**：同样使用系统非衬线；数字默认 13px、元数据最低 12px。表格用列宽和右对齐组织数值；可用 `tabular-nums` 请求等宽数字，字体不支持时仍依靠布局对齐，不承诺所有字符等宽。

需阅读的文字与背景对比度至少 4.5:1；大字至少 3:1。禁用文字与可读辅助信息使用不同语义 token。字号以 CSS px 计，不把整个界面缩小来适应窗口。

当前字体入口为 `tokens/typography.css` 的 `--cs-font-sans`。旧的 `--cs-font-serif`、`--cs-font-mono` 仅作为兼容别名，也指向系统非衬线字体。

### Windows 与内网

设计稿与 UI Kit 统一以 macOS 窗体和快捷键为基础。Windows 的原生窗口控件和快捷键由客户端构建适配，两端共用组件与业务流程。详细要求见 [Windows 与内网适配规范](guidelines/windows-intranet.md)，可视规范见 [适配卡片](guidelines/windows-intranet.card.html)。

### 间距与栅格

4px 基数，八阶：4 / 8 / 12 / 16 / 24 / 32 / 52 / 88。同组元素 8，组间 16–24，区块间 32–52，页面留白 88。**宽松留白靠「区块间 52」实现，不靠放大字号。**

参考画布 1440×900，实际宽高跟随窗口：侧栏展开宽度及最小宽度 280（窄窗口通过收起侧栏腾出空间）· 标题栏 52 · 对话正文最大宽度 720（首页）/ 760（任务内）· 右侧面板 308（信息）/ 520（产物）· 产物纸张 660。行高：导航 36 · 列表 34 · 表格 44 · 折叠头 44 · 文件行 48。**通用按钮、图标按钮与输入控件为 28 / 32 / 36 三档；分段筛选为 24px 紧凑变体；登录主动作保留 56px 高度、16px 字号特例。**

### 侧边栏导航

[侧边栏导航独立预览](components/navigation/sidebar.card.html)平铺默认展开、任务选中、空间收起、长列表与长名称、空数据和侧栏收起六种状态，每项仅展示侧边栏，支持独立操作与重置；状态锚点可直接定位。侧边栏组件页与默认首页复用 `ui_kits/enterprise-app/Sidebar.jsx`，默认数据统一由 `PreviewData.jsx` 提供。顶部固定新建任务、工作空间、认知资产、自动化、智能体 / 技能 / 连接；中部按「置顶 → 最近 → 空间」排列，三个分组（含标题与展开内容）共用一个滚动区；设置采用独立页面，以分类导航替换任务侧栏，右侧展示设置区域。底部账户区固定，复用 [UserMenu](components/navigation/UserMenu.prompt.md)，点击整行向上展开用户信息、设置和退出操作。默认展开「产品研发」，置顶使用「项目材料清单核验」作为样例。

### 圆角

4 标签徽标 · 7 小按钮与图标钮与页码 · 8 导航项与按钮与菜单项 · 9 输入框与选择器 · 11 浮层菜单 popover 提示条 · 12 卡片 · 14 卡片式窗口（对话框、命令面板、输入台）· 999 状态胶囊与开关。

### 边框与阴影

描边五阶：`.06` 列表内分隔 → `.07` 卡片内分割线 → `.09` 卡片描边 → `.12` 输入框与按钮 → `.14` 小标签下的规范线；章节分割用实心 `#14281E` 1px。

阴影四阶，只用于「浮起」的东西：`sm 0 1px 2px .06`（卡片）· `md 0 1px 2px .04 + 0 8px 24px .05`（浮层、输入台）· `lg 0 6px 18px .05`（卡片 hover）· `window 0 24px 60px .18`（对话框、命令面板）。**层级靠版式与分割线建立，不靠阴影堆叠。**

### 卡片长什么样

[卡片组件独立预览](components/cards/cards.card.html)展示基础卡片、资源骨架、工作空间、自动化、能力（智能体 / 技能 / 连接）、模板与交互状态，当前业务变体待设计确认。普通卡片最大 400px，横向自动化卡最大 800px；CardGrid 最大 1232px、最多三列，窄窗口自动减列。宽屏保留留白，不无限拉伸卡片。

白底、1px `.09` 描边、r 12、内边距 16、阴影 sm。资源卡片结构固定：**淡绿底图标 + 标题 + 可选控件 / description 说明 / 分割线后的状态页脚**。图标背景使用 `--cs-accent-wash`；工作空间变体展示更新时间、角色与最近任务；自动化变体使用紧凑横行，展示计划、最近执行、设备和执行记录入口。其他变体保持各自契约。可点击卡片 hover 时描边加深到 `.14` 并换上 shadow-lg。分组标题使用 12px 界面字体小标签 + 一条延伸细线（+ 可选的「查看全部 ›」）。列表用细分割线，不用卡片。

### 交互态

- **hover**：中性 `ink 4.5–6%` 底；次按钮描边加深至 `.22`；主按钮 `brightness(1.06)`。普通控件不以品牌底色闪烁；主操作保留自身绿色。
- **press**：`brightness(.94)`。不缩放、不位移。
- **焦点**：按钮、页签等动作控件保留统一 1px accent 描边 + 3px accent 12% 外环。文本输入、搜索、日期、多行文本、标签输入和选择字段不加品牌色框或外环，以中性灰边线提示焦点；输入台正文保持无框。错误边框保留，Windows 强制颜色模式使用系统焦点提示。
- **选中**：只加 浅绿选中底 + 略深文字，普通导航字重 400；层级标题、页签或强调项可用 500。**不用左侧色条、不用阴影。**
- **禁用**：底 `ink 8%`、文字 ink-32、`cursor: not-allowed`。
- 下拉选中项**以勾为主要标记，可辅以 浅绿选中底**，勾位固定 22px 缩进。

### 动效

`hover / 状态色 120ms ease-out` · `开关与发送键 140ms` · `视图切换 160ms 淡入 + 4px 上移` · `面板展开收起 200ms cubic-bezier(.2,.8,.2,1)` · `进度条宽度 400ms 同曲线` · `转圈 900ms linear（当前执行步骤 1.1s 琥珀）` · `骨架屏 1.4s 透明度呼吸` · `流式文本逐字、无光标跳动`。

**全局同时最多一个动效焦点。禁止弹跳、缩放入场、渐变流光、骨架屏扫光。** 状态点不加动画。

### 透明度与模糊

几乎不用。对话框遮罩 `ink 28%` **且无模糊**。唯一的半透明是主视觉渐变雾与吸顶栏的 `rgba(255,255,255,.95)`。滚动区底部用 28px 白色渐隐（protection gradient）提示可继续滚动，滚到底即消失 —— 不用胶囊式浮层遮挡内容。滚动条滑块 6px、ink 22%（hover 36%），覆盖在内容上不占布局宽度，静止 1.5s 后淡出；不用系统滚动条。

### 图片色调

源稿无摄影图像。比例容器（16/9 · 4/3 · 1/1 · 1/1.414）内容一律 cover 居中裁切，容器负责比例与圆角。若未来引入图像，应保持冷调、低饱和、无暖色滤镜、无颗粒。

## ICONOGRAPHY · 图标

**唯一图标系统是本地保存的 Lucide 官方 SVG**。原始文件位于 [assets/lucide/](assets/lucide/README.md)，保留官方路径与 **24px 画板、默认 2px 描边、圆角端点和连接、`fill: none`、`stroke: currentColor`**。界面内显示 13–16px，规范页示意 20px；描边随画板同比缩放。

操作图标不使用零散填充图标或 emoji；已有品牌 Logo、松鼠及连接服务 Logo 不属于操作图标。键盘符号与分隔中点保留为文字。

`components/foundation/Icon.jsx` 保留现有语义名称，通过构建时从 SVG 生成的 `csIcons` 注册表统一呈现。设置使用官方 `settings`，退出登录使用 `log-out`；完整名称映射、固定来源版本和文件校验值见 [manifest.json](assets/lucide/manifest.json)。

用法：`<Icon name="space" size={16} />`。新增图标应保存官方 SVG、补充映射与类型，再运行 `node tools/build.cjs`；不手写图形，不安装图标包，不在页面运行时访问外部资源。

企业原稿未提供品牌图形；开源包使用资产清单记录的客户端现有 Logo 与松鼠。界面操作图标继续使用本地 Lucide SVG。字体使用本机系统默认非衬线，`vendor/` 为本地预览运行资源。

### 组件清单的边界

组件清单以源设计稿第一册 + 第二册的构件为基础，复用补充通过源注册表统一维护。源稿明确写「极少用到的构件（快捷键提示、轮播、菜单栏、图表容器）此处不收」——本设计系统也不收。

**共享补充**（承载已有内容与页面组合，具体导出见组件清单）：

- **Icon** —— 通过共享组件与本地 SVG 注册表，统一 Lucide 图标的画板、描边与语义名称。
- **CardFooter / GroupHeading** —— 源稿把「分割线后的状态页脚」和「小标签 + 延伸细线」当作卡片结构的固定部分反复出现，抽成两个组件避免每次手抄。
- **StatusCapsule** —— 源稿的描边胶囊（「数据不出域」）与 StatusPill 几何不同（h 26 / r 999 / 描边），单列一个导出。

- **UserMenu** —— 组合 Avatar 与 DropdownMenu，统一侧边栏底部用户入口与向上弹出的操作菜单。

- **SettingsSection** —— 设置页面共享的标题、操作区和内容容器，统一使用浅边框与紧凑内容布局。

### 交互与页面一致性

- Button / IconButton 统一悬停、焦点、禁用与加载；加载保留文案与几何尺寸，阻止再次激活，并提供 busy 语义。字段标签关联控件，错误关联具体字段。
- Select / SearchableSelect / DropdownMenu 支持键盘打开、方向键移动、Escape 关闭与焦点返回；中文输入法组合期间不执行动作快捷键。浮层使用共同定位与层级，在窗口边缘翻转并限制可用高度，避免被滚动容器裁切。
- Dialog 用于跨区域阻断确认，默认聚焦取消，Tab 限制在对话框内；Escape 或关闭后返回触发器。InlineConfirm 页内确认用于与对象相邻的局部操作，按钮写具体动作；统一呈现不改变原有删除、撤销或保留规则。
- 同一语义使用共享状态标签、分段筛选和空状态。认知树等业务图形保留专属布局；普通文字优先引用语义字号与间距 token。
- 能力页继续使用客户端现有名称「IM」；目录保持一致。本轮不调整信息架构或业务用语的含义。
- 层级顺序为 sticky → popover（含任务菜单）→ modal → modal-popover → command → toast，数值只在 `tokens/elevation.css` 定义。


## 交付入口与可执行契约

当前版本由 [version.json](version.json) 定义，构建同步到 manifest；变更与迁移见 [CHANGELOG.md](CHANGELOG.md)，实际验证边界见 [verification.md](verification.md)。

- 源码消费者从 [index.js](index.js) 导入，类型入口为 [index.d.ts](index.d.ts)；需要 React 和 JSX 构建能力。离线浏览器预览使用 `_ds_bundle.js` 与 `styles.css`，正式 Renderer 保持仓库约束。
- token 是实际样式变量；未使用项删除，完整间距阶和兼容别名的保留理由列在 [tokens/reserved.json](tokens/reserved.json)。组件尺寸、字号、动效与布局间距按语义引用；边框、图形、负边距、定位和响应式计算不属于布局间距阶。
- `node tools/build.cjs` 生成交付入口与预览；`node tools/verify.cjs` 同时执行源码规则、回调契约与哈希检查。已有开发环境提供 esbuild、@babel/parser 和 postcss，不新增运行依赖。
- `.d.ts` 是属性契约，adherence 不再维护重复的属性白名单；raw px 不作全域禁令，允许几何尺寸及语义明确的组件参数。颜色使用 token，页面可覆盖 token 或组件 style。
- 单一焦点规则位于 `components/foundation/accessibility.css`；目录页专属布局位于 `composer-gallery.css`，公共 `styles.css` 不导入它。
