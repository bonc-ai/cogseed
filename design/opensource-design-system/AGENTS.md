# AGENTS.md

## 范围与边界

本文件适用于本目录及其子目录，补充仓库根目录规则。目标是以企业版通用设计基础支持 CogSeed 开源版界面重构，保留开源绿色配色、品牌与业务行为。

当前处于开源设计系统适配与确认阶段。先读 [设计适配 Handoff](HANDOFF.md)，本次只修改本包的规范、tokens、共享组件和页面样例。正式客户端代码实施需要用户另行明确要求，不能从设计确认任务推断。

企业来源的历史记录保留，但 Raymond 字标、金融版用语和蓝色品牌不作为本包要求。开源适配结果与待确认项维护在 verification.md。

- 这里是独立设计系统与交互样例。React/JSX 预览不是正式 Renderer 实现；接入客户端仍须遵循仓库的共享组件、Renderer 与 IPC 约束。
- 知识库模块和运行中心模块不纳入本设计系统的页面样例范围，不补建对应页面，也不将其列为待补缺口。能力管理中已有的「资料库」维持原有范围。除非用户明确调整范围，不扩展这两个模块。
- 改版以样式、视觉、组件呈现及必要交互为主，保留现有业务逻辑。若目标需要改变业务行为，说明影响与最小调整，取得用户确认；已有授权不重复确认。
- 预览可运行、离线检查通过、客户端启动、业务验收和发布是不同证据，不能互相替代。

## 修改顺序：规范 → 组件 → 页面

1. 阅读 [SKILL.md](SKILL.md)、[设计规范](readme.md) 及相关组件说明；搜索同一语义的规则、源码、调用位置和生成产物。
2. 通用视觉变量维护在 `tokens/`，通用规则维护在 `guidelines/` 或 `readme.md`。同步相关规范卡片与目录文案，避免旧值继续指导实现。
3. 共享行为或外观先修改 `components/`，同步 `.d.ts`、`.prompt.md` 和交互样例，再应用到受影响的 `ui_kits/` 页面。
4. 页面优先复用现有按钮、字段、状态、筛选、空状态、确认、页头和浮层；通用差异扩展共享变体，不用页面局部覆盖掩盖组件问题。业务专属图形与布局可保留在页面。

逐层判断不等于每次修改所有层。纯页面组合可以只改页面及其生成产物，并简要说明共享规范为何不受影响；不要无差别替换不同语义的同名值。

## 源文件与生成产物

- `components/registry.json` 是公开组件与辅助导出的注册来源。增删或重命名导出时更新注册表；[组件清单](components.md)、bundle 元数据和 manifest 的组件列表由构建同步，不分别手改。
- JSX、tokens、注册表或卡片元数据变化后，在本目录运行 `node tools/build.cjs`。同步生成 JS、bundle、清单与派生页面入口；不得只修改生成文件。
- 使用已有 esbuild 环境，必要时通过 `RAYMOND_ESBUILD_PATH` 指定；新依赖仍遵循仓库的事先讨论要求。
- 页面目录入口维护在 `catalog.js`；详细文件映射见 [UI Kit 说明](ui_kits/enterprise-app/README.md)。

## 交互与视觉底线

- 动作使用原生按钮，字段有可访问名称，帮助与错误关联到对应控件；不要用只有点击事件的 `span` / `div` 代替操作控件。
- 按组件角色支持键盘访问、可见焦点、Escape 关闭及焦点返回；模态对话框限制焦点范围。输入框动作快捷键忽略 `e.isComposing || e.keyCode === 229`。
- 长操作有可见进度；加载状态保留可读文案并阻止重复激活。组件页与页面样例使用同一套默认、悬停、焦点、禁用、加载和错误样式。
- 图标通过共享 `Icon` 与本地 Lucide 注册表使用，遵循统一画板和描边，不恢复历史调用点的零散描边覆盖。新增图标按 [图标说明](assets/lucide/README.md) 更新本地资源与映射。
- 字号、颜色、间距和层级优先使用对应语义 token；层级数值只在 `tokens/elevation.css` 定义。浮层复用共享定位，避免滚动裁切和越出视口。

## 页面入口与文案

- 每个独立页面必须列入导航，并有稳定直达地址；目录选择、独立打开、刷新均能初始化目标页面，不依赖此前登录或操作。独立入口和完整流程共用页面实现，保留页内交互与页面跳转。
- 除非用户明确要求，不主动添加标题副标题、功能概述或额外 description；标题已能表达含义时直接展示内容与操作。操作影响、错误恢复等必要反馈遵循设计规范。
- 高保真页面使用最终用户文案；模拟数据与实现边界留在源码和开发文档，不在业务界面显示人工状态切换器或「本次样例」说明。
- 工作区域统一称「工作空间」；同一概念同步检查导航、标题、命令入口和说明。历史稿名、来源记录和内部标识不因文案统一而自动重命名。

## 验证与交付

- 组件或生成链路改动后运行 `node tools/build.cjs`、`node tools/verify.cjs`；检查旧值残留、资源引用、源码与生成产物一致性及 diff 空白错误。纯文档改动只做相关内容与链接检查。
- 按影响范围验证代表组件和实际页面，覆盖适用的键盘、状态、长内容与受限视口；页面或路由改动覆盖受影响入口的直达、刷新和跳转，共享外壳或全局路由改动覆盖所有页面入口。
- `verify.cjs` 是离线元素、回调和组合契约检查，不能证明 DOM 布局或原生键盘行为。浏览器或客户端验证受阻时记录具体缺口，不声称验收通过，也不绕过工具安全策略。
- 验证结果与待验证矩阵维护在 [verification.md](verification.md)。本文件不记录组件数量、测试数量、临时阻挡或本轮完成状态。
- 交付简要说明受影响层级、修改范围和实际验证结果，分别陈述设计调整、生成成功、浏览器验证与正式客户端接入。
