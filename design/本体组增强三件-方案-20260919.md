## 第 1 件 · 字段值时间维度（@asof）

**对应蓝图设计**：R26 temporal_integrity（时间完整性：不用访问日期冒充事件日期；相对表述保留原词+标 needs_refresh）。

**目标**：字段值可携带「信息截至时间」（这条值正确的时间，不是写入时间）；超龄值在暴露层带「可能过时」标记；机器不自动判死（「出生年」永不过期、「大四」一年过期，机器分不清，判断权留给人）。

**数据格式**（对齐 `@proj:` 风格，人读 markdown 不变味）：

```
## 字段区
### 就读状态
- 目前大四 [手动] @asof:2026-09
- 高考英语 47 分 [手动]
```

**改动点**：
1. `personal_ontology_groups.ts`：FieldValue 加 `asOf?: string`；parseFieldValueLine 认 `asof:` marker（非法月份不认、原样保留、不报错——文件是人可编辑的）；serializeFieldValueLine 追加
2. `projection-knowledge.ts`：ontologyFacts 拍平时带 asOf / needsRefresh（asOf 距今 ≥ 12 个月 → needsRefresh=true；无 asOf → 都不带，不制造噪音）
3. `world-model-types.ts`：WorldModelOntologyFact 加 `asOf?/needsRefresh?` 两可选字段（Forecast 模型可见「这条事实可能过时」）
4. @ 注入（chat-use.js 读全文）：文本天然带 `@asof:2026-09`，模型可读原文——不做转换（最小改动）

**不做（第二步、UI 先过方案）**：memory.js 面板值行渲染「截至 2026-09 · 可能过时」标记、写值时可选填时间的输入控件。

**写入来源**：回流确认（第 2 件）与转写桥自动带当前月；用户手动编辑文件自由写；UI 手动填属第二步。

## 第 2 件 · 学习回流本体组（资产 → 候选池）

**对应蓝图设计**：R13 evolution_policy（证据提议变更 → 授权内晋升）+ 文档核心命题「KSTAR 记忆支撑本体的形成与演化」。现状是学习成果只进资产库，本体组是死表。

**目标**：资产晋升为正式资产时，判断文本自动投本体组候选池；用户确认才写入，绝不直写（未确认候选不可被用红线）。

**挂点与回流条件**：
- 挂点：promoteRecallCandidate（人工确认晋升）+ autoApplyRecallCandidate（方案甲自动晋升）+ ingestImmediateKnowledge 的 created 态（即时直投）
- **融合/更新（merged/fused）不回流**——内容已在资产里，回流是重复
- 类型白名单（照 mapOnboardingType 先例）：personal→preference/user、rule→rule/shared、fact→instance/user、preference→preference/user；**skill 类不回流**（技能内容不属于个人事实表）
- 幂等键 `asset-backflow:<assetId>`：同 id 覆盖 → 池内永远只保留该资产最新版
- confidence: 'low'、write_actor: 'llm'（照 onboarding 先例：未经用户核对不冒充高置信）
- 防洪：投池前检查池内 `asset-backflow:` 前缀条数 ≤ 20，超出不投只记日志

**确认去向收口（衔接债）**：confirmCandidate 的 toGlobalMemory 由「只写 USER.md」改为双轨——
- 资产库画像非空（已有 personal 资产）→ 投 recall 候选（origin=capture）并立即以 actor:'user' 晋升成 personal 资产 → 画像/目录/挂载全链路生效
- 画像空 → 回退旧 USER.md 路径（原行为保留）
- 切换哲学与 formatForSystemPrompt 一致（存量迁移完自然切换，不做一次性硬切）

**新文件**：`src/main/features/recall/ontology-backflow.ts`（映射+投池+防洪，独立模块好测）

## 第 3 件 · 矛盾检测（同字段值冲突暴露）

**对应蓝图设计**：R32 conflict_policy（矛盾暴露不静默消解）+ 10 条冲突复核记录。

**目标**：同字段两条值语义矛盾时检测出来、记台账、暴露给用户与世界模型；**永不自动消解**（删除权在人，且物理删）。

**检测点**：appendFieldValue（写字段）时增量检测——新值 vs 该字段既有值逐对。不做全量巡检（量小无必要）、不做跨字段矛盾（「喜欢城市=北京」vs「居住地=上海」不算）。

**判定两级**：
1. embedding 相似 ≥ 0.60（判族同阈值）——先「在谈同一件事」才谈得上矛盾
2. 送 LLM 一道二元判定（两条值是否互斥）——小调用
3. kb_embed 不可用 → **跳过检测、写值照常、日志记 degraded**（与查重降级不同：查重降级阻断自动晋升，矛盾检测降级不能卡死用户主动写值）

**矛盾记录**：组文件同目录 `conflicts.md` 台账（照 groups.md/candidates.md 台账先例）：group_id / field / valueA / valueB / detected_at / status:'open'。**不往值行里塞状态**（保人读 markdown 简洁）。

**暴露**：
- confirmCandidate 的 fieldWrites 返回带 conflictWarning（前端 toast）
- conflicts.md 台账在下次读取时自愈：值已不在（被用户删）→ 对应冲突行清除
- （第二步、UI 先过方案）memory.js 字段区冲突标记 + 世界模型暴露矛盾对

**复核动作**：用户看到冲突 → 自己删错值（真删）。无自动动作。

## 实施顺序与依赖

```
第 1 件 @asof ──→ 第 2 件回流（确认写入自动带 @asof）──→ 第 3 件矛盾检测（吃回流写值流量）
```

全量回归 `npm run test:js` 两遍 + lint + tsc；每件独立测试文件。
